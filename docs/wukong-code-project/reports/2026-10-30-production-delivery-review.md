## 第一批：草稿交付缺陷

### D1：独立微秒取整会产生非法重叠（已复现）

`plugin/engine/exporters/jianying/plan.mjs:140` 分别对镜头 start 和 duration 取整。三个连续镜头各长 `2/30` 秒时，第二镜为起点 66667μs、长度 66667μs，第三镜起点 133333μs，产生 1μs 重叠。

真实项目的 `.cache/work/jianying-plan.json` 有 8 处同样问题：s32→33、s38→39、s41→42、s57→58、s67→68、s71→72、s83→84、s94→95。`review/剪映时间量化-*.json` 和 `tools/quantize_jianying_plan.py` 记录了只裁短 1μs 的临时处理。应从统一切点相减得到长度，而不是宽容任意重叠或把包装器当作正式修复。

### D2：英文排版建议被当成字幕完整性错误（已复现）

`core/subtitles.mjs` 的 `checkEnglish` 返回超长、句号结尾等警告；`bin/wka.mjs:374–375` 在纯草稿路径中将任何返回值当作硬错误，统一报“双语字幕缺失或与中文字幕不一致”。真实竖版稿 55 条英文超过默认 28 字符，实际并非缺失英文。

项目因此使用 `tools/export-portrait-draft.mjs` 核对已签批字幕、121 对中英文本、高清预检和片段后绕过 CLI。正式修复应区分结构错误与排版建议。MP4 字框预检通过不能证明剪映内也显示正常。

### D3：固定字号映射没有表达实际逐条排版（部分已复现，映射仍需实机校准）

`exporters/jianying/plan.mjs` 使用固定 `SIZE_PER_HEIGHT`，不接收画布尺寸。同样 `size=.041` 在 1920×1080 和 1080×1920 都输出 4.26。`write_draft.py` 将字号原样交给本机已安装的 pyJianYingDraft 0.3.1。

烧录层 `core/subtitle-layer.html:31–48` 实际会分别缩小每条中英文以适应宽度；预检的 `measurements` 已记录逐条 `zh`、`en` 字号和 rects。草稿目前只写全轨统一样式，没有沿用这种逐条排版信息。

`review/剪映内字幕字号复查.md` 记录原生 UI 手调结果：横版中5/英4，竖版中10/英6；竖版英文8使片尾长句越界。它证明当时需手动返修，但不足以推出通用字号公式；这四个数值不能硬编码为全部作品的默认值。字号、缩放、位置、字体替代和长句适配应一起在新导出的隔离草稿中校准，保存后重开复查。
