# 第三批实施计划

目标：实现已批准 FR-5～FR-8，在保持真实审片门槛下减少重复验证、导出与提问。

架构：approval 维护主版证明；operations 提供阶段回执/恢复，job 分离逐镜准备和拼接；delivery 提供交付清单；review-evidence 关联人工结论与实际来源。CLI 组织各模块，导演规则负责采用已经确认的决定，机器状态不推断用户批准。

技术栈：Node.js ESM、node:test、Chromium、Remotion、ffmpeg/ffprobe、pyJianYingDraft。

依据：同目录上一级 specs 中 2026-10-29-1639 的四份 Confirmed spec。用户已明确批准。

## 全局约束（原文摘录）

- 不自动重新签批，不覆盖定稿快照，不删除客户视频；清缓存只是失去复用能力。
- 新操作记录不改客户源文件和手改字幕；缓存记录不能授予审片批准。
- 不解析任意自然语言简报为可靠授权，不下载未授权素材、不创建虚拟媒体、不将本地素材上传到外部服务。
- 不自动重写配乐、不修改原录音、不自动调低 QC 阈值，不把制作者接受冒充用户终审。

## 文件与职责

- core/approval.mjs、state.mjs、job.mjs：环境/文件指纹、主版证明、签批身份、逐镜准备。
- core/operations.mjs、CLI、jianying/index.mjs/write_draft.py：原子阶段记录、互斥、草稿完成回执、恢复/签批重试。
- core/delivery.mjs、decisions schema、CLI、director/BRIEF：存在性/新旧状态、宿主链接、明确决定复用。
- core/review-evidence.mjs、review-notes schema、audio/audit/soundtrack、qc、jianying：实际审听窗口、处置绑定、声音差异披露。
- tests/unit 与 integration 对应测试：真实文件与媒体回归、边界失败注入；不以字符串断言代替实际产物。

## 顺序与独立交付

1. FR-5 先写缓存缺失/复用/快照与集合变化的失败回归，运行 `node --test tests/integration/variants.test.mjs tests/unit/approval.test.mjs` 确认失败；最小实现后重跑。真实两管线证明第二次不执行主版 render/PSNR；原帧长变化不覆盖快照。
2. FR-6 先写阶段回执失效、强杀/外部写完未登记、用户编辑草稿、签批幂等失败用例；运行新增 unit/integration 确认失败，再实现 operations、job 分层和写入回执；纯草稿不拼接/烧录/编码但片段校验有效。
3. FR-7 先写特殊路径链接、缺失/损坏/过期产物和制作决定校验用例；确认失败后实现 delivery/CLI/规范，实际宿主打开代表文件；不可用宿主明确未验证。
4. FR-8 先写审听窗口、来源失效、QC 接受不能绕过硬错误和导出前披露用例；确认失败再实现 review-evidence 及生产接入。实际审听不可用时保留 not-listened。
5. 每项通过后独立提交。最后运行 npm test、npm run lint、npm run smoke，以及受影响的两管线/主副版/纯草稿恢复集成；读完退出码与失败数，修正当前失败后更新 PR #96 和 issue #93，不自行合并/发布。
