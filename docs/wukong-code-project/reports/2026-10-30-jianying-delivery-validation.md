日期：2026-10-30（Asia/Shanghai）。依据：[已批准 spec](../specs/2026-10-30-1230-jianying-delivery-design.md)与[实施计划](../plans/2026-10-30-1240-jianying-delivery.md)。跟踪：[#93](https://github.com/wukongnotnull/wukong-animation/issues/93)。

## 实现

1. 视频区间以渲染器输出的帧起止为准，微秒时长取共享终点减共享起点；真正重叠、缺口、逆序、零长度、非帧时间或错误终点均拒绝。Python 不再以 `min` 静默裁短目标区间；仅允许素材与目标独立量化造成的至多1μs差异，保持目标区间，明确设置对应 source 区间。
2. 纯草稿复用 `attachEnglish` 完整性检查，长度和句号保留警告。当前原生尺寸版式预检独立于全片拼接，重新测量实际字体、字幕和安全区，不用小样或旧报告替代当前测量。
3. 逐条中英文沿用烧录层测得的字号与字框中心，结合画布宽度转换到剪映尺寸和坐标；Python 选择“片段样式 → 轨道样式 → 全局样式”。旧计划仍可回退。导演规范增加实际打开、保存重开和验证边界要求。

没有修改客户的《Codex 自动剪辑》工程、原字幕、成片、原草稿或安装缓存。没有改变审片数量、母带处理或人工编辑保护；清单摘要/人工验收状态属于后续批次。本次未发布版本。

## 剪映原生校准

宿主为本机剪映专业版 **11.6.0（macOS）**，库为 **pyJianYingDraft 0.3.1**。未升级依赖。

先创建三个独立探针画布：1920×1080、1080×1920、1920×1920。每个含32/64px的参考文字“字号校准”，以及原生 size=8/16 的同文字幕。均由真实 writer 新建草稿、从剪映首页打开，观察实际播放器。探针截图与测量在[校准数据](assets/jianying-2026-10-30/calibration.json)及同目录 `probe-*.png`。

在这些画布中，原生字号按画宽转换的模型满足校准：

`nativeSize = targetFontPx × 168.75 / canvasWidth`

因此1920宽每单位约11.3778px，1080宽约6.4px；不能沿用原来的固定“画高比例×104”，也不能把横版的像素/字号关系直接套到竖版。此为已核验宿主版本的经验映射，不扩展为所有剪映版本、所有字体完全相同的承诺。

坐标采用字框中心：`x=2cx/W-1`，`y=1-2cy/H`。中文/英文各自的实际字号和中心分别写入，长英文缩放后仍按当前字框放置。

### 修复后标准 CLI 验收

用标准 `node plugin/engine/bin/wka.mjs final <隔离片目录> --formats jianying` 新导出四份：

- `WKA验收-1920x1080-32px`、`WKA验收-1920x1080-64px`
- `WKA验收-1080x1920-32px`、`WKA验收-1080x1920-64px`

每份6秒，两镜分别为暗底 `#182028` 和亮底 `#eeeeee`；第一条“字号校准 / Font size check”，第二条“主角是内容本身 / What you imagine can become what you make”。两条中英字幕独立可编辑。配置 bottom=.15、safe_area=[.05,.05,.9,.9]、白字黑描边；基础字号分别32/64px，最长英文由实际宽度测量决定是否缩小。

为满足同字体对照，参考渲染使用隔离 `WUKONG_ANIMATION_HOME`，将本机剪映自带 `zh-hans.ttf`（Source Han Sans CN Medium）和 `en.ttf`（Metropolis Medium）作为临时测试字体源；不改变用户字体缓存、不分发字体文件、不把结果当作一般 Noto/Inter 替代字体的一致性证明。

四份均实际打开，抽查0秒暗底短句和约4秒亮底长句：完整显示、无裁切、无中英重叠、安全区内可读；未在剪映内手调字号。用 Command-W 保存返回首页，再分别重新打开。重开后的0秒画布与初次打开的0秒画布逐像素相同（剪映重新打开会回到0秒，不能拿约4秒截图直接比较）。
