# 中英双语字幕设计

关联 issue：#48（来自讨论 #45）。

## 1. 问题与目标

- 现状（已核实）：第 11 道 `wka subtitles` 从人声生成单语 `subtitles.srt`；烧录层 `core/subtitle-layer.*` 每条只画一行；外挂导出 `_字幕.srt`；剪映草稿一条「字幕」轨。双语字幕在字幕工序和剪映导出器的设计稿里都明确列为非目标。
- 用户的 wk-motion-graphics 口播片默认中英双语：
  - 中文在上、英文在下，同字号、同颜色（白），无底框，靠描边保证可读；每种语言都只占一行，放不下就缩字。
  - 英文与中文字幕**逐条对应**：脚本先生成"每条中文旁一个空的英文"草稿，填完再转正式文件，条数由脚本保证。
  - 英文文风：口语意译、不逐字翻；横屏不超过约 45 个字符；产品名和术语原样保留（Claude Code、Diff、Token、Git）；中文是半句，英文也写半句；结尾不加句号，问句保留问号。
- 目标：任何风格的片子都能在 `film.json` 打开双语字幕，烧录版、外挂字幕、剪映草稿三处都带英文；keynote 按源 skill 默认双语。

## 2. 架构与组件边界

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| 设置 | `film.json` 的 `subtitles.bilingual`（布尔，缺省 false）、`subtitles.max_chars_en`（整数，可选） | 这支片要不要英文行 |
| 英文稿 | 片目录 `subtitles.en.json`（新） | `[{ "zh": "…", "en": "…" }]`，与 `subtitles.srt` 逐条对应；`zh` 用来核对没有对错条 |
| 英文稿读写与检查 | `core/subtitles.mjs` | 生成 / 更新英文稿（保留已填的）、核对、检查长度与句号（纯函数） |
| 烧录 | `core/subtitle-layer.mjs` / `.html` | 有英文时一条画两行：英文在原来那行的位置，中文在它正上方 |
| 字幕样式 | `style.json` / `film.json` 的 `subtitles` 块新增可选 `font_en`（同 `font` 结构）；keynote 设 Inter | 英文行字体；缺省与 `font` 相同 |
| 外挂导出 | `bin/wka.mjs` 的 `cmdFinal` | `srt` / `both` 时另出 `<name>_英文字幕.srt` |
| 剪映草稿 | `exporters/jianying/plan.mjs` | 另起「英文字幕」轨；中文轨上移一行 |

单语片子（`bilingual` 不写或 false）所有输出与现在完全相同。

## 3. 接口、数据与行为

### 3.1 英文稿 `subtitles.en.json`

```json
[
  { "zh": "每一帧都由代码画出", "en": "Every frame is drawn in code" },
  { "zh": "选一套画风", "en": "" }
]
```

- `wka subtitles <片>`（`bilingual: true` 时）：在生成或检查完 `subtitles.srt` 之后，按 srt 的条目重写 `subtitles.en.json`：
  - 条数、顺序与 srt 相同，`zh` 取 srt 的文字。
  - 已有英文稿里 `zh` 完全相同的条目，保留它的 `en`（按出现顺序一一取用，同一句出现两次各取各的）；其余 `en` 为空。
  - 打印"英文字幕 N 条，其中 M 条待填"，并列出待填条目的序号和中文。
  - 内容没变时不写文件。
- 英文由写片子的人（通常是 Claude）按 §1 的文风填 `en`；director 文档写明规则。
- 读取时核对（`wka subtitles --preview`、`wka final`）：
  - 文件不存在、条数不等、某条 `zh` 与 srt 对应条不同 → 报错并指出第一处，提示"重跑 `wka subtitles <片>` 会保留能对上的英文"。
  - 有 `en` 为空 → 报错列出序号。
- 检查（警告，不中断）：英文超过 `max_chars_en` 个字符（缺省横屏 45、竖屏 28、方形 34；按字符数计，含空格）；英文以 `.` 结尾（不含 `...`）。

### 3.2 烧录

- 一条字幕两行：英文行底边在样式的 `bottom`（与单语时那一行同位置），中文行在它正上方，行高 1.3、同字号、同颜色、同描边。
- 两行各自不换行，各自放不下时各自缩字（沿用现有逻辑），日志分别报"第 N 条中文 / 英文一行放不下，字号从 X 缩到 Y"。
- 英文行字体用 `font_en`，缺省同 `font`；字体子集化把英文文字一起算进去。
- keynote：`style.json` 的 `subtitles.font_en` 设 Inter（与画面英文数字用的字体一致）。keynote 的字幕带本来就按两行留的（`Guides` 画的是两行加内边距），版式不用改。

### 3.3 外挂字幕

- `mode` 为 `srt` / `both` 时，除 `<name>_字幕.srt`（中文，不变）外，再出 `<name>_英文字幕.srt`：时间与中文 srt 相同，文字为英文。

### 3.4 剪映草稿

- 新增「英文字幕」轨，条目时间与中文字幕相同，样式同中文（字体按剪映字体对照表映射 `font_en`，表里没有就用剪映默认字体并在导出日志里提示，与现有中文字体的处理一致）。
- 英文轨在原来中文那一行的位置；中文轨上移一行（字号 × 1.3）。

### 3.5 文档

- director `SKILL.md` 第 2 道（字幕方式里问要不要英文）、第 11 道（英文稿怎么填、文风规则、检查项）；简报模板「字幕方式」写明可选中英双语。
- keynote `STYLE.md`：口播片默认中英双语（在简报阶段确认）；禁忌里的"两行字幕"改成"中文字幕折成两行"，免得和双语冲突。

## 4. 约束、兼容性与非目标

- 不写 `bilingual` 的片子：srt、烧录、外挂、剪映草稿输出与现在逐字节相同（测试覆盖）。
- 非目标：自动翻译（英文由写片子的人填）；中英以外的语言；英文行字重 / 颜色单独设置；竖屏英文折行（源 skill 允许，这里统一不折行、缩字）；双语合在一个 srt 文件里导出。
- 待定（发现的现有问题，不在本次改）：`style.json` 的字幕 `size` / `bottom` 是画高的比例，keynote 写的 0.041 / 0.074 按横屏 1080 高定（44 px / 底边 1000）；竖屏 1920 高时变成 79 px、底边 1778，和 keynote 竖屏版式（40 px、底边 1500）对不上。双语在竖屏上会更明显，建议另开 issue 处理。

## 5. 错误处理与运维

- 英文稿 JSON 解析失败：报错并带文件名和解析错误信息。
- 所有核对错误都在烧录之前报出，不会烧到一半才失败。

## 6. 验收标准与测试

1. 单元：生成英文稿——条数与 srt 相同；`zh` 相同的条目保留 `en`（含同句重复）；改过的条目 `en` 置空；内容没变不重写。
2. 单元：核对——条数不等、`zh` 不同、`en` 为空各报对应错误；检查——超长、句号结尾给警告，`...` 和问号不警告。
3. 单元：外挂英文 srt 的时间与中文相同；`subtitleOutputs` 在双语时多一个英文 srt。
4. 单元：剪映计划——双语时多一条「英文字幕」轨，中文轨 `transformY` 比单语时上移一行；单语时计划与现在相同。
5. 集成：双语片子 `wka subtitles` 生成英文稿并报待填；填好后 `--preview` 烧录成功，烧录帧里字幕区域比单语时高出约一行（像素检测）；有空条时 `--preview` 报错。
6. 集成：单语片子 `wka subtitles` 不生成英文稿，现有字幕测试全部不变。
7. `node --test tests/unit/*.test.mjs tests/integration/*.test.mjs`、`node tools/lint.mjs`、冒烟测试全过。
