# 第 2 道制作简报：追问式确认 + 简报签批节点

关联 issue：#34

## 问题与目标

第 2 道现在用两轮选择卡片确认 6 项规格，选完只在聊天里回显，没有落盘：`film.json` 要到第 3 道 `wka init` 才有，换会话后简报就丢了；用途、受众、核心信息、必须出现的元素这些方向性内容也没人问。

目标：

1. 第 2 道改为**追问式**确认简报：导演按决策树分轮追问客户，每题给推荐答案，直到双方达成共识。
2. 共识达成后生成一份简报 `brief.md`，作为新的审片节点「① 制作简报」交客户签批。
3. 第 2 道先建**占位片目录**，简报和进度从这一步起就落盘，换会话可以恢复。

## 架构与组件边界

| 组件 | 改动 |
|---|---|
| `plugin/engine/bin/wka.mjs` | 新增 `wka brief <片名> [--dir 项目目录]`；`status` 能列出占位片 |
| `plugin/engine/core/state.mjs` | `REVIEW_GATES` 加第 2 道，节点编号顺延；流程版本升到 3，换算旧标签；`listProductions` 识别占位片 |
| `plugin/skills/director/templates/brief.md` | 新增简报空白模板 |
| `plugin/skills/director/SKILL.md` | 第 2 道改写为追问流程；节点编号顺延；返修选项表加 ① |
| `docs/PRODUCTION-WORKFLOW.md` | 第 2 道行与细则改写；卡片表去掉第 2 道；节点编号顺延 |
| `plugin/commands/film.md`、`README.md` 等 | 凡写到「10 个审片节点」或具体节点编号的地方同步改 |

CLI 不解析 `brief.md`，简报是给人看的 markdown；规格写进 `film.json` 仍由导演在第 3 道 `wka init` 之后完成。

## 接口、数据与行为

### `wka brief <片名> [--dir 项目目录]`

- 建 `<项目目录>/films/<片名>/`，复制 `templates/brief.md` 为 `brief.md`（片名填进标题），记录进度 `step: 1`。
- 目录里已有 `brief.md` 时报错退出，不覆盖。
- 片名为空时打印用法退出。

### 简报 `brief.md`

**必填**（客户已说清的不再问，没说清的都要问到）：片名、故事 / 主题、用途与投放平台、目标受众、一句话核心信息、基调关键词（2–3 个）、片长、画幅、人声、配乐、字幕方式、交付形式。

**有就写**（一轮里一并问一次，客户说没有就写「无」）：必须出现的元素（品牌名、logo、slogan、CTA 等）、禁忌、参考片 / 参考图、期望交付时间。

每项后可标「（推断）」，表示是导演从客户原话推断、客户在追问中确认过的。

### 第 2 道追问规则（写进 director SKILL.md）

- 把简报各项看成一棵决策树：每个决定会引出依赖它的决定（例如选了有人声才问字幕方式）。
- **分轮问**。每轮问「前沿」：前置决定都已定下、不必猜答案就能问的全部问题，一轮问完，然后等客户回答。
- 格式：每题编号，写标题和问题（可含选项），下面一行写推荐答案；措辞让客户答「是」即采纳推荐。
- 客户的回答会改变决策树：已定的决定把前沿往外推。重算前沿再问下一轮；依赖本轮未答问题的题留到下一轮。
- 能自己查的事实（可用风格、TTS 是否安装等）导演自己查，不问客户；决定交给客户。
- 前沿为空即追问结束：决策树每个分支都走到了，没有默默假定的项。**客户确认达成共识前不生成简报。**
- 第一轮必含片名（导演按故事拟工作片名作推荐答案）；片名定下即 `wka brief <片名>` 建占位目录。
- 追问用文字，不用选择卡片。

### 简报签批

- 生成 `brief.md` 后按「审片节点的签批卡片」三步提交：绝对路径 + 贴原文 → 审什么 → 「签批 / 要返修」卡片。
- 签批：`wka signoff films/<片名> "<结论>" --step 2`，`brief.md` 随定版快照进 git。
- 要返修：多选「要改哪些方面」，选项为「目的与受众 / 内容与基调 / 制作规格 / 交付」；改完重新提交 ①。
- 没有卡片的环境：签批必须等客户明确回复，不自动通过（原「未回应项按推荐项推进」的例外取消）。

### 第 3 道衔接

- `wka init <片名> --style <id> --aspect <画幅>` 在占位目录上补齐工程（现有逻辑只在已有 `film.json` 时拒绝，不会覆盖 `brief.md`）。
- 导演按 `brief.md` 把字幕方式写进 `film.json` 的 `subtitles.mode`。
- 第 3 道起各工序以 `brief.md` 为制作规格的依据。

### 进度文件迁移

- `FLOW` 升到 3。flow 1 → 先按原规则把第 11 道起的工序后移一位；flow 1、2 → 再把 history 每条的 `gate` 按当前工序重新取 `REVIEW_GATES[step]`。
- 读取时换算并写回，与现有迁移一致；`wka status` 提示「进度已按新流程换算」。

### `wka status` 与占位片

- `listProductions` 列出 `films/` 下有 `film.json` **或** `brief.md` 的目录。
- 没有 `film.json` 时：标题取目录名，风格显示「未定」。

## 约束、兼容性与非目标

- 不改工序数（仍 14 道）与工序编号。
- 非目标：CLI 解析 `brief.md`、用简报自动填 `film.json`、改其他工序的卡片交互。
- 已有片子（无 `brief.md`）照常推进，不要求补简报。

## 错误处理与运维

- `wka brief` 片名为空、`brief.md` 已存在：打印原因，非零退出。
- 不是 git 仓库时签批照常记录进度，快照跳过（沿用 `commitSnapshot` 现有提示）。

## 验收标准与测试

1. `REVIEW_GATES` 共 11 个，`REVIEW_GATES[2] === '①制作简报'`、`REVIEW_GATES[3] === '②美术定调'`、`REVIEW_GATES[14] === '⑪剪映草稿'`。（单测）
2. flow 2 的进度（gate `①美术定调` at step 3）读取后变为 `②美术定调`，`flow === 3`，并写回文件；flow 1 的进度同时完成工序后移和标签换算。（单测）
3. 只有 `brief.md` 的目录出现在 `listProductions` 中，标题为目录名、风格为「未定」；既无 `film.json` 也无 `brief.md` 的目录不出现。（单测）
4. `wka brief 寒江` 建出 `films/寒江/brief.md`（含片名）与 `.wka/state.json`；再执行一次报错且不覆盖。（集成测试，跑 CLI）
5. 在占位目录上 `wka init 寒江 --style <id>` 成功，`brief.md` 保持原样。（集成测试）
6. `wka signoff films/寒江 "简报签批" --step 2` 输出「审片节点 ①制作简报」。（集成测试）
7. director SKILL.md 与 PRODUCTION-WORKFLOW.md 的节点编号、第 2 道描述与本 spec 一致；`node tools/lint.mjs` 通过。（人工核对 + lint）
8. `node --test tests/unit/*.test.mjs tests/integration/*.test.mjs` 全部通过。
