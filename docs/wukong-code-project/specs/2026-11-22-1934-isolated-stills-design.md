# 并行检查章节静帧

## 问题与目标

章节抽帧在启动浏览器、渲染和保存工作台快照期间持有工程写入锁。同片多个章节的检查只能排队。Remotion 静帧还会打包未请求的镜头，其他章节的导入错误会阻塞本章检查。

## 命令与数据

- `wka still <片目录> --at s01:0.5,s02:1.2 --isolated` 用于主版章节自查。每次调用用独立临时目录，返回静帧目录和接触表的绝对路径。抽帧使用原片画幅和全片时间轴，并支持既有的 `--proxy`。
- 独立抽帧跳过工程锁、共享渲染工作区、阶段账本和工作台快照。排队运行的正式制作命令可以继续。各调用的静帧、接触表和渲染中间文件互不覆盖。
- 普通 `still` 的输出位置和工作台登记沿用现状。Remotion 只为请求的镜头及其依赖打包，普通静帧、独立静帧和词级抽帧共用这一行为。
- 完整静帧、词级检查或副版需要现有制作路径。使用独立模式时拒绝缺少 `--at`、要求词级检查或选了副版的请求。整片小样、签批和成片继续使用工程锁。

## 错误处理与验收

- 一批镜头失败时清理本批临时目录。成功的静帧留在系统临时目录供章节自查，需要正式审阅的静帧按原命令生成。
- 两批同片抽帧在工程锁持续被另一进程持有时成功，各拿到自己的非空静帧和接触表，共享文件不变。普通抽帧和整片渲染仍受锁保护。
- 验证 Browser 和 Remotion 的实际渲染。验证未请求的 Remotion 镜头存在错误导入时仍能抽帧，且指定镜头能读到全片时间轴上的原始起点。
