# 术语表

> 用户可能是第一次做动画。术语第一次出现时，按「解释」一栏用一句大白话说清楚。

写法约定：

- 术语一律写成「中文（English）」：中文用大陆影视、动画行业的通行叫法，英文用行业原词。
- 解释开头标〔本项目用语〕的，是本项目自己的叫法，行业里没有统一说法；代码里有英文名的写代码名，没有的不写英文。
- 国画术语的英文用艺术史上的通行译法。

按类别分节，同一节内大致按制作顺序排：

- 一、制作流程与审片
- 二、剧本与分镜
- 三、镜头语言与转场
- 四、构图与美术
- 五、声音
- 六、字幕
- 七、成片与交付
- 八、引擎与插件
- 九、开发与维护（只面向插件贡献者）

## 一、制作流程与审片

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 工序（Step）/ 第 N 道 | 〔本项目用语〕制作流程拆成的 14 个步骤，按编号称「第 N 道」 | `SKILL.md`「四、制作流程」；签批时 `--step N` |
| 审片节点（Review Gate）/ 签批（Sign-off） | 制作推进到关键环节时，把阶段成果提交给客户审阅，客户明确认可（签批）后才进入下一环节；签批后的内容视为定稿，后续改动按返修处理 | 11 个 ✅ 节点，签批后执行 `wka signoff` |
| 选择卡片 / 签批卡片 | 〔本项目用语〕用弹出的选项卡请用户做选择或签批；弹签批卡片前必须先列出交付物路径 | `AskUserQuestion`；第 2 道制作简报改用文字追问 |
| 决策树 / 前沿 | 〔本项目用语〕第 2 道追问的方法：把简报各项看成一棵互相依赖的决定树，每轮把所有不用猜答案就能问的题（前沿）一次问完 | 第 2 道制作简报 |
| 内部预审（Internal Review） | 提交客户之前，由导演先自查一遍，明显问题先改掉 | 第 4 道签批前自查、第 8 道看接触表、第 11 道看字幕预览、第 14 道交付前自查 |
| 定版快照 | 〔本项目用语〕签批时对工程文件做一次版本存档，返修出问题时可回滚到这个状态 | 每个审片节点自动做一次 git 提交 |
| 回滚（Rollback） | 返修出问题时，把片目录退回某个审片节点的定版快照 | `git log` 找到快照，`git checkout <sha> -- films/<片>` |
| 在制项目 | 〔本项目用语〕还没做完的片子，下次在同一目录运行时会提示接着做 | `wka status`；进度记在 `.wka/state.json` |
| 工作片名（Working Title）/ 占位片 | 工作片名是正式片名定下之前暂用的片名；占位片〔本项目用语〕是定下工作片名就建出、还没选风格的片目录 | `wka brief <片名>`；`wka status` 里风格显示「未定」 |
| 制作简报（Brief） | 立项时确认的制作要求清单，通常包括内容、片长、画幅、声音、交付形式等基本规格，是后续所有工序的依据 | 第 2 道追问确认，写成 `brief.md`，审片节点 ① |
| 投放平台（Platform）/ 目标受众（Target Audience）/ 核心信息（Key Message）/ 行动号召（CTA, Call to Action） | 简报里的几项：片子发到哪、给谁看、一句话要说什么、希望观众看完做的动作 | `brief.md` 的「目的与受众」「内容」，写法见 `specs/BRIEF.md` |
| 交付形式（Delivery Format） | 成片交给客户的形态：只交成片文件，或同时交可继续编辑的工程（如剪映草稿） | 第 2 道确认，第 14 道执行 |
| 美术定调（Visual Development） | 在正式制作前确定影片的整体视觉风格，包括画风、色彩、质感和运动语言。三维动画里的 Look Development 专指定材质、灯光和渲染效果，范围更窄 | 第 3 道工序，从风格库选定一种风格 |
| 声音先行（Pre-recording） | 先定对白和配乐，再按声音的节奏做画面，这是动画行业的惯例；只先做配乐时叫 Pre-scoring | 第 6–7 道工序排在画面制作之前 |
| 声轨审听（Audio Review） | 在画面制作前，单独审听混好的整条声轨（配音、配乐、音效），确认声音效果和节奏 | 第 7 道工序，⑥ 声轨审听 |
| 风格帧（Style Frames） | 正式制作前出的代表性静帧，用来确认构图和视觉效果。行业里通常只出几张定画风；本项目每镜一张，相当于 Design Boards | 第 8 道工序 |
| 动态分镜（Animatic） | 草稿版视频：每个镜头只放一张静止的画，按镜头时长停留、配上声轨，用来看节奏和声画是否同步 | 第 8 道工序，`wka animatic` 输出 `review/动态分镜.mp4` |
| 小样（Preview Render） | 画面已经动起来的低清版成片（降低分辨率和帧率快速渲染），用来审动作、节奏和声音。行业里的 Proxy 指剪辑时替代原素材的低清文件，不是这个意思 | 第 10 道工序，半分辨率、半帧率，命令参数仍叫 `--proxy`；审阅看带声音的 `review/小样.mp4` |
| 技术质检（QC, Quality Control） | 交付前对画面做的技术检查，包括量化指标检测和人工目视检查 | 第 10、13 道工序，`wka qc` |
| 终版渲染（Final Render）/ 终混（Final Mix） | 用最终规格渲染全部画面，并把配音、配乐、音效混合成最终声轨 | 第 12 道工序，`wka final` |
| 终检（Final QC） | 对成片做最后一次质检，确认无误后提交客户终审 | 第 13 道工序 |
| 终审（Final Approval） | 客户对终版成片的最后一次审阅，签批后影片定版，不再修改 | 第 13 道工序，⑩ 终审 |
| 交付（Delivery） | 终审签批后，按交付形式把成片和工程交出去 | 第 14 道工序 |
| 版本号（Version, vN） | 每提交一次编一个号，便于追溯哪一版被签批 | 剧本 v1、v2……；成片第一次终审为 v1，每返修重提加 1；剪映草稿重名时自动命名 `_v2`、`_v3` |
| 返修（Revision）/ 返修流程（Revision Loop） | 根据审片意见修改、重新渲染、再次提交审阅的循环 | 节点内返修、画面返修、声音返修、字幕返修、草稿返修五类 |
| 局部重渲（Partial Re-render） | 只重新渲染改过的那一镜，其余直接读缓存 | `--only s03` |
| 强制签批（--force） | 〔本项目用语〕分镜不符合景别规则时跳过检查强行签批；只在用户明确要这样拍时用，问题会附在签批记录里 | `wka signoff --step 5 --force` |

## 二、剧本与分镜

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 剧本（Story） | 全片的文字底稿：讲什么、分几段、每段什么情绪、说哪几句话；只写给人看，不含代码。先有剧本，再按它做分镜。英文行业通称 Script 或 Screenplay，本项目按文件名 `story.md` 写作 Story | 第 4 道工序，产出 `story.md`，写法见 `specs/STORY.md` |
| 一句话梗概（Logline） | 用一句话概括影片讲什么，用于快速对齐主题 | 剧本的第一部分 |
| 基调（Tone） | 影片的情绪底色，用 2–3 个具体的词描述，如「清冷、克制」 | 简报「基调关键词」；剧本「创作意图与基调」 |
| 梗概（Synopsis） | 用 3–5 句话按时间顺序讲完整个故事，读完能复述全片 | 剧本的一部分 |
| 段落（Sequence）/ 起承转合 | 剧本按「起、承、转、合」分成几段，每段写时间范围、画面、情绪和声音提示；20 秒以内可以把「转」「合」并成一段 | 剧本「段落结构」；分镜「段落」栏 |
| 分镜脚本（Storyboard） | 把片子拆成一个个镜头，逐个写清画面、时长、景别（画面框多大）和声音，是画面制作的施工图。行业里的 Storyboard 通常是画出来的分镜画稿；本项目的分镜脚本是文字表格，画面版由第 8 道的代表帧补上 | 第 5 道工序，产出 `storyboard.md` + `film.json`，写法见 `specs/STORYBOARD.md` |
| 镜（Shot）/ 镜号（Shot ID） | 一个镜头就是一「镜」，按 s01、s02……编号；分镜表、`film.json` 和镜头文件靠镜号一一对应 | 分镜「镜」栏、`shots[].id`、`shots/sNN.js` |
| 景别（Shot Size） | 镜头画面框取范围的大小，从大到小依次为大远景、远景、全景、中景、近景、特写、大特写；景别交替决定画面的视觉节奏 | 分镜「景别」栏，同时写进 `film.json` 的 `shots[].size`；`wka signoff --step 5` 会检查 |
| 景别序列 | 〔本项目用语〕把全片各镜的景别按顺序连成一行，如「特写 → 近景 → 远景」，一眼看出大小有没有变化 | 第 5 道提交分镜时附在表下 |
| 运镜（Camera Movement）/ 动态 | 镜头中的运动设计：镜头本身怎么移动（运镜），画面里什么在动、怎么动、快慢如何（动态） | 分镜「运镜 / 动态」栏 |
| 屏幕文字（On-screen Text） | 作为画面设计的一部分出现在画面里的文字，如片名卡、题诗、落款、印章、片尾 Logo；由镜头代码画出，成片里看得到。**不包含字幕** | 第 4 道写原文，第 5 道落到具体镜头，第 8–9 道画出 |
| 片名卡（Title Card）/ 片尾 Logo（End Logo） | 屏幕文字的两种：开头显示片名的画面、结尾的标识 | 剧本「屏幕文字」 |
| 声音铺底（Bed） | 跨好几镜持续的背景音乐和环境声，不进逐镜表，在分镜表下按全片时间轴单列 | 分镜「声音铺底」；对应 `audio/build.mjs` |
| 示范片 | 〔本项目用语〕每个风格自带的样片（如《寒江》《七十二变》），示范这个风格怎么拍，也是冒烟测试的素材 | 风格目录下的 `examples/<片名>/`；STYLE.md「9. 示范片」 |
| 口播（Talking Head）/ 口播片 | 以人说话讲解为主的信息类视频 | keynote 风格主要服务这一类，字幕默认中英双语 |

## 三、镜头语言与转场

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 帧（Frame）/ 帧率（Frame Rate, fps）/ 分辨率（Resolution） | 视频由一张张画面（帧）连成；帧率是每秒多少帧，分辨率是每帧多少像素 | `film.json` 的 `fps`、`size`；分镜表头 |
| 画幅（Aspect Ratio）：横屏 16:9 / 竖屏 9:16 / 方形 1:1 | 画面的宽高比例；投放竖屏平台时推荐 9:16 | 简报「画幅」；`wka init --aspect`；字幕每条字数也按画幅定 |
| 静帧（Still） | 从某一镜某个时刻单独渲染出的一张静止画面 | `wka still [--frames N] [--at s02:1.5]`，存在 `stills/` |
| 代表帧（Representative Frame） | 每镜挑一张最能代表构图的画面，用来拼接触表、排动态分镜。它不是关键帧，见下一行 | 第 8 道 `wka animatic` |
| 关键帧（Keyframe） | 动画里决定一段动作的关键姿态，或软件里插值用的锚点：只定几个时刻的值，中间由程序补出来 | 代码里的 `wk.keys` 在几个时间点之间分段插值；`specs/SHOT.md` |
| 停顿（Hold） | 动作完成后让画面停留一段时间，给观众留出看清和回味的余地 | 默认每镜动作完成后至少停 1 秒，风格可另定。注意 keynote 里 `hold` 是一种转场，见「续镜」 |
| 缓动（Easing） | 动作快慢变化的曲线，如先快后慢、缓入缓出；代码里用缓动名指定 | `wk.seg(t, a, b, 'sineInOut')`、`wk.ease.*`；STYLE.md「6. 运动语言」 |
| 缓入缓出（Ease In-Out）/ 指数缓出（Expo Out） | 两种常用动作曲线：缓入缓出是起停都缓，对应迪士尼动画十二法则里的 Slow In & Slow Out；指数缓出是急起缓停 | keynote：出现用 expo-out（`reveal`），移动和镜头用缓入缓出（`glide`） |
| 回弹（Overshoot）/ 弹簧（Spring） | 动作冲过头再弹回的效果 | 水墨禁用；运行时刻意不提供；keynote 只在卡片逐个弹出时用 `pop` |
| 推 / 拉（Push In / Pull Out） | 镜头往画面里靠近（推）或往后退（拉）；中文的推拉同时包含移动机位和变焦（Zoom） | 水墨不做 3D 推拉；keynote 用 `Shot` 推近取景，静止截图加 3% 缓慢推进 |
| 横移（Truck / Pan）/ 长卷 | 镜头水平平移，像把一幅长卷慢慢展开 | 水墨运动语言，每秒不超过画宽的 4% |
| 取景（Framing） | 决定画面框住内容的哪一部分、框多大 | keynote `focusOn`、`maxZoom`；景别按取景判断 |
| 神奇移动（Magic Move） | 同一个东西在前后两镜位置、大小或形态不同时，直接移动缩放过去，不硬切。这是 Apple Keynote 的叫法，通用叫法是形变转场（Morph Transition） | keynote 技法「形态变化」`MorphBox`；只做对象级，不做逐字符变形 |
| 转场（Transition） | 镜头与镜头之间的衔接方式；可用的名字由各风格的转场表规定 | 分镜「转场」栏只能填风格转场表里的名字，如水墨的连续 / 墨晕 / 雾遮 / 硬切，keynote 的 fade / hold / 硬切 |
| 转场表 | 〔本项目用语〕每个风格自己规定的可用转场名称、何时用、硬切限额 | STYLE.md「6. 运动语言 · 转场」 |
| 硬切（Cut） | 上一镜直接切到下一镜，不做过渡；非预期的硬切会破坏流畅感 | 第 10 道 `wka qc` 统计，上限是 `style.json` 的 `qc.cuts_max` |
| 淡入（Fade In）/ 淡出（Fade Out） | 画面或声音从无到有（淡入），或从有到无（淡出） | 声音铺底的动作；keynote 转场 `fade`；剪映草稿结尾淡出要用户自己做 |
| 叠化（Cross Dissolve） | 旧画面淡出的同时新画面淡入，两者叠在一起过渡；也叫交叉淡化、溶解 | keynote 要点替换、`MorphBox` 内容替换 |
| 连续 | 〔本项目用语〕水墨转场：前后两镜是同一幅画的不同阶段，后一镜第一帧和前一镜最后一帧相同 | 靠片内公共脚本实现；「连续」的两镜可以同景别 |
| 墨晕 / 雾遮 | 〔本项目用语〕水墨的换画转场：前一镜末尾用墨滴晕开或让雾漫过盖住画面，后一镜再从墨或纸面里显出来 | 水墨转场表 |
| 续镜（Hold Seam） | 〔本项目用语〕keynote 的一种转场：画面不闪，只有文字叠化，后一镜从前一镜最后的取景接着往下 | `exit="hold"` / `enter="hold"`；和「停顿（Hold）」不是一回事 |
| 接缝（Seam） | 〔本项目用语〕两镜交接的那一处；检查时要逐帧比对接缝两边的画面 | 分镜「转场」栏写的就是进入这一镜的接缝 |
| 声画同步（Sync） | 画面动作和声音（人声、音效）在时间上对得上；剪辑行业口语也叫「卡点」。注意「声画对位」在影视理论里指声画刻意形成对比，不是这个意思 | 审片节点 ⑦ 的审阅重点 |
| 节拍（Beat） | 讲解中的一个个时间点，镜头或要点在这些点上切换 | keynote `useStages(beats, …)`；音效密度规则里的「同一拍」 |

## 四、构图与美术

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 美术规格书（STYLE.md） | 〔本项目用语〕每个风格的美学硬约束：色彩、文字、构图、技法、运动、声音、禁忌、质检等，一级章节固定 10 节 | 第 3 道提报前读、选定后通读；分镜里取决于风格的栏都查它 |
| 技术规格书（TECH.md） | 〔本项目用语〕每个风格的技术选型理由和积木用法说明 | 第 3 道选定风格后通读，写镜头时对照 |
| 禁忌清单 | 〔本项目用语〕这个风格绝对不能出现的做法，一条都不能犯 | STYLE.md 第 8 节；第 3 道提报方案、第 4 道自查都要对照 |
| 运动语言（Motion Language） | 一个风格里东西怎么动、多快、用什么缓动、能用哪些转场 | STYLE.md「6. 运动语言」，对应分镜「运镜 / 动态」「时长」「转场」栏 |
| 技法 | 〔本项目用语〕风格里每种画法的短名（如「山石」「题字」），每个名字对应一个积木函数 | STYLE.md「5. 技法」；镜头文件第一行注释写本镜用到的技法，分镜表不写 |
| 景别对照表 | 〔本项目用语〕各档景别在这个风格里具体画成什么样、怎么做到 | STYLE.md「4. 构图 · 景别对照表」 |
| 交付前质检清单（QC Checklist） | 风格的逐项核对表，能量化的交给 `wka qc`，其余靠人看 | STYLE.md 第 10 节；第 10 道 `wka still --frames 4` 抽帧对照 |
| 构图（Composition） | 画面里各元素怎么摆：主体放哪、怎么分层、留多少白 | 风格帧审阅重点；STYLE.md「4. 构图」 |
| 主体（Subject）/ 陪衬 | 主体是这一镜要观众看的东西，陪衬是它周围衬托的环境 | 第 8 道自查：不能整幅只有一个物件；景别按主体占画面的比例判断 |
| 层次：前景 / 中景 / 远景（Foreground / Midground / Background） | 画面里由近到远的几层 | 第 8 道自查：每镜至少占两层，画面发空时要加层次 |
| 留白（Negative Space） | 画面里刻意空着的部分（水墨是纸面，keynote 是深色底） | 风格规定下限，下限不是要贴着做的目标；`wka qc` 量留白比例 |
| 点缀色 / 强调色（Accent Color） | 全片唯一的一种跳色，用量有上限 | 水墨是朱砂，keynote 是橙色；`wka qc` 量占比 |
| 安全框 / 安全区（Safe Area） | 画面中保证在各种屏幕和裁切下都能完整显示的区域，重要内容要放在框内；字幕用的是字幕安全框（Title Safe） | STYLE.md「4. 构图」；第 11 道字幕要在画面中间 90% 的范围内、底边留出画高 5% |
| 字幕带 | 〔本项目用语〕画面底部留给字幕的一条，画面内容不放进去 | keynote 几何；调试时用 `<Guides />` 画出来 |
| 出镜小窗（Picture-in-Picture） | 画面右上角留给真人出镜画中画的区域，标题和要看的内容都要避开 | keynote 构图 |
| 版式（Layout）/ 版式母版（Master Layout） | 预先定好的几种页面布局，规定标题、图、要点各放哪、多大 | keynote 的 L01–L07 加一个细节页，`f.layout.Lxx` |
| 细节页 / 铺满全屏（Full Bleed） | 一镜只有一张图时不放标题，让图铺满整个画面 | `film.json` 镜头标 `"full_bleed": true`，`wka qc` 就不查这一镜的留白 |
| 高亮框（Highlight）/ 压暗（Spotlight） | 用代码描出框，指出界面里要看的地方，可以顺便把四周压暗 | keynote `Highlight`；截图原有的红框要去掉 |
| 代码重绘界面 | 〔本项目用语〕产品界面、截图不直接贴图，而是用代码按原样重画，文案用演示数据 | keynote 技法「界面与截图」 |
| 透视网格（Perspective Grid）/ 暗角（Vignette） | keynote 的背景：深色透视网格加四周变暗，跨镜连续 | `ShotRoot` 自动生成 |
| 计白当黑（Treating Blank as Ink） | 水墨的原则：把留白当作画面的一部分来设计 | 水墨每帧留白不少于 40% |
| 墨分五色（Five Tones of Ink）/ 宣纸（Xuan Paper） | 水墨只用焦、浓、重、淡、清五种墨色加宣纸底色，越远越淡 | `wk.ink.palette` |
| 三远法（Three Distances）：高远 / 深远 / 平远 | 北宋郭熙总结的三种山水取景：高远是从山下仰望山顶，深远是从山前看到山后，平远是从近山望向远山 | 水墨构图，每镜选一种 |
| 散点透视（Shifting Perspective） | 不用一个固定视点的 3D 透视，横向展开像长卷 | 水墨构图 |
| 黄金分割点（Golden Ratio Point） | 画面里约 0.618 比例的位置，主体放这里比居中更有张力 | 水墨构图：主体放黄金分割点或画面一角，不居中 |
| 立轴构图（Hanging Scroll Composition） | 竖幅挂轴式的构图：上面留天、下面留地，主体放中下部 | 水墨竖屏 9:16 |
| 起笔 / 行笔 / 收笔（Stroke Entry / Travel / Exit） | 一笔的三段：起笔由细到粗，行笔粗细轻微抖动，收笔收细 | `wk.c2d.brush` 的 `taper`、`jitter` |
| 飞白（Flying White） | 笔墨跑干时，笔画里留下的顺着笔势的白缝 | `brush` 的 `dry` 参数；水墨交付前质检项 |
| 洇边（Ink Bleed） | 笔画外侧一圈极淡的墨晕 | `brush` 的 `bleed` 参数 |
| 晕染（Ink Wash）/ 水线（Tide Line） | 墨在纸上化开（晕染），化开的边缘留下一圈较深的线（水线） | 水墨技法「墨滴」`wk.ink.drop`（WebGL） |
| 皴法（Texture Strokes, Cun） | 用干笔皴擦表现山石的纹理和质感 | 水墨技法「山石」，用的是简化的皴擦：沿山体向内的短促斜笔 |
| 题字（Inscription） | 竖排、从右起、逐字自上而下写出的屏幕文字 | 水墨技法「题字」`wk.ink.inscribe`，可以逐字跟人声 |
| 落款（Signature） | 题字后面署的作者名、时间等文字，属于屏幕文字 | 第 4 道屏幕文字；第 11 道检查字幕不能压住落款 |
| 印章（Seal）：朱砂白文方印 | 朱砂底、字留白（阴刻）的方形印，随题字落下 | 水墨技法「印章」`wk.ink.seal`，配一声「笃」 |

## 五、声音

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 人声（Voice） | 片中所有说话的声音：画外音、对白、同期声等 | 第 6 道工序确定素材来源；写入 `film.json` 的 `audio.voices` |
| 画外音（VO, Voice-over） | 人声的一种：说话的人不在这个场景里，如旁白、解说、内心独白。中文口语里的「画外音」常常也包括下面的 OS | 分镜「人声」栏的默认类型，`kind: "vo"` |
| 对白（Dialogue） | 画面里出镜角色说的话 | `kind: "dialogue"`；分镜标记 `对白（角色）：` |
| 画外声（OS, Off-screen） | 说话的人不在画面里，但人在这个场景中（如门外的喊声） | `kind: "os"`；分镜标记 `OS（来源）：` |
| 同期声（Sync Sound） | 现场原声或采访录音，AI 配不出来，必须用用户的录音 | `kind: "live"`，必须挂接 `file`；分镜标记 `同期：` |
| 说话人（Speaker） | 这条人声是谁说的，或声音从哪来，如「老者」 | `voices[].speaker` |
| AI 配音（TTS, Text-to-Speech） | 由文字转语音引擎合成的配音 | 第 6 道工序的方案之一 |
| edge-tts / kokoro | 两个 TTS 引擎，装了才能做 AI 配音；edge-tts 支持调语速和音高 | 第 6 道；`wka check` 检查 |
| 音色（Voice）/ 试音（Audition） | AI 配音的声音类型（如云希、晓晓）；用同一句话合成几个音色给用户挑 | 第 6 道 `wka audition`，输出 `review/试听-<n>-<音色>.m4a` |
| 语速（Rate）/ 音高（Pitch） | 调 AI 配音的快慢和高低，如 `-20%`、`-2Hz`；压太多会发怪 | `voices[].rate` / `pitch`；`wka audition --rate --pitch` |
| 声轨（Soundtrack） | 全片的声音：人声、配乐、音效混在一起的一条音频 | 第 7 道工序，`wka soundtrack` 输出，审听副本 `review/声轨.m4a` |
| 配乐（Score） | 为影片专门创作的背景音乐 | 由 `audio/build.mjs` 用代码合成 |
| 配乐脚本（audio/build.mjs） | 〔本项目用语〕每支片里合成配乐、放音效的代码文件，返回各音轨文件；它也叫「脚本」，但不是剧本 | 第 7 道编写；`film.json` 的 `audio.build` |
| 程序化合成（Procedural Synthesis） | 用代码生成原创音乐和音效，不用现成录音 | `audio/build.mjs` 里的 `synth.qin` / `water` / `knock` / `reverb` / `bed` |
| 五声音阶（Pentatonic Scale）/ 古琴拨弦（Guqin Pluck） | 中国传统五音音阶和古琴式的拨弦单音 | 水墨配乐，音要稀疏，允许完全静默；`synth.qin` |
| 背景音乐（BGM, Background Music）/ 环境声（Ambience） | 背景音乐是垫在画面下的音乐；环境声是持续的背景环境声音，如流水 | 分镜「声音铺底」；`bgm.wav`、`ambience.wav`，剪映草稿里各占一轨 |
| 速度（BPM, Beats Per Minute）/ 小节（Bar）/ 琶音（Arpeggio） | BPM 是每分钟拍数；小节是按固定拍数划分的音乐段落；琶音是把和弦的音逐个弹出 | keynote 背景音乐 `synth.bed`：96 BPM 的和弦循环，前 4 小节之后加鼓和琶音 |
| 音效（SFX, Sound Effects） | 落在某个时刻的点状声音，如钟声、「叮」、点击声 | 分镜「音效」栏；`film.json` 的 `cues`；`sfx.wav` |
| 录音音效清单（sfx.json） | 〔本项目用语〕风格自带的录音音效名单，按使用场合命名，音频按需下载到本机缓存 | `style.json` 的 `sfx`；`wka sfx --list`；`sfx.place()`；keynote 见 `SFX.md` |
| 免版税（Royalty-free）/ 可商用、不可再分发 | 录音音效可以商用、免署名，但不能分发文件本身 | keynote 用 Mixkit 音效，只放本机缓存，不进 git、不拷进片目录 |
| 音效密度规则 | 〔本项目用语〕限制音效别太密，如每镜最多一个「叮」、同一拍不叠两个强调音 | keynote；`wka soundtrack` 会打「音效太密」警告 |
| 听感审计 | 〔本项目用语〕混音后在每个音效起点比较音量，比其余声音低 3 dB 以上算「被盖住」，列出来请用户定怎么改 | `wka soundtrack` 日志（用了 `sfx.place` 才跑） |
| 声音同步点（Cue） | 声轨上需要和画面对齐的时间点，例如某句人声的开始、某个音效的落点 | 写入 `film.json` 的 `cues`，镜头代码用 `s.cueIn()` 读取 |
| 入点 / 出点（In Point / Out Point） | 一段素材在时间线上开始和结束的时刻 | `wka soundtrack` 实测每条人声的入出点 |
| 逐字同步点 | 〔本项目用语〕题字这类屏幕文字一字一字跟着人声念到的位置写出来；引擎按停顿分句、句内均分，给每个字估一个时间点 | `voices[].chars: true` → `s.cueChars('名')`；做法见 `specs/SHOT.md` |
| 停顿检测（Silence Detection） | 用 ffmpeg 的 `silencedetect` 测出人声句中的停顿 | 没有逐字同步点时，手工把题字对到人声的备用办法 |
| 闪避（Ducking） | 有人说话时自动把背景音乐压低，说完再回升 | 音轨标 `duck: true`，说话时压到 0.48 倍 |
| 增益（Gain）/ 电平（Level） | 增益是对一条声音做的放大或衰减；电平是这条声音最后的信号大小 | 配乐返回的 `gain`；`sfx.json` 的 `level`、`sfx.place` 的 `volume` |
| 响度（Loudness, LUFS）/ 响度标准化（Loudness Normalization） | LUFS 是衡量整体听感音量的单位；引擎把声轨标准化到目标值，剪映里叫「响度统一」 | `style.json` 的 `loudness`（缺省 -18，keynote -14）；第 7 道日志打出复测值 |
| 峰值归一（Peak Normalization, dBFS）/ 真峰值限制（True Peak Limiting, dBTP） | 峰值归一是把整段声音按比例调大或调小，使最高点正好落在某个值；真峰值限制是压住声音最高点、不超过某个值，以免破音 | 录音音效峰值归一到 -1 dBFS；keynote 声轨真峰值不超过 -1.5 dBTP |
| 分轨（Stems）/ 轨道（Track） | 人声、配乐、环境声、音效各存一个文件，在剪映时间线上各占一条轨，后期可以分开调 | `bgm.wav` / `ambience.wav` / `sfx.wav`；第 14 道草稿轨道表 |

## 六、字幕

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 字幕（Subtitles） | 把人声逐句转成文字、跟着人声的时间显示的文字条，不属于画面设计 | 不算屏幕文字；第 11 道由 `wka subtitles` 生成 `subtitles.srt`，第 12 道按字幕方式烧录或外挂，第 14 道剪映草稿也读它 |
| 外挂字幕 / 软字幕（Soft Subtitles）、烧录字幕 / 硬字幕（Burned-in Subtitles） | 外挂字幕是和视频分开的字幕文件（如 srt），播放器按需显示；烧录字幕是把字直接画进视频画面，任何播放器都看得到，但关不掉 | 第 2 道确认字幕方式（`subtitles.mode`） |
| SRT 字幕文件（SubRip, .srt） | 最常用的外挂字幕格式：纯文本，每条字幕写序号、入出时间和文字 | `subtitles.srt`，可以直接手改断句 |
| 断句（Line Break） | 把一条人声切成几条字幕的位置 | 第 11 道：超过 `max_chars`（缺省横屏 18、竖屏 12、方形 14）先在标点处切，仍超长就按字数硬切 |
| 中英双语字幕（Bilingual Subtitles） | 中文在上、英文在下的两行字幕 | `subtitles.bilingual: true`；英文逐条填在 `subtitles.en.json` |
| 字幕预览（Subtitle Preview） | 把字幕烧录到小样上，先审字体、位置和有没有压字 | `wka subtitles --preview` → `review/字幕预览.mp4` |
| 字幕样式（Subtitle Style）/ 描边（Outline） | 字幕的字体、字号、颜色、描边（字外的一圈深色边）、离底边距离 | `style.json` 的 `subtitles`；片子级修改写 `film.json` 的 `subtitles.style`，逐项覆盖 |

## 七、成片与交付

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| 成片（Final Cut） | 最终交付的视频文件，文件名会标明有没有字幕 | 第 12–13 道，`<name>_有字幕.mp4` / `<name>_无字幕.mp4` |
| 审片文件夹（review/） | 〔本项目用语〕所有请用户审听、审看的文件都放在这里 | `films/<片>/review/`：声轨、试听、接触表、动态分镜、小样、字幕预览 |
| 接触表（Contact Sheet） | 把每个镜头的代表帧拼成一张大图，一眼看完整片的构图和画风 | `wka animatic` / `wka still` 生成，风格帧和 QC 都用 |
| 导出格式（Export Format） | 成片能输出的格式：视频（mp4）、动图（gif）、逐帧图片序列（png-seq）、剪映草稿（jianying） | `film.json` 的 `export.formats`；`wka final --formats` |
| 编码（Encoding）/ H.264 | 把逐帧画面压缩成视频文件的格式和参数 | 终版用 libx264 crf 16，小样用 crf 23 更快 |
| 剪映草稿（JianYing Draft） | 剪映专业版的工程文件：打开后时间线上是分好轨的视频、音频和字幕，可以接着剪 | 第 14 道工序，`wka final --formats jianying` 写进剪映草稿目录 |
| 剪映草稿目录 | 剪映存草稿的文件夹，导出器直接把草稿写进去 | 不在默认位置时用环境变量 `WKA_JIANYING_DRAFTS` 指定；导出前要先完全退出剪映 |
| 剪映字体对照表 | 〔本项目用语〕剪映不能用任意字体文件，导出时按表换成剪映字库里的对应字体（如马善政 → 古风小楷） | `engine/exporters/jianying/fonts.json` |
| 开源授权字体（Open-source Fonts） | 可免费商用的开源字体（如 SIL OFL 授权），本项目只用这类字体 | 登记在 `engine/core/fonts.mjs` 的 `KNOWN_FONTS`，按需下载 |
| 字体子集化（Font Subsetting） | 只保留片子里用到的字，让字体文件变小、渲染更快 | 需要 python3 + fonttools，`wka check` 的推荐项 |
| 交付物包（Deliverables） | 随成片一起交付的全部文件，如封面图、字幕文件、片尾字幕表 | 未采纳的提案，当前流程没有这一项（见 `CHANGELOG.md`） |

## 八、引擎与插件

| 术语 | 解释 | 在本项目中 |
|---|---|---|
| wka | 〔本项目用语〕插件自带的命令行工具，所有制作步骤（建工程、出声轨、渲染、质检、导出）都靠它 | `node <插件根目录>/engine/bin/wka.mjs`，命令表见 `SKILL.md`「一、引擎命令」 |
| 插件根目录（Plugin Root） | 插件安装所在的目录，引擎、风格、模板都在里面 | 不改里面的任何文件；片子级的调整写进片目录 |
| 必需项 / 推荐项 / 可选项 | 〔本项目用语〕`wka check` 的环境检查分级：缺必需项要停下，缺推荐项、可选项只告知影响 | 第 1 道；必需项是 ffmpeg 和渲染管线；缺了运行 `/wukong-animation:setup` |
| ffmpeg | 处理视频和声音的命令行工具，引擎编码、混音都靠它 | `wka check` 必需项 |
| pyJianYingDraft | 生成剪映草稿用的 Python 库，没装就导不了剪映草稿 | 第 14 道，`pip install pyJianYingDraft==0.3.1` |
| 无头浏览器（Headless Chromium） | 没有界面的浏览器，引擎用它逐帧打开镜头页面、截图出画 | browser 管线；setup 时下载到 `~/.wukong-animation/deps/` |
| 按需下载 / 本机缓存（Local Cache） | 字体、录音音效、浏览器依赖都在用到时才下载到用户目录，插件升级不用重下 | `~/.wukong-animation/` 下的 `cache/fonts`、`cache/sfx`、`deps/`；字体可用 `WKA_FONT_MIRROR` 指定镜像 |
| 风格 skill（Style Skill） | 〔本项目用语〕每种风格是一个独立 skill，只管「画成什么样、用什么技术画」；制作流程只在 director 里 | `plugin/skills/<id>/` |
| 72 变 / 第 N 变 | 〔本项目用语〕项目把 72 种风格比作「七十二变」，每种风格是一变 | 水墨是第 1 变，keynote 是第 70 变，自定义风格从第 73 变起 |
| 风格库（catalog.json） | 〔本项目用语〕全部风格的自动生成索引，美术定调时从这里挑 | 第 3 道；`wka list styles` |
| available / planned / experimental | 〔本项目用语〕风格或插槽的状态：可以直接开拍、还没搭建（规划中）、实验性 | `catalog.json` 的 `status`；planned 不能出现在方案卡片里 |
| 自定义风格（Custom Style） | 〔本项目用语〕用户自己新建、存在用户目录里的风格，升级插件不会覆盖 | `wka new style`；`~/.wukong-animation/styles/`；列表里标 `[用户]` |
| style.json | 〔本项目用语〕风格的机器可读配置：管线、工具包、字体、qc 阈值、响度、音效清单、字幕样式 | 各风格目录 |
| qc 阈值（QC Thresholds） | `wka qc` 判断合不合格的界线：最少留白、点缀色上限、相邻帧差上限、硬切次数 | `style.json → qc`（`whitespace_min` / `accent_max` / `diff_max` / `cuts_max`） |
| 帧间差异（Frame Difference）/ 黑帧（Black Frame）/ 空帧（Blank Frame）/ 超标帧 | QC 量的指标：相邻两帧变化多大（太大像闪），有没有全黑或空白的帧；不合格的帧叫超标帧 | `wka qc`；超标帧拼在 `stills/qc/qc-sheet.jpg` |
| 管线（Pipeline） | 把镜头代码变成视频片段的渲染方式：browser 用无头浏览器逐帧截图，remotion 用 React 组件，manim 在规划中 | `style.json` 的 `pipeline` |
| 工具包（Kit） | 〔本项目用语〕多个风格共用的绘图函数库（如 canvas2d、webgl） | `style.json` 的 `kits`；代码里挂在 `wk.<名>` 下 |
| 导出器（Exporter） | 把渲染好的画面和声轨编码成某种交付格式（mp4、gif、剪映草稿……） | `film.json` 的 `export.formats` |
| 插槽（Slot） | 〔本项目用语〕管线、工具包、导出器三类可扩展模块的统称；放进对应目录就会自动注册 | `engine/pipelines/`、`engine/kits/`、`engine/exporters/` |
| 风格积木 / 风格资产库 | 〔本项目用语〕风格把最难写的技法做成可直接调用的组件，镜头只做编排、不从零写 | 水墨 `wk.ink.*`，keynote `@wka/style`；风格的 `scripts/` |
| 运行时（Runtime，wk.*） | 所有风格都能用的基础函数：进度、缓动、插值、随机、噪声、字体 | `wk.seg`、`wk.keys`、`wk.ease` 等，见 `specs/SHOT.md` |
| 2D 画布（Canvas 2D） | 浏览器的 2D 画布，适合逐笔控制的手绘效果，不需要显卡也快 | canvas2d 工具包，水墨主要用它 |
| 着色器（WebGL Shader） | 在显卡上逐像素计算的小程序，用于晕染这类 2D 画布做不出的效果 | webgl 工具包 `wk.gl.shader`；没有显卡时用软件模拟 |
| 噪声（Noise）/ 分形布朗运动（fBm） | 生成自然起伏（山脊、斑驳、不规则边缘）用的随机函数 | `wk.noise`；shader 里的 `{{noise}}` |
| Remotion | 用 React 写视频的框架，每镜一个组件 | remotion 管线、keynote 风格；个人和不超过 3 人的公司免费，更大的公司需要购买授权 |
| 片目录 | 〔本项目用语〕一支片的全部文件所在的文件夹 | `films/<片名>/` |
| 工程文件（film.json） | 〔本项目用语〕一支片给引擎读的完整描述：镜头列表、时长、景别、种子、声音、字幕、导出设置，和分镜表逐镜对应 | 第 3 道生成，第 5 道起填写；字段见 `specs/FILM.md` |
| 进度文件（.wka/state.json） | 〔本项目用语〕记录这支片推进到第几道、每个审片节点的结论，用来恢复在制项目 | `wka status`、`wka signoff` |
| 缓存目录（.cache/）与 mix.wav | 隐藏的缓存目录，放镜头片段和混好的整条声轨 `mix.wav` | 文件大，不交给用户；审听用 `review/声轨.m4a` |
| 镜头文件 / 镜头代码 | 〔本项目用语〕每镜一个代码文件，引擎逐帧调用它画出画面 | `shots/sNN.js`（remotion 是 `.tsx`），第 8–9 道；写法见 `specs/SHOT.md` |
| 片内公共脚本 | 〔本项目用语〕多镜共用的场景画法写在一个文件里，各镜只传「画到哪一步」，镜头之间天然连续 | `shots/common.js`，在 `film.json` 的 `scripts` 里声明 |
| 纯函数（Pure Function） | 镜头的 `render` 只由时间 t 决定画面：同一个 t 永远画出同一帧，不能累加状态 | 镜头铁律第 1 条 |
| 确定性渲染（Deterministic Rendering） | 同一份工程每次渲染结果完全一致，所以可以乱序、并行、只重渲一镜 | 运行时会拦截 `Math.random()` |
| 种子（Seed） | 决定随机效果的数字；换种子等于换一版「笔迹」，构图不变 | `film.json` 的 `seed`；`s.rng`、`wk.rng(seed)` |
| 单位系数（s.u） | 〔本项目用语〕长度、笔宽都按 1080p 设计再乘 `s.u`（画高 / 1080），这样小样、竖屏、终版构图一致 | 镜头铁律第 3 条 |
| 设计尺寸 / 自然尺寸（Natural Size） | 设计尺寸是镜头按正式画幅写的大小，小样由管线缩小；自然尺寸是截图原本的像素大小 | remotion 的 `W/H`；keynote `Shot` 的 `natW/natH` |
| 镜头缓存（Shot Cache） | 每镜渲染后存缓存；代码、种子、用到的同步点等任何一项变了才重渲这一镜 | `wka render`、`wka final` 自动使用；同步点名要写成字面量 |
| 缓存图层 / 离屏画布（Offscreen Canvas） | 画好之后不再变的部分先画到一张看不见的画布上存起来，之后每帧直接贴上去，加快渲染 | `wk.c2d.cached` / `offscreen` |
| 镜头片段 / 拼接（Concatenation） | 每镜先单独渲染成一段视频，再按顺序拼起来、混音、导出 | 渲染数据流，见 `docs/ARCHITECTURE.md` |
| 并行渲染（WKA_WORKERS） | 同时开几个页面渲染不同镜头 | 环境变量，默认 min(2, CPU 数) |
| 胶片颗粒（Film Grain）/ LUT 调色（LUT Grading）/ 遮幅（Letterbox） | 通用后期效果：仿胶片噪点、套用调色表、上下黑边 | film-post 工具包，规划中 |
