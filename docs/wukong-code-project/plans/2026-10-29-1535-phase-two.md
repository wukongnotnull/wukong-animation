# 第二批实施计划

目标：按已批准的词级同步与字幕预检两份 spec，提供有来源的词锚点和保留人工编辑的字幕检查。

架构：word-sync 独立负责音频来源与运行时词 cue；subtitle-preflight 复用字幕实际布局。job/CLI 仅接入两类能力及报告，原视频时间轴继续由第一批 timing 模块维护。

技术栈：Node.js ESM、node:test、Chromium/Playwright、Remotion、ffmpeg/ffprobe。

依据：[词级同步 spec](../specs/2026-10-29-1527-word-sync-design.md)、[字幕预检 spec](../specs/2026-10-29-1527-subtitle-preflight-design.md)。用户已批准两份文件。

## 全局约束（原文摘录）

- 不改写用户字幕、录音、镜长或已签批快照；锚点文件是用户可版本管理的普通文件。
- 旧 char cue 数值保持兼容，只纠正其日志和文档来源表述；不把近似结果升级成词首实测。
- 不接入付费服务，不新增配音平台或模型下载；外部对齐结果只导入并核对，不替用户注册服务。
- 保留人工 SRT 与英文稿，修改样式不改镜头缓存；改版字幕仍使用各自文件。
- 不做通用中文语义分词、不重新翻译、不替用户修改画面重要元素，不改变首批视频帧时间轴。

## 文件与职责

- core/word-sync.mjs、schemas/sync-points.schema.json：来源、锚点解析、帧定位、报告。
- audio/soundtrack.mjs：写真实人声来源并纠正估算日志。
- core/job.mjs、cues.mjs、Browser runtime、Remotion entry/WkaShot：注入词 cue、依赖失效、帧入口和抽帧证据。
- core/subtitles.mjs 与 schemas：保护术语与既有英文重排。
- core/subtitle-layer.html/.mjs：同一字幕渲染中返回实际字框、字号及字体状态。
- core/subtitle-preflight.mjs、CLI、Keynote 配置：预检报告、几何检查、样张与交付门槛。
- tests/unit/word-sync.test.mjs、subtitle-preflight.test.mjs、相关已有单测，以及两类集成测试：来源失效、呈现帧与人工文件保护。

## 实施顺序与验证

1. 先给已有 cue 识别和字幕断词补回归，运行确认缺功能而失败：`node --test tests/unit/cues.test.mjs tests/unit/subtitles.test.mjs`。
2. 先写来源/锚点/帧坐标测试，确认失败；实现最小 word-sync 和声音来源接入；运行对应单测与两管线实际帧呈现集成测试，通过后提交。
3. 先写术语与英文保护、实际字框/安全区/重要区域测试，确认失败；实现预检与现有文件只读检查；运行字幕相关单测和集成测试，通过后提交。
4. 接入报告与现有审片门槛，补文档；所有修改都按“失败测试→确认根因→最小实现→通过→提交”。
5. 运行 npm test、npm run lint、npm run smoke，以及受影响的107镜时间轴矩阵；记录通过、失败、跳过与人工待审项。更新 #93，交付可审阅 PR，不合并或发布插件。
