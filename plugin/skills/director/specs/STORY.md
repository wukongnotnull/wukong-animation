# 剧本填写规范（story.md）

> 剧本是一支片的文字底稿，写给人看，不含代码。它回答四个问题：这支片讲什么、分几段讲、观众听到什么、画面上出现哪些字。第 5 道分镜按它的段落拆镜头，第 7 道配乐按它的声音提示合成，所以它是全片的源头。

- **工序**：第 4 道 · 审片节点 ③ 剧本
- **模板**：`engine/templates/film/story.md`，第 3 道 `wka init` 建工程时带出空白稿 `films/<片名>/story.md`
- **输入**：签批过的 `brief.md`（核心信息、基调、片长、画幅、有无人声、有无配乐）；选定风格的 `STYLE.md`（基调、运动语言、声音、禁忌清单）；用户带来口播稿时还有片目录里的 `口播稿.md`（用法见「三、有口播稿时」）
- **流程**：怎么提交、征询哪几点见 `../SKILL.md` 第 4 道
- **示例**：`ink-wash/examples/hanjiang/story.md`

## 一、不在这里写的

本项目里还有几样东西也叫"脚本"，都不在这道工序写：

| 容易混淆的 | 区别 |
|---|---|
| 分镜脚本 `storyboard.md`（第 5 道） | 剧本按**段落**写，分镜脚本按**镜头**写；景别、运镜、转场留给分镜 |
| 镜头代码 `shots/sNN.js`、片内公共脚本 `shots/common.js` | 画面的代码，第 8–9 道写 |
| 配乐脚本 `audio/build.mjs` | 合成音乐的代码，第 7 道写 |

## 二、逐部分写法

| 部分 | 写什么 | 写到什么程度 |
|---|---|---|
| 基本信息 | 标题写片名；表里写片长、画幅、风格 id、剧本版本号 | 与第 2、3 道签批的规格一致<br>首稿 v1，返修一次加 1 |
| Logline | 一句话说清这支片讲什么 | 一句，30 字以内，有主体、有发生的事<br>不写"展现了""体现了"这类空话 |
| 创作意图与基调 | 想让观众感受到什么、目标受众、情绪基调 | 基调用 2–3 个具体的词（如"清冷、克制"）<br>不违背风格 `STYLE.md` 的"适合 / 不适合" |
| 梗概 | 用 3–5 句讲完整个故事 | 按时间顺序，读完能复述全片<br>没有情节的意象片，写画面如何一步步展开 |
| 段落结构 | 按起承转合分段，每段写时间范围、画面在发生什么、情绪、声音提示（配乐情绪、关键音效） | 时间首尾相接、不重叠，加起来等于片长<br>单段不短于 3 秒（分镜单镜 3–8 秒）<br>20 秒以内可以把"转""合"合成一段<br>声音提示写到"什么声音、大约第几秒" |
| 人声文案 | 人声原文，每条以 `[段落]` 开头标出所在段落 | 每段字数不超过"段落秒数 × 3.6"（中文约每秒 3.6 字）<br>句与句之间留停顿，语气贴合风格（如水墨要短句、停顿 ≥ 0.8 秒）<br>没有人声写"无"，并写明用什么声音代替 |
| 屏幕文字 | 由镜头代码画进画面的文字：片名卡、题诗、落款、印章、片尾 Logo 等 | 每条写出原文、所在段落、出现形式；引用的诗句注明出处<br>没有写"无"<br>**不包含字幕**：人声原文只写在「人声文案」，字幕第 11 道按人声自动生成 |

## 三、有口播稿时

用户带来了现成的口播稿（`口播稿.md`），它就是写剧本的素材：人声用用户的原句，其余各部分围绕它写。

| 部分 | 怎么用口播稿 |
|---|---|
| 人声文案 | **原句照搬**，按段落加 `[段落]`；不润色、不改口吻，口头禅也留着。要改的句子只进改稿建议表，用户同意了才改 |
| 段落结构 | 一段一个观点，按稿子里观点的先后切分；时间按字数估（每秒约 3.6 字），片长以稿子为准。「画面在发生什么」逐段写出画什么、怎么动 |
| 梗概、Logline | 从稿子里提炼，不加稿子里没有的观点 |
| 屏幕文字 | 写口播没说出口的那一层：标题写提炼的结论，要点写口播没说的信息，步骤写界面上的原始标签；不照抄口播 |

**改稿建议**：写「画面在发生什么」时，指不出画什么、怎么动、要什么素材的句子，就是要提建议的地方。常见的几类：

| 问题 | 表现 | 改法 |
|---|---|---|
| 抽象形容 | 「强大」「丝滑」「直击痛点」 | 换成一个看得见的结果：「改了哪几行，一眼看到红绿」 |
| 一句多点 | 一句里讲了三个功能 | 拆成三句，各自成段；或改成步骤 |
| 否定句 | 「你肯定没有」「不用再……」 | 画面画正面的「我有，它长这样」，否定留在口播里当钩子 |
| 数字无参照 | 「快了 30%」「节省很多」 | 给对比：之前 vs 之后 |
| 指代不清 | 「这个」「那边」「它」 | 第一次出现说全名：「Git 图谱面板」 |
| 看不见的动作 | 「我试了很多方法」 | 换成屏幕上发生的事，或用图形隐喻 |
| 缺素材 | 提到别人的界面、网页、数据 | 句子保留，列出要用户提供的截图 / 录屏；拿不到就改写 |
| 句子太长 | 一句 30 字以上一口气说完 | 在意思停顿处断句，字幕一条放得下 |
| 顺序跳跃 | 讲完 B 又回到 A | 按画面出现的顺序重排 |

转场句（「这只是开胃菜」）、开场和片尾只有一句大字的段落都是允许的，不要求句句有画面。

建议写进片目录的 `review/改稿建议.md`，随剧本一起提交：

```
| # | 原句 | 问题 | 建议改法 | 改后画面 |
|---|---|---|---|---|
| 1 | 「它的功能特别强大」 | 抽象形容，没有可画的对象 | 「它能把 20 个分支的合并关系画成一张图」 | 图谱全景，分支逐条亮起 |
```

表后附：需要用户提供的素材清单（每项写用途）、按字数估的时长。用户同意的条目改进剧本的人声文案，版本号加 1；用户坚持保留的句子按原句想办法画。`口播稿.md` 始终是原稿，不改。

## 四、示例：段落结构

示范片《寒江》（12 秒、无人声）的段落结构：

| 段落 | 时间 | 画面在发生什么 | 情绪 | 声音提示 |
|---|---|---|---|---|
| 起 | 0–4s | 宣纸上远山清墨淡入，近岸淡墨山晕染，山脚落一点墨石 | 静，像屏住呼吸 | 极轻的流水声铺底；0.6s、3.2s 各一声古琴（D3、A3），音与音之间留空 |
| 承 | 4–8s | 江面几笔水纹写出，右下一叶小舟随之写成，停住 | 开阔，带一点孤寂 | 6.0s 一声古琴（G3） |
| 转合 | 8–12s | 右上竖排题字逐字写出，落一方朱砂印，留白收尾 | 落定、回味 | 10.8s 落印一声轻"笃"，之后只剩流水 |

## 五、签批前自查

导演先过一遍，再提交：

- [ ] 七个部分都填了
- [ ] 各段时间加起来等于片长
- [ ] 每段人声都没有超出段落时长
- [ ] 屏幕文字每一条都标了所在段落和形式
- [ ] 有口播稿时：人声文案与 `口播稿.md` 逐句一致，不一致的每一处都是用户同意过的改稿建议
- [ ] 基调与内容没有触犯风格 `STYLE.md` 的禁忌清单
