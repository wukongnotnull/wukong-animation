# v0.19.4 · 大文件读取与预览性能优化

本版交付第三批性能优化：有界文件哈希、单次来源扫描去重，以及完整配对测量证据。[实现 PR #118](https://github.com/wukongnotnull/wukong-animation/pull/118) · [跟踪 #113](https://github.com/wukongnotnull/wukong-animation/issues/113)

## 改了什么

- **大文件哈希按块读取**：单次读取和缓冲区最多 1 MiB，避免随音轨大小分配整块内存；摘要和缓存的原有字节契约保持一致。
- **一次扫描只读一次同一来源**：单次同步来源扫描内复用摘要，结束前检查文件和目录变化。下一次扫描、跨异步阶段及交付双遍检查继续独立读取。
- **可复核的性能证据**：57 个配对场景、570 次正式计时、114 次独立探针，零超出批准门槛的回退；三平台新增确定性的文件读取边界测试。

## 实测收益与边界

在 M1 Pro、16 GiB 内存的同机配对中，107 镜、约 256 MiB 音轨的无修改预览中位耗时：browser **33.882 → 15.988 秒**，Remotion **33.964 → 15.601 秒**，约减少 **53%–54%**；主 Node 峰值 RSS 从约 **617–620 MiB 降至 108 MiB**。

这是主 Node 的指标，不是整套进程树总内存。首次整片制作收益较小，Remotion 部分首次制作内存持平或增加；测试不能外推到所有硬件、网络盘或复杂 4K 镜头。完整输入、五轮原始数据、回退判定与限制见[验收报告](../wukong-code-project/reports/2026-10-31-performance-phase-three-validation.md)。
