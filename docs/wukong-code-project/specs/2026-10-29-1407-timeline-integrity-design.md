# 统一时间轴与累计误差质检

Status: Draft — 等待用户审阅本文件

日期：2026-10-29（Asia/Shanghai）

依据：已批准的 [PRD](../prd.md) FR-1、FR-2；[体验报告](../reports/2026-10-29-codex-editing-experience.md)；[issue #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。源码基线 `dd230e7`（插件行为同 `8daae3e`）。以下为本次提交审阅的具体设计，获批前不实现。

## 1. 问题与目标

当前计划切点来自镜头时长的连续累加，但 Browser 和 Remotion 均独立计算每镜帧数。Remotion 小样还把每镜独立降帧。片段直接拼接后，实际切点可能逐渐偏离配音时间轴。现有 QC 按计划时间判断镜号，不先检查实际视频时长。

本批交付一个跨管线的帧时间约定和验证链：对 Browser、Remotion 的主副版、高清与小样，每个切点及片尾相对原计划偏差不超过一个输出帧；缓存、字幕和导出不得掩盖偏差。不自动改写 film.json。

已核实边界：film schema 仅允许整数 fps，范围 1–120；每镜 duration 最小 0.1 秒。Manim 是 planned 占位管线，不新增实现。小样输出帧率沿用 `max(1, round(film.fps / 2))`。

## 2. 架构与组件边界

| 组件 | 本批职责 |
| --- | --- |
| `core/timing.mjs`（新增） | 纯函数构建帧时间轴；媒体探测、帧数与时间戳校验；生成可审阅报告 |
| `core/job.mjs` | 创建任务时附加统一帧分配，计入镜头哈希；验证片段后拼接，再验证拼接视频；动态分镜使用同一分配规则 |
| Browser 管线 | 按任务给定帧数绘制，停止独立舍入 |
| Remotion 管线 | 主渲染帧数取统一的 film.fps 时间轴；代理降帧精确匹配输出帧时间轴 |
| `core/qc.mjs` | 先验证时间轴，再做像素 QC；按实际帧切点归属镜号；时间检查不通过时总体不通过 |
| CLI、字幕预览、MP4 导出 | 输出前验证来源视频；输出后验证视频帧数和帧率；未通过不打印完成或提交签批 |
| 管线 README、模板、director | 记录新帧分配约定、诊断报告与恢复说明，避免再指导用户手动量化所有镜长 |

不在本批改关键词 cue API、字幕断句、配乐编排或主版 PSNR 复用。

## 3. 接口、数据与行为

### 3.1 帧时间轴：先切点后镜长

对镜头原始时长 d₀…dₙ₋₁ 和当前输出帧率 F：

```text
T₀ = 0
Tᵢ = sum(d₀ ... dᵢ₋₁)
Bᵢ = round(Tᵢ × F)
Nᵢ = Bᵢ₊₁ - Bᵢ
```

`B` 是整个视频从 0 开始的切点帧号，`N` 是每镜帧数。时间范围采用左闭右开 `[Bᵢ, Bᵢ₊₁)`。不得把 `round(dᵢ × F)` 或逐镜至少一帧再求和作为替代。

新增纯函数 `buildFrameTimeline(shots, fps)`，返回：

```text
{ version: 1, fps, totalFrames, duration,
  shots: [{ id, plannedStart, plannedDuration, startFrame, endFrame, frames }] }
```

`duration` 为 `totalFrames / fps`，`plannedStart/plannedDuration` 保留原始秒数。累计浮点只做正常数值计算；整数附近允许有限精度误差，测试覆盖临界值，不引入会随镜数累积的固定补偿。

所有正常切点的量化误差至多 0.5/F 秒（除浮点容差）；验收对外上限为 1/F 秒。29.97、30000/1001 不在当前 schema 支持范围内，本批维持现有校验错误，不偷偷取整。

**极短镜头：** 任一 `Nᵢ <= 0` 时，渲染或动态分镜在启动媒体进程前拒绝，报告镜号、时长和输出 fps，并建议调整镜长或使用足够高的帧率。不能静默删镜、补成一帧或修改 film.json。低帧率下合法的 0.1 秒镜头也可能触发此条件；声轨制作和原始工程读取不受此限制。

### 3.2 任务参数与画面时间语义

`loadFilm` 保留原始 shots 的 `start/duration` 与 totalDuration，避免改变声轨和声音 cue。创建渲染任务时计算 output timeline（job.fps）和 native timeline（film.fps），为管线镜头附加 `frames`、`nativeFrames`、`startFrame`；`job.timeline` 指当前输出帧时间轴。

- Browser：画 Nᵢ 帧；局部 `t = frame / job.fps`，`s.start/s.T` 仍为原计划值。
- Remotion：Composition 的 fps 与组件 `s.fps` 仍为 film.fps，`dur` 改为 native timeline 分配帧数，避免代理输出改变所有现有按帧动画的速度。
- 量化可能使最后一帧略超出名义镜长，属于不超过一输出帧的采样；不拉伸整个镜头、不重新缩放声音 cue。
- 静帧保持用户指定秒数语义；只有可呈现帧范围按新的 native/output timeline 夹取。
- 主副版共用原镜头序列和时长，按相同 fps 得到相同切点帧号；尺寸与覆盖文件不参与时间量化。

### 3.3 Remotion 代理输出

高清直接使用 nativeFrames。代理保留现有“按 film.fps 渲染再降帧”方式，但最终片段必须恰有 output timeline 分配的 frames，时间戳从 0 开始且间隔为 1/job.fps。

在降帧/缩放阶段显式截取目标帧数；若转换结果少帧，最多以镜尾帧补足两输出帧，再精确裁至目标数。此上限覆盖 native/output 两套量化边界带来的差额。超出此范围应按异常报错，不能补任意数量的静帧来掩盖缺失镜头。正常转换的校验必须在写入缓存前完成。

可采用 ffmpeg 的 fps、末帧延展、按帧 trim 和 setpts 组合；具体滤镜排列由实施测试确定，验收不绑定命令字符串。不得用最终视频 `-t`/`-shortest` 修剪来代替切点正确性。

### 3.4 动态分镜与导出时间线

动态分镜沿用 12fps，将统一规则用于每镜图片停留帧数，通过帧数裁切各输入并重置时间戳后拼接；不继续把独立秒数 `-t` 的量化结果当作最终时长。完成后也做媒体时间检查。

`render` 返回的 segments `start/duration` 改为实际输出帧区间对应的秒数，供剪映导出使用；原始计划值保留在 job.shots 与 timing 数据中。交给导出器的 timeline.duration 使用实际视频总帧时长，音频 cue 保持原秒数。高清、小样与副版不能互相混用时间线。

### 3.5 实测校验和报告

时间检查独立于像素 QC 的 10fps 抽样；使用 ffprobe/解码帧信息核对视频轨帧率、解码帧数、首帧与末帧时间、帧间隔，不把含 AAC padding 的容器总时长作为唯一依据。

验证顺序：

1. 每个新片段校验通过才提交缓存；命中缓存的片段在拼接前同样探测，错误片段拒绝使用。
2. 根据实际片段帧数形成累计切点，与规划的 Bᵢ 比较。正常片段帧数必须等于 Nᵢ，比产品的一帧上限更严格。
3. 校验拼接视频总帧数、CFR 时间戳及总视频时长，不能只检查片段之和。
4. 小样配音版、字幕预览、烧录视频和最终 MP4 输出后再次校验视频轨。音频过短导致现有 `-shortest` 截断时报告失败，提示检查声轨；不擅自拉伸或补全用户音频。

探测失败、帧率不符、读不到完整帧数、非连续时间戳或未达到约定帧数均不是通过。时间戳误差容忍一个媒体 time_base tick；计划秒数到帧的量化容忍一个输出帧。这两类容差分别报告。

报告写入 `review/时间轴检查[-<画幅>][-proxy].json` 和同名 `.md`。动态分镜使用 `时间轴检查-animatic[-<画幅>]`，避免与成片混淆。报告包括 version、画幅、用途、输出 fps、期望/实测总帧数、每镜计划秒数、期望/实测切点、偏差及错误；通过时写“视频时间轴检查通过”，不宣称关键词或旁白语义同步通过。

在当前画幅缓存下分别保存 `timing.json` / `timing-proxy.json` 的来源信息：输入时序签名、按序片段路径及各片段文件 SHA-256、拼接视频 SHA-256、timeline。此文件用于关联校验对象，不代替再次探测。时序签名覆盖有序镜头 id/duration、画幅、fps、proxy 与 timing version；路径按片目录解析。QC 先确认文件签名与当前输入匹配，再执行媒体探测。报告缺失或过期不能复用旧的通过结论。

导出后检查的数据附在同一报告的 outputs 列表，逐项标记文件、帧数和结果；外部剪映草稿、GIF 不套用 MP4 视频轨探测，它们使用已通过的来源时间线。

### 3.6 QC 行为

`runQc` 先运行上述检查，再做已有像素检查。报告不存在或来源不匹配时，时间检查为“未验证/需重新渲染”，总体不通过；已有工程可通过重新 render 建立证据，不能无证据给旧视频补一份通过报告。

切点匹配时按统一帧时间轴归属镜号和边界。时间检查失败时仍保留诊断，但不把按错误计划归属的像素问题称为确定镜号；时间报告优先指向相关片段。CLI `qc` 继续用退出码 2 表示不通过。

## 4. 约束、兼容性与非目标

- 不增加必填 film.json 字段；不修改原镜头时长、旁白、字幕文本或客户工程。
- 镜头哈希纳入 timing version、nativeFrames、frames 及切点，避免旧规则片段命中新规则缓存。修改前镜长造成后镜量化帧数变化时，受影响镜头必须失效。
- 不自动删除或覆盖 `.cache/approved/`、approved.main、签批历史。主版已有签批时，发现新旧哈希或帧数差异必须明确提示；副版仍用原快照比较，真实切点变化不得标为主版不变。
- 只有用户明确要求重出主版时才执行主版重渲。重渲不等于重新签批；新的时间分配改变定稿时，交回第 13 道审阅，原快照保留至用户实际重新签批。
- 不引入旧时间规则兼容模式来继续制造累计误差；旧报告或快照缺失时如实说明无法证明。
- 不发布版本、不改已安装缓存；不实现 Manim，不扩展小数帧率，不在本批优化 PSNR 比对缓存。
- 不承诺识别声音与画面内容是否表达同一件事；词级同步属于后续 FR-3。

## 5. 错误处理与运维

- 零帧分配：启动渲染前失败，指出镜头与 fps，原工程不变。
- 片段校验失败：不提交新缓存、不拼接；已有命中片段失效，报告明确建议重渲相应镜头。不把损坏文件继续写成新的通过 manifest。
- 拼接或最终输出失败：保存失败报告、不打印“完成”，不触发自动签批；下次依靠正常镜头缓存恢复。
- 单镜校验先通过、拼接失败时，已通过缓存继续保留；下次仍验证后才能复用。
- QC 不可解码或来源签名不符时返回不通过，并保留可执行的修复提示。
- 校验成功才写正式 timing manifest，使用临时文件加原子改名；已有成功记录与当前文件不匹配时视为失效。
- 不添加用户选择卡片或额外审片节点，复用现有 QC 与终审流程；必须把时间报告纳入审片交付。

## 6. 验收标准与测试

实施时按 TDD 先补会失败的回归测试，确认失败原因是独立量化/缺少校验，再逐项实现；不得通过更新预期来接受累计漂移。

| 场景 | 预期证据 |
| --- | --- |
| 107 镜 × 1.02 秒，30fps/15fps | 总帧数分别为 round(109.14×30)=3274 和 round(109.14×15)=1637；每个实际切点匹配 Bᵢ，不随镜数偏移 |
| 交替镜长、整数帧镜长、临界小数、24/25/30/60/120fps及奇数 fps | 累积切点单调，总长匹配；小样沿用现有 fps 规则；整数帧原本正确的用例不改变帧数 |
| 0.1 秒镜头、1fps 和足够高 fps | 低 fps 零帧时明确失败；高 fps 正常；film.json 字节不变 |
| 29.97fps 输入 | 现有 schema 拒绝，不取整后继续 |
| Browser 与 Remotion，横/竖，高清/小样 | 真实渲染与 ffprobe 验证帧数；107 镜用低分辨率简单画面降低成本，不能只测数学函数 |
| Remotion 31 原生帧降到15fps | 按累计分配目标输出；同时覆盖需要裁一帧和补尾帧的镜头；时长不再逐镜增长 |
| 实际拼接切点 | 用可区分镜头标记，解码检查每个边界前后帧所属镜头；不能仅按 manifest 声称画面切点正确 |
| 动态分镜 | 12fps 实际帧数和每镜切点匹配统一计划，音频存在与不存在均验证 |
| 缓存重用/前镜时长变化/旧分配片段 | 正常缓存命中；时序受影响时失效；错帧数缓存被查出，不能被拼接 |
| 正负偏移互相抵消 | 即使全片总帧数相同，中间切点偏移仍判失败 |
| 改坏片段、替换拼接视频、过期报告 | 帧探测或来源签名校验发现问题；QC 退出2，不显示时间检查通过 |
| 字幕预览、烧录版、无字幕版、音频短于视频 | 正常版帧数保持；被截短的版本报告失败，不靠容器时长掩盖 |
| 旧主版签批与副版保护 | 原快照和签批记录不变；新规则改变画面/帧数时不能通过原主版不变检查；需实际重审后才更新 |

建议测试落点：`tests/unit/timing.test.mjs`（新增）、现有 remotion-entry / shot-hash / qc-judge 单测，以及 `tests/integration/timing.test.mjs`（新增）和现有 render / remotion / variants / subtitles 集成测试。依赖缺失必须明确报告未验证，交付前具备依赖并实际完成两条管线的主要验收矩阵，不能用 skip 充当通过。

本批完成前运行 `npm test`、`npm run lint`、`npm run smoke`，记录通过、失败、跳过数。旧定稿与回归图像变化需解释原因；不自动重录冒烟基准来掩盖偏差。报告中同时列本地验证与 CI 状态，本地通过不替代 CI。
