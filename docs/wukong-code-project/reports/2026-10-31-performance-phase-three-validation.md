## 测量范围与口径

Apple M1 Pro、10 个逻辑 CPU、16 GiB RAM、macOS arm64（Darwin 27.0.0）、Node v25.8.1；引擎使用相同锁定依赖、Chromium/headless shell、ffmpeg/ffprobe 和字体身份，worker 保持引擎默认值。完整环境、工具/输入摘要、准备日志和展开后的命令均保存于原始 JSON；Node 20 的纯文件 I/O 兼容性另以官方 v20.20.2 验证。

共 57 个场景：9 个哈希/状态场景和 48 个真实命令流程场景。每引擎每场景交替执行 5 次无读取探针计时，另做 1 次独立探针，共 **570 次正式计时、114 次探针，零失败、零超时**。所有场景的中位数增量均未超过 `max(100ms, 基线中位数×10%)`。原始结果没有删除异常或挑选有利样本；准备时间单列，不计入制作时间。

例片是《春江》前 6 镜（42.54 秒）和《七十二变》4 镜（14 秒）的独立副本。长片为 107 镜 × 2.05 秒、219.35 秒、512×288、30fps 输入；大音轨组使用同样长片及有效 PCM WAV，约 256 MiB，指定相同播放区间。长片画面刻意简单，不能代表复杂艺术镜头、1080p/4K、网络盘或其他硬件的制作耗时。

“首次/无修改”指制作缓存状态；没有清理操作系统文件缓存。无修改及单镜场景每次恢复相同种子缓存，分别验证零镜/一镜重渲。所有比较都是同命令、同工作量；下表 `render` 指整片 `render --proxy`，不能与逐镜 `preview` 互当提速基线。

主 Node CPU 记录自身及其线程，不含子进程 CPU；RSS 为主 Node 生命周期最大值，不是进程树总峰值。探针记录显式同步 fs API 和已捕获子进程，排除模块加载器、原生库及子进程内部 I/O；子进程耗时可能重叠。逻辑读取字节不是物理磁盘流量，API 计数也不是完整系统调用数。表内为 5 轮中位数，逐轮最小/最大值、CPU、RSS、输出验证和全部计数见 JSON。

## 读取量、附加开销与校验边界

- 大音轨逐镜预览中，目标音轨完整读取由 216 次降至 108 次，57,982,068,000→28,991,034,000 字节，约 54→27 GiB。每次 sourceState 由两遍改为一遍；整个命令仍进行 108 次独立观察。没有跨调用、跨 await 或全局摘要缓存。
- 单次 sourceState 的 8/64/256 MiB 夹具均从 2N 降为 N；单文件摘要仍为 N；交付双遍快照仍为 2N。候选目标文件最大读取请求均不超过 1 MiB。大音轨整片制作的目标音轨完整读取为 10→7 次，其他需要独立读取的检查保持。
- 去重增加元数据检查。256 MiB sourceState 的显式 stat/fstat 为 217→884、目录枚举 3→8。browser 大音轨无修改预览的显式 stat/fstat 合计 38,015→139,975、目录枚举 3,896→4,436。这些数字排除旧 readFileSync 内部调用，不能解释为完整系统调用增量；新增检查的开销已包含在候选计时中。
- 全部 48 个流程场景的完整帧 ffprobe 检查数和 ffmpeg 进程数逐项相同。大音轨首次预览为两边各 62 次完整帧检查；browser 各 215 次 ffmpeg、Remotion 各 431 次。其余逐项计数在 JSON 中。
- 每轮检查重渲镜数、实际帧数/尺寸/帧率、音频流与首末局部预览音频区间。恢复保持只读；交付只写约定的四份报告，缺签批的退出码 2 是预期阻断，不伪造批准或审听。
- 检查后视频再次读内容、fresh 语义、双遍交付扫描、特殊文件/链接拒绝、实现身份以及前两批流程与依赖保护均保留。

这些结果支持本批的有界哈希与单次状态去重；它们不支持减少完整解码检查、删除第二遍交付扫描、跨阶段共享摘要或调整并发。108 次独立状态观察可作为未来研究对象，需要另行约定稳定性与生命周期，未纳入本批。
