# 八道制作流程实施计划

目标：交付唯一新流程、本地用户录音定位和历史项目只读保护。

架构：state 统一管理新流程和历史身份；所有写入口先检查身份，档案使用只读报告。制作仍由现有任务记录恢复，工作台按新步骤审阅；本地语音定位提供可追溯 cue，声轨和镜头消费同一版本。

技术栈：Node.js ESM、JSON Schema、现有本地浏览器工作台、ffmpeg、Chromium/Remotion、本地 whisper.cpp 适配器。

规格：[流程与档案](../specs/2026-11-08-1217-production-flow-design.md)、[本地录音定位](../specs/2026-11-08-1217-local-voice-alignment-design.md)，均按长期授权默认通过。

全局约束（摘自规格）：
- 只维护新的八道流程，旧项目只读留档；不自动迁移、不继承旧签批。
- 不修改发布版本号、安装缓存，不自动发布或推送触发媒体 CI。
- 每批视频生成（含测试和重试）仍单独获得开始授权。
- 首版仅本地处理，不接在线识别，不上传录音、原稿或时间点。
- 不自动删词、截断、变速，不生成 AI 人声或字幕。

## 任务与顺序

1. **流程与档案边界**：修改 `core/state.mjs`、`cli/run.mjs`、`cli/commands/project.mjs`；新增流程单测/CLI 集成测试。先验证空素材目录新建、旧标记留档及旧文件零写入失败，再实现 `flow:6` 和统一八道定义。运行 `node --test tests/unit/production-flow.test.mjs` 及不生成媒体的对应 CLI 测试，确认通过后提交。
2. **工作台与签批**：修改 `core/workbench*.mjs`、`cli/workbench-server.mjs`、`workbench/app.js`、`review.mjs`、`final-delivery.mjs` 和相关 schema。先写档案拒绝写、原上下文查看、8 阶段与 6/7/8 版本绑定失败测试，再实现。运行定向无媒体测试与浏览器验收；新增渲染测试先取得批次授权。
3. **取消旧生产能力**：修改音频、最终导出和剪映入口，移除当前路径中的 TTS/字幕及隐式回退；保留通用历史查看与非字幕共享工具。先写旧命令拒绝、无隐式字幕和缺录音不估算测试，再最小实现并运行定向无视频测试，提交。
4. **本地台词定位**：新增音频定位模块、CLI 入口、记录 schema/报告，修改 soundtrack 的真实录音与混音依赖。先写文本/时间边界、缓存过期、人工补点和本地程序契约失败测试，再实现与验证；真实录音验证单独记录，不能由 mock 代替。
5. **制作指引与文案**：同步导演、film/setup、brief/storyboard 等规范、模板、帮助及生成文档。方案简报、分镜稿与八道文案统一，旧项目仅留档。`npm run lint` 校验文档生成与架构；所需单元和集成回归保留实质行为覆盖。
6. **整链验收与收尾**：审查变更、确定媒体测试批次，展示模型/数量/时长/预计费用/预算并取得授权后运行完整回归和严格剪映集合；真实浏览器核对新片制作与旧档案只读。记录平台、识别精度和专用软件未验事项，提交全部本次改动，更新 #133，检查并处理闲置分支/worktree。未获授权不推送触发新媒体 CI。

当前实施状态与验证结果随提交记录更新；计划不是通过证明。
