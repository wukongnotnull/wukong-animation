# 第二批 A：词级同步与证据标记

Status: Confirmed — 用户于 2026-10-29 明确批准两份 spec

日期：2026-10-29（Asia/Shanghai）

依据：[已批准 PRD](../prd.md) FR-3、[体验报告](../reports/2026-10-29-codex-editing-experience.md)、[issue #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。源码基线：`c787f44`，首批时间轴修复已通过 PR #94 合并。用户已采纳编写第二批 spec，本文件已获实现批准。

## 1. 问题与目标

客户遇到“念到有素材，屏幕文字却延迟出现”。首批修复了视频切点漂移，但正确切点并不能保证镜内词语与旁白同步。

核实的当前行为：

- `audio/char-cues.mjs` 按静音区间分组，再均分每字时长，分组对不上时整句均分；它不是逐字强制对齐。
- `audio/soundtrack.mjs` 在检测到声音区间时把这类点标作“按人声实测”，容易混淆句子/停顿实测与词首实测。
- Browser 提供 cueChars，Remotion 的 WkaShot 只有 cueIn/cueOut；两条管线均支持命名 cue。
- 源码里手写秒数或均分镜长不能在换配音后可靠更新。现有镜头缓存能够提取字面量 cue 依赖，应继续利用。

目标：给明确声明的关键词/列举步骤提供可追踪的词首锚点，准确区分人工标注、外部对齐结果与估算；换录音、换文字后不误用旧锚点。对有效锚点的呈现定位误差不超过一个输出帧。

本批不承诺自动对齐所有人声，也不安装新对齐模型或访问第三方服务。缺少词首证据时明确未验证，保留现有审片节点来听审和修正。

## 2. 架构与组件边界

| 组件 | 职责 |
| --- | --- |
| `core/word-sync.mjs`（新增） | 校验词锚点声明、匹配文本出现位置、处理来源与过期状态、解析运行时 cue、生成报告 |
| `audio/soundtrack.mjs` | 为本次实际人声建立来源记录，准确描述旧逐字点的估算性质 |
| `core/job.mjs`、`core/cues.mjs` | 在运行时注入词 cue，按引用的锚点及其证据参与缓存失效；不回写原 film.cues |
| Browser runtime、Remotion WkaShot | 继续支持 cueIn/cueOut；为新增词 cue 提供按真实输出切点定位的帧入口 |
| director/SHOT.md | 列举、步骤和关键词显现使用词 cue；交付同步证据与抽帧，不把均分写成实测 |

不在此 spec 改字幕断句或视觉遮挡检测，后者见同批独立的字幕预检 spec。

## 3. 接口、数据与行为

### 3.1 声音来源

`wka soundtrack` 完成人声准备后，在 `.cache/voice-sources.json` 原子写入版本为 1 的来源记录，每个 voice cue 包含：实际用于混音的原始人声文件相对路径、文件 SHA-256、完整原文 SHA-256、音频生成请求 SHA-256、在全片的 at 和实测 duration。

生成请求签名覆盖 voice_source、文本、音色、rate、pitch、源录音身份等影响声音的字段，排除 at、配乐和音效。源录音需核对当前文件内容；AI 音频需同时核对生成请求与已生成文件。没有音频或尚未重新生成时，不建立“实测可用”的来源记录。删除人声时清理对应来源。

只改变 at 时，本地词时刻随该句整体平移；改变文字、音色或音频内容时，旧测量失效。

### 3.2 可选词锚点文件

片目录增加可选 `sync-points.json`，不为旧 film.json 增加必填字段。格式如下（哈希字段使用实际 64 位十六进制值）：

```text
{
  version: 1,
  points: [{
    id: "material-available",
    voice: "v26",
    text: "有素材",
    occurrence: 1,
    method: "manual" | "aligned" | "estimated",
    source: { audio_sha256, text_sha256 },
    range: [入点秒数, 出点秒数],
    evidence: "标注说明或本地对齐结果路径"
  }]
}
```

- id 在全片唯一，限定小写英文字母起始的字母、数字及连字符，映射到保留命名空间 `word:<id>`；与已有同名 cue 冲突时报错，不覆盖。
- text 按 Unicode 字符精确匹配人声原文，不忽略大小写或擅自改写。唯一匹配时 occurrence 可省略；重复出现必须给定从 1 开始的 occurrence。找不到词、序号越界、格式错误均报错，不默认取第一个。
- manual/aligned 必须提供音频/原文哈希、range 和 evidence。range 相对该句音频开头，必须有限、入点不小于 0、出点晚于入点且不超出实测音频范围。
- estimated 不接受“实测”标签：按旧逐字估算点提取该次出现对应的区间；没有逐字点时按当前句内文字比例估算。报告明确方法与局限。
- method/evidence 是来源声明，不是声学准确性的自动证明；人工标注需实际听审，aligned 需保留可核对的对齐结果。
- 文件不存在时旧片行为保持；不会扫描全片并替用户虚构关键词或自动认定测量完成。

### 3.3 运行时使用与帧定位

两条管线继续允许 `s.cueIn('word:material-available')` / cueOut 取得局部秒数，并新增 `s.cueFrame('word:material-available')` 取得该管线可直接比较的显现帧号：Browser 与 s.frame 比较，Remotion 与 useCurrentFrame 比较。非 word 名称不接受此新帧接口，原 cue 秒数语义不改变。

词首先映射到实际输出切点下最接近的可呈现帧，再转换为管线的呈现帧坐标。Remotion 小样仍保持原生动画 fps，必须考虑降帧采样，不能简单把全片秒数乘原生 fps。目标帧位置与误差记录在报告中；边界上无法满足一输出帧限值的点标为不可验证，不能静默夹取后算通过。

词 cue 入点相对实际呈现的镜头起点计算；旧 cueIn/cueOut 和 s.start 保持首批既有语义。镜头内只要采用新词 cue，就不能再额外均分镜长或无说明地推迟文字入场；起始动画需把第一可见帧对准锚点，完整淡入完成时刻不冒充起始时刻。

新增帧接口纳入静态 cue 依赖识别。字面量只依赖相关锚点的时间、质量和来源签名；动态引用保守依赖全部 cue。无关词点变化不导致无关镜头失效。

### 3.4 失效、报告与审片

来源缺失或签名不符时，保留用户标注文件但停止使用旧测量时间；报告“未验证/需重新标注”。需要预览时只能明确使用当前输入重新计算的估算点，不把旧测量值当新估算沿用。

点落在引用它的镜头范围外时，标出 voice、word、镜号与全片时刻，不把负数偷偷改成 0。源声明错误是错误；缺少测量、估算和范围问题是未验证项，允许预览和用户审阅，但不能标词级同步通过。

在 render/still/animatic/final 时，按当前画幅与输出 fps 生成 `review/词级同步[-画幅][-proxy].json/.md`：每点列 voice、匹配位置、来源质量、有效性、全片/镜内时间、目标输出帧、引用镜头和问题。单纯加载一个点不能证明镜头实际正确使用它。

对被引用点输出词首前/当/后抽帧及对应人声音频链接，复用现有声轨、小样与改版审阅，不新增签批节点。自动报告区分“来源有效/定位可验证”和“画面响应待人工核对”；所有声明点均无问题也不能自动宣称整片语义同步通过。

## 4. 约束、兼容性与非目标

- 不改写用户字幕、录音、镜长或已签批快照；锚点文件是用户可版本管理的普通文件。
- 旧 char cue 数值保持兼容，只纠正其日志和文档来源表述；不把近似结果升级成词首实测。
- 旧片无词锚点声明时报告“未声明词级检查”，不作已验证承诺。
- 不接入付费服务，不新增配音平台或模型下载；外部对齐结果只导入并核对，不替用户注册服务。
- 不改变首批视频时间轴与缓存保护验收，主副版继续共用声音。任何管线映射变化需重跑首批切点矩阵。

## 5. 错误处理与运维

提供插件内 schema，错误指向声明文件与 point id。缺文件、旧来源和损坏记录不能复用上次通过结论；报告以原子方式写入。静态源码没有足够信息时采用保守依赖，不通过正则猜测复杂 JS 的实际视觉效果。

对未验证项直接交给已有审片流程，并说明需要提供或复核哪些时间点；不反复询问已经确认的配音决定。该检查验证词点的来源及定位，与首批视频帧时间轴检查分别呈现。

## 6. 验收标准与测试

1. “有素材、无素材、纯文字”采用不同实测词首时间，两个管线均按锚点而非镜长三等分显示；用音频脉冲及画面标记验证误差不超过一输出帧。
2. 覆盖主副版、30/15fps、奇数原生 fps 及首批非整数帧切点；实际解码首个可见标记帧，不能仅断言返回数值。
3. 同词多次出现、英文术语、Unicode、缺词、越界 occurrence、音频区间外和镜头范围外均有明确结果。
4. 停顿均分点只能得到 estimated；人工或外部测量缺来源证据不能得到“有效测量”；已有旧点不被错误升级。
5. 换录音、换文字、改音色后旧测量失效；只平移 voice.at 时位置整体平移；无关配乐变化不使词测量失效。
6. 相关词点/质量变化使相关镜头缓存或其验证记录失效；无关词点不重渲不相关镜头；动态引用保守失效。
7. 旧片、旧 cueIn/cueOut、char cue 和定稿保护回归通过；源码声称用了 cue 不代替实际画面抽查。

实施后以失败回归测试先行，增加 word-sync、cue 依赖及真实媒体集成测试；运行 npm test、lint、smoke，并重新验证受影响的首批矩阵。源音频测量误差、人工核对结果与引擎帧定位误差分别记录。
