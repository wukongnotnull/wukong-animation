# 主版保护校验复用（FR-5）

Status: Confirmed；用户在本会话明确回复“确认”，批准本文件。
日期：2026-10-29；基线：main `d370839`。
依据：[已批准 PRD](../prd.md) FR-5、[体验报告](../reports/2026-10-29-codex-editing-experience.md)、[issue #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。

## 1. 问题与目标

已核实 `core/approval.mjs/checkMainUnchanged`：当前哈希只与 `state.approved.main` 比较；代码变化但主版像素不变时，后续每次副版命令都会重复逐帧 PSNR。现有镜头缓存不能替代比对结果缓存。

目标是在当前主版输入、签批基线、实际片段及验证条件完全相同时复用成功结论。任何无法证明相同的情形重新检查或报告未验证。签批快照与原签批哈希保持不变。

## 2. 架构与组件边界

- `approval.mjs` 负责校验键、成功记录、失效和报告；沿用 `shotHashes`、`inspectVideo`、`psnrMin`，不新增一套渲染缓存。
- `job.mjs` 暴露生成校验指纹需要的主版渲染条件；`state.mjs` 记录主版签批身份。FR-6 仅接收阶段状态，不判断主版是否通过。
- 成功记录放 `.cache/main-check.json`，不进 Git；报告仍是各副版的 `review/主版不变报告-<画幅>.md`，增加结构化 JSON。不同副版可复用同一份主版证明，报告画幅各自准确。

## 3. 接口、数据与行为

### 3.1 缓存条件

记录版本 1，包含 `validatorVersion`、`key`、`verifiedAt`、有序镜头集合及逐镜结果。校验键使用完整 SHA-256；Infinity PSNR 序列化为字符串 `inf`，不写 JSON null 冒充测量值。

键必须包含：

1. 当前主版镜头集合与顺序、`shotHashes`、累计帧时间轴、画幅、尺寸、帧率；其现有依赖覆盖共用脚本、使用中的 cue/word cue、字体文件、风格素材、管线与 runtime。不得只用 film.json 的修改时间。
2. 已签批主版哈希及签批身份。新签批产生新的身份，即使镜头哈希相同，也重新建立证明；旧工程无身份时以现有基线和快照内容生成兼容身份，不能伪造历史批准时间。
3. **每一镜**定稿快照的文件内容 SHA-256、实际帧数/帧率/尺寸。源哈希相同也先确认快照完整可读；缺失、损坏不能作为通过记录。
4. 参与 PSNR 的当前片段文件内容 SHA-256、实际帧数/帧率/尺寸，避免缓存文件被替换却沿用旧结论。命中前查文件并校验内容；无需解码所有像素，但仍需探测媒体结构。
5. PSNR 阈值、比较算法版本及代码内容、timing 校验版本、渲染相关源码和锁文件指纹、ffmpeg/ffprobe、实际渲染器/浏览器版本及平台、所用字体状态。不能获得验证条件时不复用，不把 unknown 当稳定环境。

副版画幅不改变主版证明键；主版音轨、字幕不在当前“镜头画面未变”证明范围内，报告明确范围，不宣称成片声音和字幕也相同。

### 3.2 执行

- 主版或尚无主版签批时保持现有返回语义；未签批仍明确“未检查”。
- 先检查已签批/当前镜头集合的并集。增镜、删镜、排序、时间轴或尺寸改变均不能漏过；帧长/帧率变化继续保留原快照，不自动重渲已签批主版。
- 相同来源且快照完整的镜头标 `same`；变更镜头按现有流程渲染并与快照比较。只对需检查的镜头调度，避免新建无关副版素材。
- 完整键命中且上次全量成功时，返回 `reused:true`；不再调度主版渲染或执行 PSNR。报告同时列本次检查时间、原测量时间和复用依据，不把旧测量时间改成当前时间。
- 不命中时执行必要检查；全部 same/pass 才原子写入新成功记录。fail、missing、异常和未结束运行均不能成为成功缓存；当次报告覆盖旧结论。
- 缓存损坏按 miss 处理并说明原因。重新签批后旧缓存失效；不改写 `approved.main` 来制造命中。

## 4. 约束、兼容性与非目标

- 保持 PSNR 每帧严格大于 50 dB 的现有标准，不放宽阈值换速度。
- 不自动重新签批，不覆盖定稿快照，不删除客户视频；清缓存只是失去复用能力。
- 不引入跨工程缓存、远程存储、常驻守护进程或通用依赖分析器。
- 不扩大为最终音视频等价证明；FR-1～FR-4 已建立的时间轴/字幕检查继续独立执行。

## 5. 错误处理与运维

日志区分“主版验证命中”“主版重新比对”“快照缺失/条件不可核验”。报告失败必须显示受影响镜号与原因；不能沿用上次成功文案。写入使用同目录临时文件后 rename；临时文件不算有效记录。并发命令不能把不同键的半成品合为成功记录。

## 6. 验收标准与测试

- 实际 Browser 和 Remotion 各有一个共用脚本仅影响副版的工程：第一次主版 PSNR 通过，第二次另一副版命令不调用主版 render/PSNR；结果和原测量时间可追踪。
- 改镜头、共用脚本、使用的 cue/word cue、字体、帧率、尺寸、快照内容、签批身份或验证器条件逐项失效。未使用 cue 的变化遵守已有依赖范围，不要求无关重渲。
- 快照/当前片段缺失、损坏、同路径字节被换、上次失败、记录半写、记录版本过旧均不能通过复用。
- 删除/增加镜头及改变顺序不能报告主版不变；旧定稿帧长变化时不改原快照与主版缓存。
- 真实编码 PSNR 用例证明像素变化失败；命中路径以调用计数证明跳过昂贵操作，不能只比较报告字符串。
