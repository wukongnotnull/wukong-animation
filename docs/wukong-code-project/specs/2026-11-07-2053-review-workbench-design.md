## 问题与目标

提供随插件分发的本地网页工作台。沿用 15 工序、12 审片节点，覆盖文档、图像、声音、视频、字幕、报告、主副版及专用软件交付物。界面负责只读预览、定位批注、逐项检查和阶段签批；制作与返修由对话发起。

## 架构与组件边界

- `core/workbench-catalog.mjs`：现有文件、制作清单和用户登记的交付物映射；按内容种类和声明来源计算依赖，不执行影片代码。
- `core/workbench.mjs`：项目内交付物版本、批注、检查和审阅记录；文件快照与版本绑定；调用注入的既有签批处理器，复用生产锁。
- `cli/workbench-server.mjs`：只监听本机的 HTTP 服务、项目枚举、媒体分段读取、带会话凭据的审阅操作及明确点击后的文件定位。
- `cli/commands/workbench.mjs`：启动、登记、快照、待办查询；签批调用现有 reviewCommands 处理器，不复制字幕/时间轴/终交检查逻辑。
- `workbench/`：无新增前端依赖的静态 HTML/CSS/JS。深色五区布局，普通浏览器可用，不依赖 Codex 专属界面。
- CLI 制作命令在已接入工作台的项目中保留修改前/后的交付版本；文档等由 Agent 写入的交付物通过明确的 capture 命令登记，导演规则要求覆盖前先保存，交审前再登记。

## 接口、数据与行为

### 入口与项目

`wka workbench <项目或片目录> [--port N] [--open]` 启动本地服务，打印真实地址；默认随机可用端口。项目入口只枚举自身 `films/` 的直接子目录，单片入口只允许访问该片。可从仅有 brief.md 的早期项目开始，不要求先生成 film.json。

`wka workbench <片目录> --capture` 保存当前交付物；`--register <文件或目录> --step N [--label 名称] [--depends 路径列表]` 明确登记非标准命名交付物及来源；外部路径只能由此 CLI 的明确登记或已存在的正式导出记录引入。`--pending` 输出仍待处理的意见，保留版本和定位，不触发执行。

### 交付物及历史

账本位于 `.wka/workbench.json`，包含登记项、不可变版本、批注、逐项检查、阶段结论。快照位于 `.wka/workbench/objects/`，以内容摘要去重；目录中放置忽略规则，媒体不进入 Git。快照非可再生渲染缓存，不由 clean 命令删除。损坏或较新账本明确拒绝，不覆盖为新账本。

标准映射包含 brief/story/storyboard、`visual-direction.md`、`review/人声来源.md`、已知 review/stills 文件、局部预览、字幕及正式终交清单。尚无统一记录的美术和声音选择由导演形成文件，旧项目缺失时提示补登记，不能虚构历史。登记项允许声明更准确的来源文件；媒体默认依赖实际镜头/公共脚本、声音输入、相关字幕与画幅配置，文字阶段按简报/剧本/分镜之间的关系绑定。没有影响声音的字幕修改不得使声轨作废。

同一路径内容被替换时保留旧字节；同内容不重复存储。上游变化但当前文件未变时保留该版本原来源并提示需要复核；成功重新制作或用户显式复核后记录新的来源上下文。首次接入只证明当前磁盘内容，不把旧签批冒充当前版本批准。

### 批注与阶段签批

批注目标是交付物 ID + 版本 ID，支持总体、文字偏移与原文、图片归一化坐标、时间点/区间；坐标和时间验证范围，文本定位必须匹配快照。意见有未解决/已解决状态以及是否阻塞，刷新后持久保留。

逐项检查与正式阶段结论分开。所有必需项存在、当前版本完成检查、当前版本无未解决阻塞，才允许提交阶段通过。每次操作携带页面观察到的版本/阶段摘要；文件或依赖变化时拒绝陈旧提交。查看、播放、默认值均不是通过。旧版意见及结论可查，不转移到新版。

通过调用既有 signoff 处理器；13/14/15 节点同时绑定现有 final-delivery 的 review revision，并保留其技术校验。草稿外部打开证据由用户明确选择提供，不能由定位按钮伪造。签批失败时不展示已通过；Git 未确认时明确提示已记录批准但存档待核实。需要修改只保存结论和待办，不推进流程。

### 网页与文件服务

顶部影片选择及进度；左侧阶段与文件；中央媒体/阅读器；右侧版本、检查信息、意见和审阅操作；音视频底部镜头定位与时间区间控件。文字用安全的文本节点展示，支持选段，不执行交付物 HTML/脚本。图片可点击定位，媒体使用浏览器原生播放与服务端 Range 支持。专用目录展示快照组成、明确的检查状态和定位当前原文件的按钮。

仅绑定 `127.0.0.1`，每次启动随机会话凭据，不写入工程。API 要求凭据，写入要求同源 JSON；校验 Host/Origin，媒体只按登记 ID 和版本解析，路径与符号链接不能逃出授权根。预览存储不能跟随 `.wka` 等可写目录的外部符号链接。正文有大小限制；不会提供 shell、任意路径浏览或生成接口。

## 约束、兼容性与非目标

- 不修改版本号，不同步 Projects，不自动发布或改写已安装插件缓存。
- 不剪辑、不直接编辑文字、不云协作、不上传媒体、不实现专用软件工程编辑器。
- 批注及需要修改不触发制作；每批视频生成必须另获明确授权。
- 不执行影片脚本来预览，不迁移旧 state；兼容检查在任何工作台写入前完成。
- 保留旧 CLI 行为；新增命令和 help 行扩展兼容测试，不改原 22 个命令保护策略。
- 快照增长不自动删除；空间不足和读写错误明确失败，不假报版本已保留。

## 错误处理与运维

服务停止时页面保留当前上下文并提示重启；文件缺失、账本损坏、依赖变化、锁被占用及专用软件不可用均显示具体原因。媒体预览失败提供定位入口，不能算作播放成功。重复 capture 幂等；审阅写入使用现有工程锁和原子账本保存，服务器同时处理多个页面时不覆盖彼此意见。

## 验收与测试

逐条覆盖 PRD 的 12 项验收。自动化重点：全阶段枚举、旧文件与缺失状态、不可变历史、分组依赖失效、文字/图片/时间定位验证、陈旧签批拒绝、阻塞项、现有 signoff 集成与失败、回对话待办、只读旧流程、媒体 Range、凭据/来源/路径/符号链接边界、干净副本启动。真实浏览器验证文档阅读、图像定位、音视频播放/时间定位、版本切换、批注持久化和阶段签批。

运行 `node --test tests/unit/workbench.test.mjs tests/integration/workbench.test.mjs`、完整 `npm test`、`npm run lint` 及既有 smoke；不为测试调用收费视频生成。记录实际通过数、浏览器观察和未验证平台，验证后提交改动并检查分支/worktree。
