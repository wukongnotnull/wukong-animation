# 用户自带口播稿作为写剧本的素材 · 设计

关联 issue：#87（来自 #45「口播稿审稿」一项）

## 1. 问题与目标

- director 第 4 道默认剧本由导演从零写，没有说用户已经带着一份口播稿来时怎么办。keynote 这类口播信息片，用户常常先有稿子。
- 源 skill wk-motion-graphics 有一套审稿做法（找"念得出来、画不出来"的句子，只提建议、不代笔），keynote 迁移时还没带过来。
- 目标：口播稿作为第 4 道写剧本的素材，原句进 `story.md` 的「人声文案」，其余各部分围绕它写；画不出来的句子随剧本提改稿建议，用户同意才改。

## 2. 不做的

- 不新增工序、不新增审片节点：工序编号写死在引擎 `PRODUCTION_STEPS` / `REVIEW_GATES`（`engine/core/state.mjs`），插一道要整体后移并迁移在制片子。仍在审片节点③签批（`--step 4`）。
- 不改模板结构（`engine/templates/brief.md`、`film/story.md`），示范片不动。
- keynote 的审稿范例、重绘界面细则、分镜范例、踩坑条目以后再迁。

## 3. 行为

| 工序 | 有口播稿时 |
| --- | --- |
| 第 2 道 简报 | 用户给的口播稿原文存为片目录 `口播稿.md`（`wka brief` 建目录之后），以后不改它；故事 / 主题写"见 `口播稿.md`"加一句概括；片长按稿子字数估（每秒约 3.6 字）；人声推荐旁白 |
| 第 4 道 剧本 | 人声文案原句照搬、按段落加 `[段落]`；段落按稿子里的观点切分，时长按字数估；梗概、Logline 从稿子提炼；屏幕文字写口播没说出口的那层，不复述 |
| 第 4 道 提交 | 另交改稿建议表 `review/改稿建议.md`：原句 / 问题 / 建议改法 / 改后画面；用户同意的条目才改进剧本 |

## 4. 改动文件

- `plugin/skills/director/specs/BRIEF.md`：通用规则加口播稿一条；故事 / 主题、片长、人声三项的说明补有口播稿时的写法。
- `plugin/skills/director/specs/STORY.md`：输入加 `口播稿.md`；新增「三、有口播稿时」（各部分怎么用稿子、画不出来的常见情况与改法、改稿建议表格式）；自查清单加两条。
- `plugin/skills/director/SKILL.md`：第 2 道补口播稿的处理；第 4 道补素材来源和提交改稿建议表。

## 5. 验证

- `npm run lint`、`npm test` 通过（`templates-structure.test.mjs` 核对规范说明表与模板逐项对应）。
- `wka brief` 后在片目录放 `口播稿.md`，`wka init` 能正常补齐工程、不删这个文件。
