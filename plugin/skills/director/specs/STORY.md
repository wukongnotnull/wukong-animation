# 剧本填写规范（story.md）

> 剧本是一支片的文字底稿，写给人看，不含代码。说明讲什么、为什么值得看、如何推进、最终留下什么。剧情与意象片以故事正文为主体，口播讲解片以完整人声稿为主体；同一模板按作品特点调整详略，供录音与分镜承接。

- **工序**：第 3 道 · 审片节点 ② 剧本
- **模板**：`engine/templates/film/story.md`，第 2 道 `wka init` 建工程时带出空白稿 `films/<片名>/story.md`
- **输入**：签批过的 `brief.md`（核心信息、受众、基调、目标片长、画幅、有无人声、有无配乐）；选定风格的 `STYLE.md`；用户带来的文字素材按素材导入流程保存在 `资料/`，例如 `资料/素材稿.md` 或 `资料/口播稿.md`（处理范围见「五、输入素材与改稿权限」）
- **流程**：怎么提交、征询哪几点见 `../SKILL.md` 第 3 道

## 一、文档职责

正文负责交代内容与表达目标，段落表负责检查推进和节奏，人声文案是完整台词的唯一清单。剧情与意象片充分展开正文；口播讲解片把正文缩成段落摘要与表达目标，完整讲解只写在人声文案。混合型按段落需要处理，不强制整片选一种。不要在正文、段落表与人声文案中重复粘贴整段内容。

| 容易混淆的 | 区别 |
|---|---|
| 分镜稿 `storyboard.md` | 剧本按**段落**写，分镜稿按**镜头**写。正文可以写具体发生的事、可见的对象和变化；画面怎么拍、景别、运镜、转场、声音铺排、屏幕文字的出现形式都留给分镜稿 |
| 镜头代码 `shots/sNN.js`、片内公共脚本 `shots/common.js` | 画面的代码，第 6 道写 |
| 配乐脚本 `audio/build.mjs` | 合成音乐的代码，第 6 道写 |

模板只保留填写骨架与自检问题；以下类型提示和示例用于辅助写作，不整段复制进交审稿，也不要求逐项作答。

## 二、逐部分写法

| 部分 | 写什么 | 写到什么程度 |
|---|---|---|
| 基本信息 | 标题写片名；表里写目标片长、画幅、风格 id | 沿用已签批的简报，目标片长不是录音实长；需要改变已批信息时列入待确认事项 |
| 写作依据与约束 | 链接方案简报与实际来源，注明素材性质和允许的处理范围 | 素材合集、待修改口播稿、已确认定稿分别处理，见第五节；没有外部素材时注明依据简报创作。有特殊朗读排版或字数要求时才增加“口播约定”，没有则不留空字段 |
| 一句话核心表达 | 一句话说清主要人物与变化、要解释的问题，或要成立的观点 | 让读者能复述这支片的核心；不写“展现了”“体现了”这类空话，不机械限制字数 |
| 创作意图与基调 | 目标受众、预期感受或收获、情绪基调 | 从已批简报提炼简短摘要，不重新征询已确定的需求；基调用 2–3 个具体的词，不违背 `STYLE.md` |
| 故事正文 | 按 `P01 段落名` 等三级标题分段，交代内容与表达目标 | 剧情与意象片连贯展开；口播讲解片只保留段落摘要和表达目标；混合型按段调整。必要时在段落后补充“表达依据与保留要点”，不逐镜描述 |
| 段落结构 | 每段一行，写编号、预计时间、推进作用、情绪变化 | 与正文段落顺序一致；作用说明这一段如何推动故事或理解，不复述正文；估时规则见第四节 |
| 人声文案 | 可直接录音的完整原文，每条以 `[P01]` 等段落编号开头，再写说话人和原文 | 旁白写“旁白”，对白写角色名；多角色逐条区分，必要时注明对白、OS 来源或同期原声。标记不读入录音；无人声写“无”；录音前按第六节检查 |
| 屏幕文字 | 画面上要出现的字：片名、题诗、落款、要点、片尾标识等 | 默认只写原文与所在段落，引用注明出处；跨段使用时列全编号。必要时增加“用途与约束”列，见第七节。没有写“无”；不写出现形式。**不包含字幕**：不把人声原文逐句搬进表中，不制作字幕 |
| 自检与待确认 | 回答模板中的五项自检，并集中列出未解决的问题 | 无需数字评分，未满足项不勾选；不适用项注明原因，如“无人声”。问题写清影响和需要确认的决定，没有待确认事项时写“无”。自检不代替用户签批 |

## 三、正文与类型提示

所有类型都要说清核心表达、观众为何关心、内容如何推进以及结尾留下什么。按作品特点展开正文或人声稿，再检查是否缺少支撑；不把这些问题变成额外的必填表单。口播片的正文摘要应说明实际内容与表达目标，例如“解释全站共用主色变量如何让多个页面保持一致”，不能只写“讲解功能”。

| 类型 | 写作提示 | 推进示例 |
|---|---|---|
| 剧情故事 | 主体想要什么，遇到什么阻碍，做了什么选择，选择带来什么变化？ | 想渡河 → 尝试失败 → 改变办法 → 渡河后的发现；起承转合可作参考，不要求四段 |
| 科普讲解 | 观众最初困惑什么，通过哪些现象、例子或解释逐步理解，最后能解释什么？ | 为什么影子会变长 → 比较光照角度 → 用关系解释现象 → 回答最初问题 |
| 观点表达 | 主张是什么，论据如何支撑，哪里需要回应疑问或限定适用范围，观众最后得到什么判断？ | 提出主张 → 给出案例和依据 → 说明边界 → 回到结论；不捏造案例、数据或引用 |
| 意象表达 | 意象如何展开、形成联系和情绪变化，结尾如何回应开头？ | 晨雾中的树 → 光线显出枝叶 → 风过后的静止；不强加人物冲突 |

“情绪变化”既可以是人物或观众的情绪，也可以是理解状态，如“疑惑 → 明白”。确实保持同一基调时写“保持平静”，不为填表制造转折。

### 表达依据与保留要点（按需）

涉及关键论据、具体演示或容易误解的含义时，在对应正文段落之后补一句“表达依据与保留要点：……”。说明观众应理解什么、哪个来源或素材支撑它、哪些含义不能改变；其他段落不保留空字段，也不要求每句话配一张图。

- **事实与证据**：数字、引用和效果结论注明来源；会变化的数据注明核对日期，未核实的列入待确认。前后对比应对应同一对象，不能借另一产品的成果暗示本产品效果。
- **真实与示意**：真实截图、实测结果和用于解释的重绘、演示数据明确区分。示意材料可以讲清原理，不能充作实际测试或使用经历的证据；可能被误认时，在屏幕文字中列出“示意”等标识。
- **必须保留的含义**：例如“首页按钮蓝色、价格页按钮紫色，用于说明样式不一致”，后续强调色不能掩盖这个区别。数量、顺序和对象关系同样按语义保留。

这里约定内容，不写构图、景别、运镜、转场或出现时长。把“只改一处主色，多个页面随之变化”作为表达目标，具体如何展示由分镜决定。

## 四、段落编号与预计时间

### 段落对应

- 初稿按阅读顺序使用 `P01`、`P02`……，段落名描述本段内容，段落数量按需要增减，不预设四段。
- 正文标题写 `### P01 段落名`；段落表、人声文案、屏幕文字和分镜稿都引用同一编号。编号仅供文档对应，不是镜号或录音 cue。
- 调整顺序或改段落名时保留编号；新增段落使用未占用编号，删除、拆分或合并时同步检查所有引用，不能留下悬空引用。表格顺序跟随正文，编号不必重新连续排列。
- 无人声或无屏幕文字时，相应部分写“无”并删除占位条目；不把未提供录音误写成无人声。
- 人声只在实际出声的段落列条目，无需每段都有台词。单人旁白也标明“旁白”；角色类型不清时补充“对白（角色）”“OS（来源）”或“同期（来源）”，便于分镜沿用。

人声格式示例（按影片需要选用，不是默认台词）：

```text
1. [P01] 旁白：雨停后，河水仍在上涨。
2. [P02] 小舟（对白）：我们再找一条路。
3. [P02] 阿禾（对白）：先去上游看看。
```

### 估时与实长

- 基本信息保留简报的**目标片长**；段落表填写**预计时间**，例如 `0–6s`、`6–14s`。预计区间首尾相接、不重叠，其总长是本稿的预计总长，不冒充实测结果。
- 检查预计总长是否符合简报中的目标或允许范围；不符时列入待确认事项，说明差额及原因，不擅自修改目标片长或删稿凑数。
- 注明估时依据；有用户实际语速样本时优先参考样本，无样本时中文每秒约 3.6 字仅作粗估，还需考虑停顿、语气和无台词段落。它用于发现可能超时的问题，不是字数上限；语速与停顿应贴合内容及所选风格。
- 第 4 道以完整录音实长核对，测量值与句段定位保存在人声阶段记录中。剧本的预计时间不改称实长；需要回溯时引用对应记录，历史估时明确标注为历史，不与当前安排混用。录音与稿件冲突时由用户选择重录或修改剧本并重新确认，不自动改稿；超过已批片长限制由用户决定。
- 第 5 道有人声时按已批准的完整录音和句段定位规划镜头，不为匹配预计时间裁切或变速录音；无人声时沿用已确认的剧本节奏。分镜保留段落编号，解释预计节奏与实际安排之间的差异。

## 五、输入素材与改稿权限

通过 `wka materials` 导入后，以素材清单登记的实际路径为准，例如 `资料/素材稿.md`、`资料/口播稿.md`；来源文件独立保留，不因改编而覆盖。不要仅凭文件名判断是否定稿：从用户已有要求判断素材性质与授权，并写进“写作依据与约束”；只有无法判断且会影响处理方式时才询问。

| 素材性质 | 处理方式 | 需要另行确认的边界 |
|---|---|---|
| 素材合集 | 在已授权范围内提炼、重组和口语化，保留事实依据；图片、清单、参考句不等于必须逐句录制的台词 | 新增事实、改变观点或改动用户锁定内容时，先提出建议并确认 |
| 待修改口播稿 | 按用户已明确的修改要求调整，保留要求保留的原句和口吻 | 超出修改范围的内容先确认，不把“改顺一点”扩大为改变结论 |
| 已确认定稿 | **原句照搬**，只添加段落编号和说话人等非台词标记 | 未获授权的改动先列为建议，确认后才写入人声文案；朗读检查不能自动解锁定稿 |

同一来源中可以同时有可改编素材和锁定原句，注明各自适用范围。已明确授权的处理直接执行，不逐句重复审批；已有要求发生冲突或素材性质不明时，保留原内容并把决定列入待确认。没有外部素材时，注明按已批简报创作，不虚构来源。

口播讲解片按以下方式承接素材：

| 部分 | 怎么承接素材 |
|---|---|
| 人声文案 | 按上述权限整理成完整可录音稿；用 `[P01]` 等编号关联段落，标明说话人；保留用户锁定的原句 |
| 故事正文、段落结构 | 正文只保留段落摘要与表达目标，不再写一份完整讲解；段落表只写推进作用、预计时间及情绪变化。估时超出已批目标时列入待确认，不自动改规格 |
| 一句话核心表达、创作意图与基调 | 从素材和已批简报提炼，保留事实与观点依据；两者不一致时列明差异并请用户决定 |
| 屏幕文字 | 标题提炼结论，要点给出有素材支持的补充信息，步骤保留准确标签；不逐句照抄口播，不凭空补充事实，信息取舍见第七节 |

**改稿建议**：无法说清一句话的具体含义或缺少支撑素材时，先核对处理权限；已授权的顺句、重组直接实施，需要另行决定的内容再列为建议。建议只涉及人声和内容推进，不写景别、运镜和声音安排。常见的几类：

| 问题 | 表现 | 改法 |
|---|---|---|
| 抽象形容 | 「强大」「丝滑」「直击痛点」 | 换成一个看得见的结果：「改了哪几行，一眼看到红绿」 |
| 一句多点 | 一句里讲了三个功能 | 拆成三句；必要时拆段，或改成步骤 |
| 否定句 | 「你肯定没有」「不用再……」 | 给出可以理解的正面事例；原句是否可改按已记录的处理范围判断 |
| 数字无参照 | 「快了 30%」「节省很多」 | 补充有来源的前后对比；无依据时标为待确认 |
| 指代不清 | 「这个」「那边」「它」 | 第一次出现说全名：「Git 图谱面板」 |
| 看不见的动作 | 「我试了很多方法」 | 换成具体发生的事，或有助理解的比喻 |
| 缺素材 | 提到别人的界面、网页、数据 | 句子保留，列出需要的截图、录屏或来源；拿不到时提出改写建议 |
| 句子太长 | 一句 30 字以上一口气说完 | 建议在意思停顿处断句，方便录音 |
| 顺序跳跃 | 讲完 B 又回到 A | 按事件、解释或论证的推进关系提出重排建议 |

连接句（「这只是开胃菜」）、开场和片尾只有一句大字的段落都是允许的，不要求句句有独立画面。

需要用户决定的建议写进片目录的 `review/改稿建议.md`，随剧本一起提交；没有此类建议时不创建空文件：

```text
| # | 原句 | 问题 | 建议改法 | 改后这段讲什么 |
|---|---|---|---|---|
| 1 | 「它的功能特别强大」 | 抽象形容，没有可讲的对象 | 「它能把 20 个分支的合并关系画成一张图」 | 20 个分支的合并关系被画成一张图 |
```

示例中的数量须有素材支持，不能直接当作影片事实。表后按需附缺少的素材及用途、对预计时长的影响，在剧本「待确认事项」链接该建议文件。表中需另行确认的改动获同意后才写入人声文案；已经授权的改编无需再逐句审批，用户锁定的句子继续保留。

## 六、朗读检查与口播约定

有人声时，在录音前检查完整台词；无人声时此项注明“不适用：无人声”。检查不代表用户已录音或已确认人声。

- **念得顺**：按实际说话方式通读，找出绕口、缺主语或宾语、连续堆叠概念的句子。停顿应落在意思完整处；断行不能让人误解句子关系。
- **听得懂**：按只听一遍的标准检查“它”“这个”等指代，否定、转折与因果是否成立。特别检查“所以”“不过”“不是……而是……”是否真能连接前后内容，避免依靠标点或屏幕补足必要含义。
- **承诺兑现**：开头及时说明为什么值得继续看，后文回答开头的问题或兑现承诺。按作品类型决定节奏，不把固定“前三秒”或必须使用夸张钩子当作通用要求。
- **按权限修订**：朗读发现的问题依第五节处理；已确认定稿或锁定原句只提建议，不能借朗读检查自动改写。

只有用户有特殊要求时，才在“写作依据与约束”增加“口播约定”，记录标点、换行、停顿和字数口径。比如“一行一口气，空行表示较长停顿，900–1000 个汉字”是某支影片的约定，不是默认格式；字数限制不代替实际录音测时。没有特殊要求时使用自然、清晰的标点和段落，不留空约定项。

## 七、屏幕文字的信息分工

默认保持“文字／所在段落”两列；存在必须传递的信息或准确性约束时，才增加“用途与约束”列。未涉及特殊约束的行写“—”，不要求所有影片都增加第三列。

- **用途**：明确是必须读到的核心信息、补充信息还是辅助标识。不能为了缩短口播，把理解结论所必需的信息全部移到一闪而过的屏幕文字中。
- **保留范围**：完整名称、命令、数值和引用是否必须原样保留；允许简称时直接写出已确认的简称。允许断行不等于允许删字，实际换行、字号、位置和停留时间由分镜安排。
- **信息负担**：检查观众是否要同时听一组数字、读另一组数字，或一边听解释一边读长命令。根据重要程度调整口播与文字的分工，必要时删减辅助信息或在分镜中错开呈现，不能靠缩小字号塞入全部内容。
- **示意标识**：需要标明“示意”等字样时，作为明确的屏幕文字条目关联段落，不只写在幕后备注里。

可选扩展示例（只演示填写方法）：

```text
| 文字 | 所在段落 | 用途与约束 |
|---|---|---|
| web-design-guidelines | P01 | 工具名称；保留完整拼写，可断行，不自行简称 |
| 操作示意 | P02 | 区分示意与真实操作结果；必须可读 |
```
