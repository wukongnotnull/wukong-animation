# 工作台审阅流程完善

Status: Confirmed
Spec approval: 用户长期授权默认通过；PRD FR-27～FR-34 于 2026-11-08 明确获批。
Issue: https://github.com/wukongnotnull/wukong-animation/issues/127

## 问题与目标

在既有本地工作台上完成准确的版本审阅、结构化阅读、待审导航、隔离草稿和用户返修复验。保留现有界面风格、制作管线和正式 signoff。范围来自已批准 PRD，不重新设计插件或增加制作能力。

## 架构与组件边界

- `core/workbench.mjs`：版本上下文、复核有效性、批注返修及用户处置。账本保留版本 1 并兼容缺少新增字段的旧记录；新字段不改写旧快照。
- `core/workbench-catalog.mjs`：正式/参考分类，已知制作成果及明确登记项保持正式，其他扫描文件作为参考。
- `core/workbench-ui.mjs`：独立本机草稿/位置/布局存储及轻量文件变更指纹；不写正式意见、签批或制作状态。
- `cli/workbench-server.mjs`：新增受原鉴权及同源保护的 UI 状态、变更状态、返修结果接口，原媒体 Range 与路径边界保留。
- `workbench/model.mjs`、`document.mjs`：纯状态选择、筛选、版本上下文和带原文偏移的只读文档分块；供真实前端与单元测试使用。
- `workbench/app.js`、HTML/CSS：总览、版本一致的预览、草稿保存、返修处置、响应式面板；复用既有深色布局。

## 接口、数据与行为

### 版本、分类与通过

新版本保存当时的镜头 ID、起点、时长、总时长及交付类别。旧版本若没有镜头上下文，隐藏镜头跳转并说明未知，仍可按媒体自身时间播放；不补造历史。局部视频只展示该镜的局部时间。

检查记录绑定当前交付 revision（含内容、依赖和可用性）。用户显式复核后的相同 revision 显示有效，历史版本的原始依赖摘要不被覆盖；再次改变来源会再次失效。历史预览只展示所选版本的检查依据，当前阶段签批信息另行标识。

标准文档、已知 review/stills 产物、生产 operations 输出、终交合同和明确登记的正式文件参与必检；未知扫描文件列为参考。历史已移除项保留在原阶段的历史分组中。参考项不阻塞正式阶段；正式项关联的未关闭阻塞意见跨版本保留，不能靠生成新版或移除文件绕过。

已在专用软件打开的勾选仅在当前影片、当前阶段 revision、当前交付版本选择中有效，任一上下文变化清空；服务端继续校验完整阶段 revision。播放器新实例同步实际倍速，不保留错误显示。

### 返修闭环

新意见 `status=pending`；兼容旧 `resolved`。`recordWorkbenchRepair` / `POST /api/repair` / `wka workbench <film> --repair <id> --artifact <id> --version <id> --summary <text> --verification <text>` 只登记已有版本的结果，不生成。结果记录唯一 ID、目标交付版本及 revision、修改说明、实际验证说明和时间，状态为 `awaiting-review`，仍阻塞。

用户 `POST /api/resolve` 选择确认解决、退回待处理或无需修改关闭。确认解决必须携带当前看到的返修结果 ID；目标版本/依据已变化时拒绝，要求重新复验。无需修改必须有理由；所有转换追加历史，保留原意见/定位。旧接口 `resolved=true` 不再允许无理由关闭未返修意见。阶段级需要修改可登记返修结果，最后仍由已有阶段通过动作确认，不能用单条意见解决代替阶段签批。

### 草稿与位置

草稿以影片 ID + 交付 ID + 版本 ID 分组，阶段结论以影片 ID + 阶段 + revision 分组。正文、定位和阻塞选择一并保存；切换先保留当前组，再恢复目标组。检查打开勾选不作为可恢复草稿。

`GET/POST /api/ui` 使用授权工作区内 `.wka/workbench-local/state.json`（自行忽略 Git）保存草稿、上次影片/选择、布局，逐键乐观版本检查和独立短写锁避免页面互相覆盖；该存储不占用制作锁或改变正式审阅。输入同时保留浏览器本地后备，连接失败时明确区分仅浏览器保留与已同步到本机工程。失败草稿不删除，不自动重发正式提交；恢复连接后可同步草稿，正式意见仍由用户点击提交。不同启动端口优先恢复工程已保存状态，未同步的浏览器草稿留在其原地址并提供明确提示。

保存正式意见使用请求 ID 去重，避免响应丢失后的重复提交；成功只清除对应版本、对应内容的草稿。返回旧位置失败时提示并转到可用总览，不把失效位置当正确恢复。

### 阅读、总览与布局

只读 Markdown 支持标题、段落、列表、代码块及表格，HTML 以文字显示；每个文本片段保留原文 UTF-16 起点。选择与跳转始终转换到原文偏移及原句；跨块选择可保留中间原文，不以显示排版拼出假原文。分镜表提供镜号入口；窄窗口将行显示为字段卡片。原文/排版切换保留选段；非 Markdown 文本默认原文。

首次进入总览；之后恢复最后影片/阶段/交付/版本。搜索覆盖名称、阶段和意见；可筛选阻塞、待复验、需复核、未检查及分类。待办跳到原批注或返修目标版本，历史项目也可达；“下一项”按当前待审队列定位。

宽窗三栏可收起及调宽；窄窗（断点在实现中统一定义）用文件/预览/意见/检查切换面板，保留 DOM 内容、播放器位置、选段和输入。主操作键盘可达，状态有文字。图片定位补充键盘十字定位入口。

### 更新与断线

`GET /api/status` 返回素材及来源文件的元数据指纹、制作占用和服务时间，不捕获媒体快照、不执行制作脚本。前台定期检查，后台页面降低频率；检测变化后取新报告作为待应用更新，提示用户主动查看，不能替换正在审阅的内容或草稿。最后同步时间仅在成功读取时更新。401 显示重新打开最新启动链接；占用和断线显示各自说明，保留已加载预览。

## 约束、兼容性与非目标

- 不修改项目版本号，不发布、不改安装缓存、不同步 GitHub Projects。
- 不提供剪辑或文档编辑，不上传媒体，不自动提交正式意见、签批或生成。
- 不增加完整版本对比、制作时并行正式审阅写入、容量/备份管理或完整手机版。
- 不删除旧快照、意见或签批；旧账本、新版本账本及路径/符号链接保护保持有效。
- 每批媒体生成与重试单独获得明确授权；开发优先纯文字夹具和已有媒体。

## 错误处理与运维

草稿写入冲突明确报错并保留本页内容；拒绝无效来源/版本、空返修说明、无理由关闭和陈旧复验。未知历史时间轴只降级镜头导航。保留原 CLI 与正式审阅失败语义；不以错误状态生成成功提示。
