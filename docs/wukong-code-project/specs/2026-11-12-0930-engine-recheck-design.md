# 引擎变动后的复核接受（wka recheck）

## 问题

插件升级后，`implementation` 与交付依赖里的引擎文件摘要全部变化，已生成的最终交付产物被判为 `changed`，哪怕本片画面与声音完全没受影响。此前只能整片重新生成。

## 行为

- `wka recheck <片目录>`：只读。对每个交付槽位的最新产物，列出变动的引擎文件，并判断是否可接受。
- 可接受须同时满足：变动的依赖组去掉引擎文件后与生成时完全一致；产物文件仍与账本快照一致；无确定技术错误；交付要求未变；不是外部修改产物。
- `wka recheck <片目录> --accept --note "<复核说明>"`：对可接受的槽位向 `.wka/final-delivery.json` 追加一条新产物记录。`provenance` 为 `engine-recheck`，带 `recheck.of`（旧记录 id）、变动文件列表、说明和时间；依赖与工具身份按当前引擎重新采集；旧记录一字不改。
- 说明缺失时 `--accept` 报错。不可接受的槽位给出原因，不写账本。
- 旧批准绑定旧记录 id，复核后不沿用，须重新签批。
- 退出码：全部可接受（或无需复核）为 0；存在不可接受项或 `--accept` 没有写入任何记录为 2。

## 不做

- 不改阶段缓存（`stale` 阶段重跑时仍会复用镜头缓存）。
- 不处理影片输入、设置、交付要求变化，也不处理工具（ffmpeg、pyJianYingDraft）身份变化引起的 `unknown`。

## 验证

`tests/unit/final-delivery.test.mjs` 的 B1、B2：只读不写账本；接受后旧记录原样保留、新记录可追溯、新鲜度恢复为 `current` 且验收仍待定；影片输入变化或产物被改时拒绝。
