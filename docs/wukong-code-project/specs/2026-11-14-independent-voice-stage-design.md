# 独立制作人声工序

状态：用户经 grilling 逐项确认，并于 2026-11-14 明确「确认并实施」。

## 产品需求

流程变为九道：制作准备、确定方案、编写剧本、制作人声、规划镜头、制作小样、制作成片、调整画幅、导出剪映草稿。第4道独立试听签批，后续顺延，最多八个审片节点。

人声工序负责用户录音接入检查、原稿核对、句段定位、默认逐词表和试听。完整录音可用、稿件核对通过、句段已确认应用才可通过。逐词表未全部确认不阻塞签批，但未确认词不得用于制作。配乐、音效、环境声和混音留在小样。

明确无任何人声时自动跳过；需要录音而尚未提供时停留第4道。漏词、改意等冲突由用户决定重录或改稿；改稿后重新确认剧本。画面依据完整实测录音时长安排，超已批片长限制由用户决定，不擅自剪词、截断、变速。

## 架构与系统设计

- 工程协议 FLOW=8（与包、插件和技能发布版本分离），旧 FLOW=7 及更早记录只读，不自动迁移，不继承签批。本次不增加迁移命令。
- 角色编号集中在 state；最终交付绑定改为7/8/9。
- 人声读取允许尚无镜头；混音、渲染继续要求有效镜头时间轴。句段和词表的来源身份排除全片起点 at，保留录音文件内容、原稿与本地时间证据。
- 人声独立摘要绑定当前剧本、人声源与句段本地定位，不绑定分镜、画面、配乐或全片起点。逐词参考表不成为签批硬门，未确认词引用仍阻塞。
- 完整录音整体移动只重新映射全片 cue。更换录音、修改原稿、内部节奏或句段语义对应需返审。受影响下游交付仍按其来源验证。
- 工作台第4道直接播放登记的原始录音，展示句段报告和参考词表；清单记录相应证据。无需生成混音来验收人声。

## 技术与事务边界

沿用已有本地 whisper.cpp 识别、人工补点、Git 两阶段签批及工作台历史对象，不引入新依赖。GitHub 仓库/代码检索未发现更合适的现成流程实现；复用本仓库定位与审核机制。所有读写保留路径范围和旧流程保护。

人声批准持久保存当前摘要；分镜及后续签批要求人声批准仍有效（明确无人声除外）。全片起点改变需重新应用句段映射，在后续制作用镜头总长校验不越界。缺失配置不可冒充无人声。重用 approval-id 仍必须验证当前证据。
