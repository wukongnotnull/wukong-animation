# 日常渲染性能与负载

状态：用户于 2026-10-30 经 grilling 确认六项取舍及最终方案，明确授权「是，开始实施」。本文固化已批准的会话方案，不增加审批节点。跟踪：#109。

## 问题与目标

Remotion 小样按原帧率绘制后降帧，局部返修仍拼接整片，多个阶段重复解码检查。减少重复工作，平衡速度与日常机器负载，不以降低终稿画质换速度。

## 架构与组件边界

- 渲染配置统一小样尺寸/帧率和并发：长边不超过 960、不放大小尺寸素材、保持画幅且输出偶数尺寸；帧率不超过 15，原本更低则保留。终稿尺寸、帧率和编码品质不变。
- 两条管线直接使用输出时间轴生成帧；词首定位与实际生成帧率一致。Remotion 常规小样只编码一次，尺寸不能等比例精确缩放时允许尺寸后处理。
- 日常新增 preview 入口，只更新变更镜头或明确选择的镜头，输出可播放的局部审阅文件；render/final 保留明确要求整片的含义。
- 验证层根据视频内容、期望帧数/帧率、检查实现和 ffprobe 版本复用成功证据；失败、损坏或缺失证据不能复用。完整预览、QC、验收和终稿在本次调用完整解码检查，每个相同媒体不重复解码。
- 字体子集准备复用相同来源和字表；镜头缓存按源字体及镜头自身输入判断，不因另一镜新增字形而全部失效。

## 接口、数据与行为

- `wka preview <片目录> [--only s01,s03] [--aspect 9:16] [--force]`：默认小样配置、低并发；无 only 时查变更，指定 only 时限于这些镜头，不隐式生成整片。复用现有混音的对应时间段，不触发重新配音。没有声轨时明确标为无声。
- `wka render <片目录> --proxy`：明确要求完整小样；`wka final`：完整终稿。动作细节可用原帧率片段预览。
- 日常默认 1 个渲染 worker，终稿沿用最多 2 个；已有 WKA_WORKERS 显式覆盖继续有效并校验正整数。日常视频编码线程受限。
- 保留每镜最新小样与高清缓存；主动清理入口仅删除明确可再生渲染缓存，不碰混音、人声、签批快照、成片或用户素材。
- 局部预览不建立整片通过证据，不可用于替代原有字幕、QC 和终审关卡。日志区分生成、复用与局部预览。

## 约束、兼容性与非目标

平衡优先；终稿原定画质；整片仅按明确需求生成；缓存默认留存；流程可复用。旧镜头缓存由输入哈希安全失效，旧检查缺少新证据时重新检查。共用代码、源字体或公共依赖变化仍使相关镜头失效，不冒险复用。不默认启用硬件编码，不承诺固定提速倍数或风扇静音。不修改用户既有成片或插件安装缓存。

## 错误处理与运维

非法镜头名与并发参数在渲染前失败。视频变化必须重新验证，损坏媒体阻断任务；检查缓存损坏按未命中处理。中断不能发布半成品或写入成功证据。缓存清理保留验收快照，并使后续命令重新建立所需渲染证据。

## 验收标准与测试

1. 横竖/高帧率/低帧率/小尺寸素材的小样规格符合上述策略，终稿不变；长片累计切点误差不超过半帧。
2. Remotion 小样实际生成帧数等于输出时间轴帧数，不先生成原帧率帧；词首提示正确。
3. 两镜工程首次局部预览产生局部文件而无整片；无修改复用；单镜修改只重渲该镜；--only 不渲未选镜头；音频对应原时间位置。
4. 相同媒体检查可跨调用复用；期望值、内容或检查条件变化重查，坏缓存不通过；完整检查不依赖历史成功报告。
5. 新增另一镜汉字不使未变镜头缓存失效；源字体变化仍失效。
6. 清理不会删除原始文件、声音、成片和签批快照；小样与高清互不覆盖。
7. 回归 unit/integration、lint、构建与适用 smoke；在隔离副本做代表片段首次/未改/单镜变更测量，记录耗时与资源指标，区分实测与未验证。
