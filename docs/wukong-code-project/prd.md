## 1. 背景与问题

wukong-animation 面向通过代码制作动画短片的创作者，已经具备简报、剧本、声音、镜头、字幕、横竖改版与草稿交付流程。本次客户最终签批了全部交付物，但反复遇到不能打开审片文件、字幕遮挡、后段同步漂移、列举词出现滞后，以及等待阶段难以判断的问题。

事实与源码依据见 [体验报告](reports/2026-10-29-codex-editing-experience.md)。回溯时发现 Remotion 独立镜头帧数舍入与逐镜代理降帧可引入累计时长误差，客户工程曾通过时长量化规避。该首批问题现已由 [PR #94](https://github.com/wukongnotnull/wukong-animation/pull/94) 修复并补齐长序列验证；其余体验需求继续分批推进。

这是本仓库首份 PRD，当前只记录本次需求，不反向宣称所有历史功能已通过产品验收。用户于 2026-10-29 在本会话明确回复“批准”，确认本文件及首批 FR-1/FR-2 的推进；第二批 FR-3/FR-4 两份 spec 随后分别获批，并通过 PR #95 合并；后续 spec 仍分别审阅。

新增问题：v0.15.0 已提供 Claude Code、Codex 和 ChatGPT 桌面本地环境入口，用户要求在更多主流 Agent 上安装。本地核对发现技能依赖完整插件目录中的引擎、画风和模板，单独复制技能不保证可用；各宿主发现目录、工具能力、作用域与媒体交付也有差异。官方文档与安装器目录调查见[兼容性报告](reports/2026-10-29-agent-installation-coverage.md)。本轮新增需求独立由 #98 跟踪。

2026-11-07 新增问题：用户希望每个制作环节都有统一的交付物检查与预览界面，采用类似剪映的工作区布局，并明确不需要剪辑能力。经分轮访谈，用户确认面向所有插件安装用户，采用本地浏览器工作台，支持定位批注、阶段签批和历史版本，由对话统一执行返修。

2026-11-07 立项时的源码事实：制作流程有 [15 道工序和 12 个审片节点](../../plugin/skills/director/SKILL.md)，已有阶段、签批和最终交付记录；[中间交付清单](../../plugin/engine/core/delivery.mjs)未完整覆盖简报、剧本、分镜与局部小样，[preview](../../plugin/engine/core/job.mjs)生成的是每镜 MP4，尚无审阅网页。工作台是新增界面与全流程交付物管理能力，不把当时的文件链接或渲染画布算作已实现。由 #127 单独跟踪，#93 和 #109 的原有待办不因此关闭。

2026-11-08 完善背景：工作台首版已在本地实现；完整回归 590 项、严格剪映集合 19 项及此前 13 项浏览器操作检查通过，集合有重叠，详见[首版验证记录](reports/2026-11-07-review-workbench-validation.md)。本轮实际审阅又发现分镜原始表格难读、待办缺少直接定位入口、未保存意见缺少上下文隔离、检查文案和来源复核状态矛盾、历史视频沿用当前镜头表等路径；已有测试通过不等于这些新路径已覆盖。用户确认先改善审阅效率、定位问题与返修复验，视觉细节随后，继续由 #127 跟踪。

2026-11-08 制作流程调整：用户希望减少新片的独立工序与签批，将美术并入方案简报，将声音、镜头和剪辑合为制作小样，再将终版渲染与终审合为制作成片。在用流程仅使用用户提供的人声，完全取消字幕能力；用户进一步要求弃用旧流程、不再维护，旧片只读留档，续作另建新项目复用素材，不开发自动迁移。工序文案最终确定为八道工序，文字镜头安排的交付物命名为“分镜稿”，由 #133 独立跟踪。

本轮调研基线为已发布 v0.20.0 的 `44892d6`：[进度记录](../../plugin/engine/core/state.mjs)仍按 15 道工序、12 个审片节点运行，缺少进度文件的目录也可能已有简报或影片文件；[工作台](../../plugin/engine/core/workbench.mjs)和[交付物目录](../../plugin/engine/core/workbench-catalog.mjs)使用旧工序归属。[录音处理](../../plugin/engine/audio/soundtrack.mjs)可测量录音时长，但尚未内置台词识别或强制对齐，读取总时长不能证明每句台词已准确定位。[剪映导出](../../plugin/engine/exporters/jianying/plan.mjs)还存在从人声文本生成字幕的路径，不能只删除字幕工序文案就宣称新片已无字幕能力。这些是待改动的现状，不是本轮完成证明。

## 2. 目标与非目标

目标：让创作者在第一次收到审片材料时就能打开、理解并评审；让长片声画同步可量化验证；减少重复计算、重复提问和中断后的重复操作。

非目标：增加动画风格、替换渲染框架、自动跳过客户审片、修改客户现有成片、解决模型额度或第三方服务故障、此次自动发布插件。剪映草稿的声音母带处理完全等同成片不在首批目标内。

本轮新增目标：用户能在尽可能多的主流 Agent 中可靠安装、发现和使用同一套动画制作能力；首批具名目标 27 个工具族，交付门槛至少 25 个有证据的安装适配，标准兼容的其他工具继续扩展。安装覆盖数量与宿主实际渲染数量分别报告。

本轮不自动安装各家 Agent 客户端、注册云账号、购买模型额度或提交各平台商店；没有本地/可配置终端执行能力的普通聊天界面不列为完整制作支持。无需为扩平台复制多份制作流程或让用户改变现有作品结构。

### 全流程审阅工作台的目标与边界

目标：所有具备本地制作环境的插件用户，都能在一个工作台按阶段找到交付物、检查具体内容、留下可定位意见、提交真实有效的阶段结论，再回到对话集中处理返修。新旧版本及其审阅状态可追溯，缺失、失效或无法直接预览的产物有明确说明。

第一版边界：单人使用、本地浏览器、素材留在电脑、无需另建账号；界面提供只读预览与审阅操作。不开设剪辑、直接文字编辑、在线协作、云端素材托管或宿主内嵌界面。保存意见或提交需要修改不自动触发生成；本次开发不修改版本号、不自动发布或改动已安装插件缓存。

本轮首批完善目标：让“发现问题 → 记录意见 → 对话返修 → 查看新版本 → 用户确认解决”成为可连续完成且版本可信的审阅过程。优先电脑普通浏览器和宿主浏览器侧栏的较窄窗口；适配侧栏尺寸不新增宿主专用内嵌集成。完整手机版、完整版本差异对比、制作期间并行提交审阅、容量与备份管理延后。本批保留已有版本切换和历史查看能力。

### 新影片精简流程的目标与边界

目标：新片按 8 道工序、7 个审片节点组织制作，以完整小样、正式成片的整体效果验收；过程文件、真实检查、失败恢复与版本依据继续可见。工序使用短名称和一句说明，交付物直接使用成果名称。具备本地制作条件的插件用户可接入整段或多段人声，通过本地自动台词定位或人工补充时间点完成声画编排。

只维护新的八道制作流程。旧流程及其 AI 配音、字幕制作等运行能力弃用，旧项目仅保留已有文件、成片、签批和批注的历史查看；不删除或改写原记录，不自动迁移或换算旧签批。需要续作时另建新项目，复用素材后按新流程补齐并审阅，不继承旧项目的通过状态。在用流程不提供 AI 人声生成及任何字幕制作、导入和交付能力；旧字幕文件可作为历史资料查看，不因此恢复字幕制作能力。配乐、音效、环境声和画面标题、题字等继续保留。工作台仍是预览与审阅界面，不新增手动剪辑或文字编辑器；剪辑由插件在制作过程中完成，不扩展为通用多轨素材编辑器。首版不接在线识别服务、不上传录音，不新增独立的录音识别签批环节，不自动修改版本号或发布。

## 3. 用户与场景

- 作为不写代码的创作者，我想直接播放审片文件，以便把时间花在内容判断上。
- 作为制作多镜头讲解片的创作者，我想片尾仍然声画一致，以免全片返工。
- 作为制作中英双语横竖片的创作者，我想术语完整、字幕清晰，画面文字不被盖住。
- 作为继续被中断任务的创作者，我想代理知道已完成什么，以便继续制作而不重复导出。
- 作为使用 Cursor、Copilot、Gemini 或其他 Agent 的创作者，我想直接安装并使用同一套动画工具，而不必切换助手。
- 作为同时使用多个 Agent 的创作者，我想共享制作能力，并清楚知道各宿主能做什么、哪些能力尚未验证。
- 作为已有其他技能和工程的用户，我想安装、升级或卸载 wukong-animation 时保留自己的设置和作品。
- 作为正在审阅影片的创作者，我想按制作阶段看到文档、画面和声音，以便不再逐个寻找散落的文件。
- 作为提出返修意见的创作者，我想指出文字、画面位置或播放区间，并在对话中统一处理，以便不必反复描述问题出现在哪里。
- 作为确认某一版本的创作者，我想让通过结论只对应我检查过的内容，以便发现后续修改对已审阶段的影响。
- 作为接续旧项目的插件用户，我想接入现存交付物并保留此后的版本，以便开始使用工作台而不用重做影片。
- 作为反复切换交付物的审阅者，我想恢复每份文件未写完的意见和上次审阅位置，以免丢失内容或把意见记到错误版本。
- 作为复验返修的创作者，我想看见每条意见对应的修改说明、新版本和验证结果，由我决定解决或继续修改。
- 作为使用较窄侧栏的创作者，我想优先看清预览，并随时切换文件、意见和检查面板而不丢失当前上下文。
- 作为开始新片的创作者，我想通过方案简报、分镜稿和完整小样逐步确认内容，不再分别停下签批美术、声轨和镜头制作。
- 作为提供录音的创作者，我想直接交整段或多段人声音频，让画面适应真实录音；时间点无法可靠确定时，我能补充修正。
- 作为接续历史作品的创作者，我想保留旧片的文件和审阅记录，并在独立新项目中复用素材，按唯一在用的新流程继续制作。

## 4. 功能需求

本轮适用范围说明：以下 FR-1～FR-34 保留原编号与历史批准。FR-4 的字幕制作要求、FR-7 的字幕制作约定、FR-16 的独立旧工序清单、FR-18 的字幕专用预览及 FR-24 的旧项目继续审阅写入，对今后的制作标记为 **Deprecated（旧流程弃用）**，由 FR-35～FR-46 的单一新流程和历史只读规则替代；历史描述保留，不继续维护旧制作能力。旧文件的通用只读查看及现有记录保留仍适用。其余同步、检查、可追溯审阅、平台兼容与新项目交付要求继续适用。

| 编号 | 优先级 | 用户可见行为 |
| --- | --- | --- |
| FR-1 | Must，首批 | 高清与小样、主版与副版均使用一致的剪辑时间约定，每个切点与全片总长的误差不随镜头数累计 |
| FR-2 | Must，首批 | 审片前校验输出切点和总帧数；超限时标明画幅、位置、期望值与实测值，不能报告同步通过 |
| FR-3 | Should，第二批 | 列举词与步骤文字可依据实测人声同步点出现；缺少可用同步点时明确标为未验证 |
| FR-4 | Must，第二批 | 横竖双语字幕保留完整英文术语，保留人工断句，并在审片前检查遮挡与亮暗背景可读性 |
| FR-5 | Must，第三批 | 主版保护结果只在输入、定稿基线和验证条件都相同的情况下复用；发生变化时重新检查 |
| FR-6 | Must，第三批 | 进度清楚标识当前画幅和阶段；中断恢复时先检查状态及产物，已授权且无需用户审片的步骤继续执行 |
| FR-7 | Must，第三批 | 每次交付提供存在的、符合宿主规则的可点击文件；素材来源明确询问；已确认的字幕、画幅、草稿交付要求不重复询问 |
| FR-8 | Should，第三批设计 | 配乐提交前审听开场和段落变化，QC 逐项区分未解决问题与有依据的人工接受项，草稿与成片的声音差异在导出前说明 |

“首批/第二批/第三批”为建议拆分，每批先独立 spec 审阅，不把本 PRD 作为一次性跨模块修改的许可。

### 主流 Agent 安装覆盖（已确认）

| 编号 | 优先级 | 用户可见行为 |
| --- | --- | --- |
| FR-9 | Must | 保留现有原生插件安装，并覆盖至少 25 个具名主流 Agent 工具族的适用安装入口；同一工具的 IDE/CLI、地区版本不重复凑数 |
| FR-10 | Must | 安装后可发现动画入口，访问完整引擎/风格/模板并完成环境检查；复制、下载或移动安装位置不依赖开发机路径或缺失的外部兄弟目录 |
| FR-11 | Must | 用户可选择宿主实际支持的项目级/用户级作用域，预览将写入的位置，检查已装版本、升级和卸载；重名或用户修改得到明确处理，不误覆盖其他技能、配置或作品 |
| FR-12 | Must | 同一制作流程适应宿主实际工具能力：可用卡片则用卡片，否则文字确认；媒体用可用预览或真实文件交付；缺少执行能力时明确受限，仍保留全部必要签批 |
| FR-13 | Must | 兼容矩阵按工具/版本/操作系统分别列出文档依据、安装契约、宿主发现和最小制作验证结果；未测试或失败不写成已通过 |
| FR-14 | Must | 提供面向各主流工具的简明安装、检查、开始制作、更新和卸载说明；新增标准兼容宿主可扩展，不改变既有项目及原生插件用法 |

覆盖目标详见调查报告中的 27 工具族矩阵。数量按有依据的适配入口统计，不能因为所有宿主都能读取一个文件就宣称全部制作功能兼容。

### 全流程交付物预览与审阅工作台（已确认）

| 编号 | 优先级 | 用户可见行为 |
| --- | --- | --- |
| FR-15 | Must | 插件用户可启动本地浏览器工作台并切换影片，无需另建账号；本地素材不因打开工作台而上传 |
| FR-16 | Must | 按现有全部制作阶段组织交付物，覆盖简报、剧本、分镜、美术方案、配音试听、声轨、风格帧、动态分镜、局部小样、字幕、检查报告、主副版成片及最终交付；区分未生成、缺失和不适用 |
| FR-17 | Must | 默认深色布局：顶部切换影片，左侧阶段与交付物，中央预览，右侧版本、检查结果及意见；音视频下方显示只读时间轴，文档阅读时收起时间轴 |
| FR-18 | Must | 文档、图片、音视频、字幕和检查报告可直接查看；音视频可播放及定位时间/镜头；文字和制作内容只读，不提供剪辑或文字编辑器 |
| FR-19 | Must | 支持整份交付物留言，以及文字选段、图片位置、音视频时间点或区间批注；意见绑定具体版本，点击意见回到相应内容 |
| FR-20 | Must | 界面可提交通过或需要修改，逐项保留检查状态、按阶段正式签批，并与现有制作流程同步；必需交付物缺失或存在未解决的阻塞问题时不能报告该阶段已通过 |
| FR-21 | Must | 默认展示当前版本，保留历史内容供切换比较；明确待审阅、已通过、需要修改、已被替代等状态，旧版本通过不自动批准新版本 |
| FR-22 | Must | 上游内容变化后，受影响的下游成果明确标为需要复核，保留原文件和历史结论；不把无关成果一律作废 |
| FR-23 | Must | 界面保存意见和待办，用户回到对话发起处理后，插件读取对应版本、定位和要求执行返修，无需逐条复制；保存或提交返修意见本身不启动生成 |

## 5. 非功能要求

- 兼容既有 film.json 与已签批工程；不得自动改写客户镜头时长来掩盖引擎误差。

- 缓存只能减少重复工作，不能隐藏输入变化或复用失败、缺失、未完成的校验。
- 同步检查以当前输出帧率计量；不能用最终音视频截短掩盖中间切点漂移。
- 无法自动判断的视觉/音乐问题保留人工审阅，不宣称自动识别所有语义错位或可读性问题。
- 首批覆盖支持的渲染管线时间约定；各管线改动范围由 spec 根据代码与测试确定。
- 本轮安装能力覆盖 macOS、Linux、Windows；路径含中文/空格时有效，不依赖某一种 Unix shell 或管理员权限。各宿主不提供的作用域明确标注。
- 保持一套版本一致的制作规则、引擎与风格资源，避免跨宿主升级后混用版本；依赖仍按实际环境安装，不把开发机缓存和成片打包给用户。

- 排版阅读与原文查看均保持只读；展示文档不能执行其中的脚本或使原有批注位置失真。
- 草稿只保留在本机；明确显示保存失败，不能把失败写入显示为已保留。页面恢复、服务重启或新版出现不将草稿静默转移到其他交付物或版本。

## 7. 成功指标

首批以可自动复现的验收标准为交付门槛。上线后的返修率、等待时间与重复操作减少量待定，当前只有单片样本，不设虚构改善百分比。后续可在用户同意的本地制作记录中比较同步缺陷次数、无效链接反馈次数与重复比对次数。

新增安装需求以“有证据且契约通过的具名工具族数”和“实际宿主最小制作通过数”分别计数，首项目标至少 25；不把不同安装目录、地区版或同工具多客户端重复计数。实际使用转化率和安装耗时指标暂无数据，不编造数值。

工作台首版以 FR-15～FR-26 的可复现验收为交付门槛。审阅耗时、重复描述次数和返修效率暂无基线，暂不承诺改善百分比；后续是否采集指标另行决定，不默认增加遥测。

本轮以 FR-27～FR-34 的完整审阅路径和状态一致性为门槛，不以增加控件数量或视觉改动幅度衡量完成。仍无真实用户效率基线，不新增遥测或承诺改善百分比。

精简流程以 FR-35～FR-46 的逐条验收为门槛：唯一在用的 8 道工序/7 个审片节点、旧档案只读且可独立新建续作、整段与多段录音能完成定位及小样制作、失败可通过补修时间点继续。制作耗时、识别误差和人工修正量需按实测样本记录；当前不承诺固定加速比例、识别准确率、所有电脑自动对齐或统一处理时长。

## 8. 范围外与风险

- 帧分配改变会影响缓存与实际切点；必须在 spec 说明迁移和旧定稿保护，不能悄悄替换已签批画面。
- 正确总长不等于内容语义同步，FR-3 与人工抽查仍有必要。
- 文本边界与视觉遮挡无法仅靠当前像素 QC 全量判断，不承诺通用自动碰撞检测。
- 模型额度、接口错误和外部播放器行为不由插件控制；通过恢复与明确状态减轻影响。
- 剪映草稿母带差异继续明确披露，自动母带一致化另立设计。
- 不同宿主或多宿主安装器升级可能改变发现路径、复制规则和优先级，适配依据须记版本和日期；不能仅依据安装器宣传的数量认定本插件兼容。
- 技能被扁平复制、名字去掉插件命名空间、符号链接被宿主拒绝，均可能使入口失效；确切分发与资源定位方案留待 spec，不在需求文档预设某个安装器必定可行。
- 云端与远程 Agent 不自动继承本地依赖、素材和预览能力，实际执行及产物取回另做验证；项目级技能可安装不等于具备完整媒体制作环境。
- 现有中间交付清单不覆盖全部早期产物，美术方案也没有统一文件契约；实现时必须补齐实际制作登记，不能只扫描文件名就宣称全流程覆盖。
- 历史签批记录不等于历史文件仍然存在；不得把当前内容冒充旧版本。持续保留媒体版本会增加磁盘使用，首版不擅自删除审阅证据；空间不足时报告失败，不能丢弃历史后仍报告保存成功。
- 上游变更与下游有效性必须按真实依赖判断；旧阶段序号较大不等于所有成果当前有效。
- 本地浏览器不能替代剪映等专用软件；外部打开和实质验收需要分开记录。浏览器播放成功也不等于内容质量已获用户批准。
- 本轮不包含完整版本差异对比、制作期间并行提交审阅、容量与备份管理、完整手机版；已有历史版本切换、数据保留及明确失败提示继续有效。
- 文档排版和分镜卡片会改变可见结构，必须验证批注仍定位到原版本原句；未知历史时间轴不得用当前镜头信息补造。
- 返修回填可能发生在新版继续变化之后，必须明确结果对应哪个版本；未完成、失败或尚待用户复验的事项不能静默归为已解决。
- 旧记录与新流程的同号工序含义不同，历史查看只能展示原记录，不得按新编号重解释或写回。只替换全局名称/工序数量仍可能造成历史签批串用；未知流程记录不得降级成新片。
- 自动识别的文字与时间戳不天然等于给定原稿的准确对齐；多说话人重叠、数字和不清晰录音可能需要人工修正，不增加字幕能力或单独识别签批来代替这种复核。
- 本地组件及模型的系统、架构和语言支持不同；[whisper.cpp 官方资料](https://github.com/ggml-org/whisper.cpp#readme)与 [WhisperX 官方资料](https://github.com/m-bain/whisperX#readme)说明本地 CPU 路线可行，但不构成本项目的平台或精度验收，也不在 PRD 锁定唯一实现。具体选择及验证范围在 spec 中确定，无法自动处理时保留人工时间点路径。
- 本轮不新增在线识别服务、AI 人声模型或自动配乐服务，不维护旧制作流程、不自动迁移旧项目，不扩展工作台为剪辑器；旧档案只读保护与新流程制作分别验证，历史已通过的测试不能作为新流程已实现的证据。
