# 本地审阅工作台

在包含本次功能的插件中说：**“用 wukong-animation 打开这个项目的审阅工作台。”**

插件会在浏览器打开本机页面。无需账号或带凭据的长链接，直接打开启动命令显示的 `http://127.0.0.1:<端口>/` 即可；新标签页、换浏览器和刷新均可使用。素材留在电脑上，第一个启动服务的终端进程需保持运行；后续打开项目会复用服务，接入后命令退出。工作台自 0.20.0 起随发布包提供；本页自动复用行为需包含本次改动的引擎，旧安装版本不会自动获得新行为。

工作台只监听本机地址，并校验浏览器请求来源，其他网站或其他端口不能直接读写。现代浏览器会自动提供所需信息。已兼容部分扩展把 `Origin` 端口删掉的情况：目标地址必须准确，且浏览器仍明确标记同源；这不会允许跨站请求。如果仍报 403 或只显示文字，请检查跨域、代理或请求头修改扩展是否进行了其他改写。缺失来源信息时拒绝请求。

## 怎么审阅

同一个地址可以切换多部影片。以后打开任何项目，只需：

```text
wka workbench "/路径/新项目" --open
```

命令优先复用已登记的工作台，把新项目加入顶部“当前影片”；页面几秒内自动更新列表，保持当前预览和输入，不需刷新或重启。新打开的链接用 `?film=` 选中目标影片（不是凭据），裸地址仍可使用。首次默认端口 63711；服务关闭后再次运行命令会恢复已加入的项目和原端口。后台标签更新较慢，切回页面会立即检查。

一个工程的 `films/` 下可放多片，也可以一次指定多个独立目录。原文件和正式审阅记录各留在原目录，不需要复制；同名影片带路径区分，重复接入只显示一次。不扫描其他工程，也不接管旧版或其他任务的未登记服务。旧版服务需升级后重启一次。

统一服务的目录清单与私人会话保存在引擎用户数据目录 `workbench/` 下（默认 `~/.wukong-animation/workbench/`）。旧单片工作台私人草稿保留原处，不读取或迁移。`--capture`、`--pending`、`--register`、`--repair` 每次仍只接受一个片目录，且不启动或连接服务。

1. 首次打开显示待审总览，可搜索文件、阶段和意见，筛选阻塞、待复验、需复核或未检查。以后恢复上次的影片、交付物及查看版本；“待审总览”始终可达。
2. 中央只读阅读文档、查看图片或播放音视频。Markdown 默认按标题和表格排版，可以切到原文；分镜表提供镜号定位。视频下方可以定位镜头和时间；旧版本缺少镜头证据时会明确说明，只按播放时间定位。
3. 选中文字、点击图片，或点击“标注当前时间”，在右侧留下具体意见。音视频区间可以填写起点与终点；总体意见不用定位。
4. 每项检查完成后点击“标记此版本已检查”。本阶段所有正式必需项齐全且阻塞意见解决后，再点击“通过本阶段”。额外扫描的参考资料不自动成为必检项；历史交付物仍能打开。也可以填写结论并点击“需要修改”。
5. 回到对话说“处理工作台里的待办”，插件会读取意见和准确位置，不必复制每条意见。保存批注不会启动生成。

“查看版本”可切换历史；旧版通过不代表新版通过。来源变化会显示“需要复核”，明确检查后按新依据记录；再次变化则重新复核。制作产生新版本后，工作台在制作结束时自行载入最新报告，并把正在查看的交付物切到当前版本。未提交草稿留在原版本。“刷新交付物”仍可重新读取并保留当前选择。

宽窗三栏可以收起及调宽；窄窗通过“文件 / 预览 / 意见 / 检查”切换，播放位置、选段和输入保持。分镜表在较窄窗口展开为字段卡片。用“下一待审项”继续处理队列。

未提交意见按影片、交付物和版本分别保存草稿，阶段结论按阶段依据保存；切换和重新打开时恢复。顶部会区分“只保留在此浏览器”和“已保存到本机工程”。草稿不会自动变成正式意见；点击“保存意见”才提交，失败仍保留。阶段依据变化后，旧草稿可在“其他依据下的结论草稿”查看。

返修结果包含修改说明、目标版本和实际验证结果。回填后显示“已返修，待复验”，阻塞仍保留；打开对应版本并检查后，点击“确认复验通过”。也可以退回继续处理，或填写理由选择无需修改关闭。新版不会自动解决旧意见；“全部意见与历史”可查看处置记录。阶段返修最后仍通过“通过本阶段”确认。

剪映草稿等专用工程显示文件组成和检查状态，通过“定位原文件”前往系统文件管理器，再用专用软件检查。定位成功不等于已经打开或验收。

## 给制作助手的入口

下面 `wka` 指当前安装插件的 `node <插件根目录>/engine/bin/wka.mjs`；由技能根据实际安装路径解析，不使用作者电脑路径。

```text
wka workbench <项目或片目录> --open
wka workbench <片目录> --capture
wka workbench <片目录> --pending
wka workbench <片目录> --register <文件或目录> --step 3 --label "美术方案"
wka workbench <片目录> --repair <意见或阶段要求ID> --artifact <交付物ID> --version <版本ID> --summary "实际修改说明" --verification "实际验证结果"
```

支持 `--port N` 指定本机端口；有统一服务运行时需与其端口相同，否则明确报错。`--port 0` 可另开临时独立服务，不读写统一项目清单；适合隔离验收。端口被其他程序占用时不会自动结束该程序。自定义交付物可用 `--depends "来源路径1,来源路径2"` 声明来源，依赖路径以片目录为基准；仅供参考的资料加 `--reference`。外部交付物必须明确登记，页面不能任意浏览电脑文件。

制作助手应在覆盖文字等交付物前 capture，写好后再次 capture。接入后的引擎制作命令也会保存交付版本。美术方案及选定理由保存到 `visual-direction.md`；人声来源和试听选择保存到 `review/人声来源.md`。与原命名不同的旧材料可登记，不需要为了使用工作台重做影片。

处理待办后逐项回填已有当前版本：ID 来自 `--pending` 和 `--capture`，不能凭空填写或把失败处理标为完成。`--repair` 只记录结果，不生成、不替用户解决意见或签批。阶段要求回填时指定本阶段的目标交付物，最后请用户检查当前阶段成果。

## 保存、故障与边界

- 审阅账本：片目录下 `.wka/workbench.json`。历史内容：`.wka/workbench/objects/`，按内容去重并排除出 Git，保留在本机。备份影片时应同时备份这两处。
- 草稿、审阅位置和布局：统一服务在用户数据目录 `workbench/workspace/.wka/workbench-local/` 保存；临时独立服务仍保存在启动工作区 `.wka/workbench-local/`。已经同步的草稿可跨服务重启或端口恢复；断线未同步的内容只在浏览器原地址，勿清除该地址数据。多个页面发生冲突会保留本页内容并提示核对，不静默覆盖。
- 项目清单 `workbench/catalog.json` 与运行记录 `workbench/runtime.json` 使用本机受限权限。运行记录中的控制凭据仅供 CLI 接入项目，不进入页面或链接；浏览器不能调用项目接入控制接口。异常退出可在下次启动恢复，损坏或新版记录不会被自动覆盖。
- 工作台不能找回从未保存、已被覆盖的旧内容，也不会把当前文件冒充历史版本。历史存储会占用磁盘；空间不足时应先处理，不能删除证据后继续假报保存成功。
- 文件缺失、来源变化、检查不通过、其他制作命令正在写入时，页面提示具体原因和最后同步时间；制作占用时正式提交暂不可用，已加载内容和草稿仍保留。恢复后由用户再次提交正式意见。文件存在或可播放都不等于用户已通过。
- 字幕、时间轴、主版保护、最终交付的既有签批条件继续生效。批准已记录但 Git 存档未确认时，回到对话核实存档状态。
- 需要本地 Node.js 环境和可用浏览器。没有本地执行能力的纯聊天宿主不能启动本机服务。专用软件和浏览器格式支持以实际检查为准。
- 不提供剪辑、文字编辑、云端协作或自动生成；视频生成仍按每批单独确认的规则执行。
