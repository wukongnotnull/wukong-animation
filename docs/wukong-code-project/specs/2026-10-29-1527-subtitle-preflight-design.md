# 第二批 B：术语保护与字幕预检

Status: Confirmed — 用户于 2026-10-29 明确批准两份 spec

日期：2026-10-29（Asia/Shanghai）

依据：[已批准 PRD](../prd.md) FR-4、[体验报告](../reports/2026-10-29-codex-editing-experience.md)、[issue #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。源码基线 `c787f44`。本文件与同批词级同步 spec 可分别审阅、分别实施。

## 1. 问题与目标

当前 subtitles.mjs 的 hardSplit 逐字符硬切，能拆开 A-roll、B-roll、Remotion。字幕条内时间仍按整句字数比例分配，不能把断句检查通过称为词级声学对齐通过。

字幕层会把过宽文字逐像素缩小到 8px；当前只打印缩小日志，不输出实际字框或安全区报告。安全区写在风格文档和 Guides 中，但没有在烧录时核对。Keynote 的统一 bottom=0.074 也不能直接满足文档中竖屏底边 y=1500 的约定。客户曾在所谓“没有遮挡”的提交后发现字幕压住画面标签。

目标：生成时保护术语、运行时保留人工字幕；按实际字体和双语布局检查字框，输出能实际看清的亮暗背景样张及影片抽帧。已知遮挡自动报告，未知画面内容明确留给人工审阅。

## 2. 架构与组件边界

| 组件 | 职责 |
| --- | --- |
| `core/subtitles.mjs` | 按不可拆的术语单元分条；检查手改条目的边界风险，不覆盖原文 |
| `core/subtitle-layer.html/.mjs` | 返回实际字号、含描边字框、字体加载信息与行高；预检和烧录共用同一布局结果 |
| `core/subtitle-preflight.mjs`（新增） | 合并版式约束、检查字框和已声明重要内容区域、生成报告与预览 |
| schemas、style/film 配置 | 定义可选保护术语、字幕安全区和按画幅覆盖 |
| CLI、director、Keynote | 把预检接入字幕预览与最终输出；提交带证据的结果，不声称自动理解全部画面 |

不依赖词级同步 spec 才能实施；有实测词点时仍可使用另一个 spec 的能力，但本 spec 不改变字幕计时算法或重新翻译英文。

## 3. 接口、数据与行为

### 3.1 术语作为不可拆单元

自动识别连续 ASCII 字母/数字及内部连字符、下划线、点、斜线、加号、井号组成的术语，至少覆盖 A-roll、B-roll、Remotion、Codex、3.5、C++。维持已有数字小数点和千分位的断句语义。

新增可选 `film.subtitles.protected_terms: string[]`，主副版共用，支持多词英文或中文固定词组。保护词按 Unicode 精确匹配，最长匹配优先；不改大小写、翻译或用户用词。

继续优先在标点/已有语义段落断开；超长段落按计数字数装箱，但只在术语单元之间切开。单个术语本身超出上限时完整保留并明确警告，不生成半词；字数上限是排版建议，不成为破坏术语的理由。

英文副版重排也以保护单元为边界，并保持原译文词序、内容与术语。不能因保护词而制造空英文条目；无法放下时报告而非重译或删词。

已存在 SRT 的默认行为仍是只检查；检查发现相邻字幕可能拆开保护词时给出条号和合并/改切点建议，不替用户重写。`--force` 沿用既有明确覆盖行为；不把普通 preview/preflight 隐式变成 force。

### 3.2 单一有效字幕样式

在 style.subtitles 增加可选 `by_aspect`（以 16:9、9:16 等为键）和可选 `safe_area: [x,y,w,h]`，safe_area 使用相对整幅画面的 0–1 坐标。

生效顺序为：基础风格字幕样式 → 风格当前画幅覆盖 → film.subtitles.style → film.variants 当前画幅的 subtitles.style。film 的 style 可覆盖 safe_area，但不加入嵌套 by_aspect，继续利用现有 variants。

没有 safe_area 时只能检查画布边界，报告“未配置平台安全区”，不能认定满足某个平台 UI 避让。Keynote 显式使用已有文档中的横屏安全区 (120,80,1680,920) 与竖屏 (72,200,936,1300)，归一化存储；字幕底边横屏 y=1000、竖屏 y=1500，按画幅配置 bottom。单语与双语底边一致，双语向上扩展。

渲染与预检共用同一有效样式和实际字框；旧 Guides 的示意不作为已测量证据。预检截图叠加实际字幕带、安全区和重要区域，无需用户修改镜头源码来临时插入 Guides。

safe_area 限制可用宽度，拟合文字时采用它与现有 90% 画宽中的较小值；含描边字框仍须落在安全区内。缩小字号后比设定字号低超过 20% 时警告；该阈值是排版风险提示，不声称可读性的通用标准。

### 3.3 已声明的重要内容区域

增加可选片级 `subtitle-layout.json`，版本 1，按 `aspects[画幅][shotId]` 存放重要内容区域数组。每区包含唯一 id、说明 label、归一化 rect `[x,y,w,h]` 和相对镜内秒数的有效区间 time `[from,to]`。

根据首批实际切点与字幕时间求重叠时段，再检查实际含描边字框是否与有效内容区相交。相交时报告镜号、字幕条、时间段和区域 label；不擅自把画面元素搬走或删除字幕。

缺少区域声明时，遮挡检查标为未覆盖，必须交人工看画面；不能把空区域列表当作“全片没有遮挡”的证明。不做 OCR 或通用动画对象碰撞识别。full_bleed 只影响留白质检，不豁免字幕可读性和关键内容遮挡。

### 3.4 CLI 与交付物

新增 `wka subtitles <片> --preflight [--aspect <副版>]`：使用当前画幅已通过首批时间轴检查的小样，读取现有字幕并生成预检，不改 SRT。`--preview` 自动包含预检；最终输出在全分辨率布局下再检查一次。

基础命令不带 preview/preflight 时维持现有纯文本字幕生成/检查行为，不要求先渲染视频。

生成 `review/字幕预检[-画幅][-proxy].json/.md`，记录：

- 字幕和英文稿内容摘要、有效样式、测量尺寸/fps、字体 CSS/字体文件和输入视频的来源签名。
- 每条字幕实际字号、两行字框、是否缩小、画布/安全区/已知内容区检查结果。
- errors、warnings、manual_required 三类结果，分别列出机器可确定错误、风险和人工待查项。

生成可打开的样张与接触表：最长中文/英文、最拥挤双语、亮/暗底和实际视频中代表性的亮暗时刻。每个样张标明字幕条号、画幅、时刻与实际字号；提供原始字幕版本和带安全区叠加版本，原审片视频不被替换成辅助线版本。

若源片无亮底或暗底，补可复现的纯白/纯黑/灰格合成样张并明确标为合成测试，不能冒充实际片段。真实画面抽样覆盖每条字幕的起/中/末时刻；接触表重点呈现风险和亮暗代表样本，不能用有限样本推断整段没有遮挡。

### 3.5 结果含义与阻断

确定错误包括：字幕时间/格式错误、实际字框出画布或已配置安全区、声明的重要内容区域与字幕相交、英文条目缺失或对应错误。存在确定错误时 preview/final 返回失败并保留诊断材料；不提交字幕签批通过记录。

警告包括：术语本身过长、字号明显缩小、短时长、可能被手工拆开的保护词。仍可输出审阅材料，明确提示。

亮暗背景可读性、未声明内容区和完整动画遮挡属于 manual_required，不通过亮度均值或文件存在推断已通过。结果无 errors 只能显示“机器检查未发现确定错误”，不能显示“全部字幕无挡字/全部可读”。用户继续在既有字幕与改版节点审片，不新增重复审批节点。

## 4. 约束、兼容性与非目标

- 保留人工 SRT 与英文稿，修改样式不改镜头缓存；改版字幕仍使用各自文件。
- 不把所有风格的白字描边统一加粗，不自动改变用户已签批片子的字幕样式。旧 Keynote 竖屏若未显式覆盖 bottom，新的画幅默认值会改变排版，须明确提示并重新提交原审片节点；显式 film 覆盖优先保留。
- 不做通用中文语义分词、不重新翻译、不替用户修改画面重要元素，不改变首批视频帧时间轴。
- 不承诺仅靠几何或样张检测所有可读性问题；检查范围与缺失项始终可见。
- 无字幕片跳过本检查并如实标注；单语不因缺英文而失败。

## 5. 错误处理与运维

源视频或首批时间证据缺失时给出具体重渲命令；字幕文本、译文、字体、画幅或样式变化使相应预检失效，不复用旧通过结论。来源签名覆盖布局声明和保护词表。

先输出诊断，再因确定错误退出；只保留当前输入对应的报告状态。字体未能按请求加载时记录 fallback 和测量环境，无法确定实际布局时不得判几何通过。配置错误指向具体字段/区域，用户原文件不被自动修正。

## 6. 验收标准与测试

1. 横竖字幕中 A-roll、B-roll、Remotion、Codex、C++、数字小数及自定义多词术语完整；单个超宽术语得到完整文本与警告。
2. 手改 SRT 和英文稿在普通检查、preflight、preview 后字节不变；只有现有 force 操作可以重新生成。
3. 两条管线、横竖、单语/双语的实际字幕测量与烧录一致；已知出安全区和“分句拼接”标签遮挡用例失败，移开后通过对应机器检查。
4. full_bleed 的白底文档仍纳入检查；实际画面无亮暗两类时提供标明来源的合成样张。人工未核对前不宣称可读性通过。
5. 缩小超过 20%、长英文、缺字 fallback 与缺内容区域有明确结果；缺区域时不能得到“无遮挡”结论。
6. 验证 Keynote 1080×1920 的字幕底边约定、有效样式覆盖顺序与上下两行实际字框，不能仅检查配置常量。已有 film 明确覆盖不被覆盖。
7. 人声或字幕变更后，旧报告失效；预检样式修改不触发无关镜头重渲；首批帧数和定稿保护回归保持通过。

实施前补术语拆词、人工文件保护和真实渲染的遮挡失败测试，再最小实现；运行 npm test、lint、smoke。验收同时记录机器结果和人工预览结果，没有人工审阅的数据明确标为待审。
