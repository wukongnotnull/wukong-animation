# 逐词时间表（制作小样·台词定位）

Status: Confirmed；用户在本会话逐题确认设计摘要后回复“确认”，批准本文件（spec 审批已长期授权）。
日期：2026-11-11；基线：main `4972587`。

## 1. 问题与目标

制作小样时，画面和音效需要对准旁白里每个词。现有 `wka align-voice` 只给句段时间，词点只能手写 `sync-points.json`，`char-cues.mjs` 的逐字点是按字数均分的估算。目标：根据用户已登记的旁白录音，自动生成**逐词时间表**，每个词有起止时间、时长、置信度和状态，镜头与音效可直接按词踩点。

不做：SRT/VTT/字幕、上传录音、新镜头 API、修改 `speech:` 句段点、自动改稿、用均分时间冒充实测。

## 2. 入口与触发

- `wka align-voice <片目录>`：句段定位成功后默认继续生成词表（有录音时）。词表问题不改变句段定位的退出码，只在输出和报告中提示。
- `wka align-voice <片目录> --words`：只重算词表。复用已保存的识别证据；缺失或过期才重新本地识别。
- 词表只是数据；画面是否逐词踩点仍由分镜决定，默认编排仍是句段同步。

## 3. 词的定义

- 有原稿以原稿为准；无原稿用识别文字。
- 用 `Intl.Segmenter`（`zh`，词级）切词，非字母数字（标点、空白）不计时。英文自然按词切。
- 每个词保留逐字子级时间。逐字只是词内细分（来自识别 token 的均分），**精度低于词边界**，不作实测声明。
- 停顿用“前停顿”（与上一词之间的间隔）表示。

## 4. 对齐方法

1. **识别**：每段录音单独用 whisper.cpp 的 DTW 词时间（`--dtw <预设> -nfa`，预设只按官方模型文件名识别）取得字符级识别时间；含汉字原稿或语言为 zh 时加固定风格提示 `--prompt "以下是普通话的句子。"`，避免输出繁体而对不上原稿。没有 DTW 预设时，退回句段识别的 token 时间，精度较低。
2. **比对**：原稿字符与识别字符做保序序列比对（Needleman–Wunsch），不靠文字查找，重复词按序号区分。
3. **整体平移**：识别时间整体偏差可达 100–600ms（DTW 通常偏晚 150–200ms），先在 ±0.45 秒内搜索整体偏移，取与能量边界候选得分最高者。
4. **边界吸附**：用 ffmpeg 解码的 10ms 能量包络得到候选（停顿区间、能量低谷、文件首尾语音延续），按字符做逐边界的全局最优吸附（单元最短 70ms）；首尾边界使用更大容差。找不到可靠候选就保持平移后的识别时间，并记 `refined:false`。
5. 对齐器与精修是纯函数（`word-alignment.mjs`），后续可换成强制对齐器而不改数据格式。

精度目标：词首、词尾误差 ±50ms，最低可接受 ±100ms。

实测（macOS `say` 逐词合成并拼接得到已知真值，small 多语言模型）：

| 场景 | 比对边界数 | 中位误差 | 最大误差 | ≤50ms |
|---|---|---|---|---|
| 干净音频 | 28 | 8ms | 27ms | 28/28 |
| 加粉红噪声 | 28 | 6ms | 26ms | 28/28 |
| 语速 260 | 28 | 12ms | 29ms | 28/28 |

早期方案（解码器 token 时间 + ±0.12 秒局部吸附）中位误差约 145ms，已放弃。

局限：真值音频是孤立词拼接，边界清晰；真人连续语流的精度尚未验证，需要用户提供录音（最好带原稿）听审后补充。

## 5. 可信度与状态

词状态：`measured`（比对一致且置信度 ≥ 0.5）、`pending`（有字对不上/缺失，或置信度不足）、`confirmed`（用户听审后人工确认）。有 pending 词的录音状态为 `pending`。

pending 词仍带尽力估计的时间，便于听审，但**不注册为可用 cue**；镜头用到 pending 或过期的词时，渲染直接报错并说明原因，不会改用均分时间。人工确认沿用 `--import <json> --confirm "用户确认说明"`：导入文件的某段录音写 `words:[{n,text,start,end}]`，只覆盖列出的词，且必须绑定当前录音来源。

## 6. 数据与交付

- `.wka/word-timeline.json`（version 1）：每段录音 `source`（来源哈希，录音/原稿/起点变化即过期）、`status`、`words`、`tool`、`issues`。时间相对该录音，全片时间 = `source.at + t`。
- `review/逐词时间表.md`：序号、词、全片起止、时长、前停顿、置信度、状态，pending 词单独标出。
- cue：已可用的词注册为 `word:<录音cue>:<序号>`（序号从 1 起，每段录音独立编号）。镜头里用 `s.cueFrame('word:v01:3')`（帧号）或 `s.cueIn/cueOut`；音效 `audio.build` 的 `cues` 里同名键为 `[起, 止]` 全片秒。手写词点 id 不含冒号，不会冲突。
- 词表文件纳入制作输入：渲染缓存按镜头实际用到的词失效；终交依赖记录包含词表。

## 7. 验证

- 单元：分词、字符比对（重复词/遗漏/替换）、边界吸附、状态判定、来源过期、人工确认。
- 集成：合成脉冲音频走完整 `align-voice` CLI（伪造识别组件），词 cue 驱动镜头帧号与音效 cues。
- 本机真实识别（开发验证，不进 CI）：用 macOS `say` 逐词合成并拼接得到已知真值，度量实际误差；真人录音由用户提供后补充听审。
