## 1. 问题与目标

| 编号 | 已核实的现状 | 本批目标 |
| --- | --- | --- |
| R4 | `bin/wka.mjs::cmdSetup` 只生成含直接 dependencies 的清单，再执行 `npm install`，不复制仓库锁文件；仓库 CI 的 `npm run setup` 则执行 `npm ci`。用户依赖目录仅按引擎版本 0.2.0 区分，解析器逐包尝试共享目录、开发目录及 Node 后续搜索位置。 | 用户安装与 CI 使用同一份锁定依赖；不同锁文件或运行平台不共用同一目录，不能混合加载多套依赖或把失败安装当作就绪。 |
| R5 | `state.mjs::migrateProgress` 仅对 `flow === 5` 原样返回，其他值最终均改为 5；`readProgress` 和 `listProductions` 会写回迁移结果。CLI 的写入锁和 active-command 记录早于实际命令逻辑。 | 较新流程只提供兼容性诊断；旧引擎在产生制作副作用之前拒绝，不能降级状态、重标历史或签批。旧流程仍按既有规则迁移。 |
| R6 | `smoke.yml` 没有安装 pyJianYingDraft。13 项剪映集成、1 项真实终版交付集成、1 项字体映射检查依赖探测失败后跳过；v0.19.2 两组 Linux CI 各有 15 项此类跳过。 | 独立剪映任务在每次 push、PR 和手动触发时运行，依赖缺失、版本错误、测试失败或跳过均不得显示成功。 |

R5 已做隔离复现：临时 `.wka/state.json` 的 `flow: 6` 经 `readProgress` 变为 5，文件字节改变，历史自定义标签变为“终检与交付”。临时目录已删除。现有 state 单测 17 项通过，说明旧测试没有覆盖该边界。R4 为静态核对，尚未进行实际干净安装对比；R6 为源码与第一批发布 CI 日志证据。

三项按用户指定的同一批次管理，各自具有独立接口与验收，不建立跨模块的新框架。

## 2. 架构与组件边界

| 组件 | 职责 |
| --- | --- |
| `core/paths.mjs`、新增依赖身份/安装模块 | 提供依赖目录根、由清单与锁文件计算的身份、安装完成凭据；不读取或修改影片状态。锁文件检查按需发生，不能让无关的 help/status 因缺依赖失效。 |
| `core/deps.mjs` | 统一选择一套经检查的依赖根，供 requireDep、resolveDep、hasDep 使用；Remotion 的 React 等别名仍指向同一套包。 |
| `bin/wka.mjs` 与仓库 setup 脚本 | 用户 setup 在用户目录安装；仓库 setup 保留 engine/node_modules 开发安装并在成功后登记同样的依赖身份。二者都以仓库清单和锁文件为准。 |
| `core/state.mjs` | 唯一流程版本判定及旧版迁移规则，提供不写文件的兼容性检查；拒绝未知较新版和非法版本。 |
| CLI 与共享制作入口 | 在写锁、账本、缓存、报告、音频、签批等写入之前检查目标影片；兼容检查不能只放在最终保存 state 时。 |
| 独立 `jianying` workflow 与测试运行器 | 安装固定 Python 依赖、真实执行指定测试集合、收集结构化结果并拒绝 skip/todo；不安装或操控剪映桌面应用。 |

## 3. 接口、数据与行为

### 3.1 R4：按锁文件安装并隔离依赖

#### 安装输入与身份

- 用户 `wka setup` 必须完整复制随插件分发的 `engine/package.json` 与 `engine/package-lock.json`，执行 `npm ci --no-audit --no-fund`；不再生成另一份简化依赖清单。不在插件安装目录里安装依赖。
- 锁文件缺失、JSON 损坏、锁文件格式不支持或与清单不一致时明确失败；不能退回 `npm install`、在线补版本或重写源锁文件。本批支持现有 lockfileVersion 3，不借机升级依赖。
- 依赖身份包括引擎包版本、清单原始字节 SHA256、锁文件原始字节 SHA256、操作系统、CPU 架构和 Node 主版本。结构化序列化后再计算完整 SHA256，不能只靠引擎版本判断兼容。
- 建议用户目录为 `deps/<engineVersion>/<platform>-<arch>-node<major>-<identity>/`，根仍由 `WUKONG_ANIMATION_HOME` 控制。同一身份重复 setup 可复用通过检查的安装；锁文件或平台身份变化得到新目录。
- Chromium 由这套依赖中实际安装的 Playwright CLI 安装，不能通过 npx 临时抓另一版。保持 Playwright 现有浏览器缓存约定；不错误声称浏览器二进制必在 npm 依赖目录下。

#### 安装成功与失败

- 新安装先在同父目录的专属临时目录完成 npm ci、直接依赖版本检查及 Chromium 安装/可用性检查，再登记完成凭据并发布到目标目录。失败目录不得被解析器选中，不改已有有效安装。
- 完成凭据记录格式版本、依赖身份、Node/npm 版本和成功安装事实；只在实际成功后写入。凭据证明受控安装流程完成，不宣称能检测任意人为篡改全部 node_modules 文件。
- 重复 setup 需核对凭据、清单/锁摘要、必需直接包的实际版本及 Chromium 可用性。已安装 npm 包完好而仅浏览器缺失时，可只补浏览器；失败仍返回非零。
- 同身份并发 setup 只允许一个发布者；另一调用等待后重新核验或明确提示正在安装。只清理由本次调用创建且可确认归属的临时目录，不自动清除旧版本或未知目录。
- 旧的 `deps/0.2.0/node_modules` 保留但不作为新版本的可信来源。升级后第一次需执行 setup 获取新目录；旧插件仍可继续用自己的旧目录，作品和共享字体、音效不受影响。

#### 依赖解析与开发兼容

- requireDep 与 resolveDep 必须使用同一个已选择根；该根中缺包、版本不符或加载报错时保留原因，不能换到另一根凑齐运行。
- 优先使用匹配身份且完成的用户安装。没有此身份安装时，允许使用通过仓库 `npm run setup` 建立凭据的 engine/node_modules；仅“目录存在”或“某个包可 import”不再足够。
- 用户候选目录存在但不完整/失配时明确要求重跑 setup，不用开发目录掩盖损坏。解析结果必须处于选定根的 node_modules 内，不能沿父目录或 NODE_PATH 意外取包。
- 仓库 `npm run setup` 仍先在 engine 执行 npm ci，成功且版本核验通过后在被忽略的 node_modules 内写凭据；不把本机凭据纳入插件分发。贡献指南说明直接 npm ci 后尚需执行该统一入口。
- `wka check` 输出实际依赖来源、身份摘要和不匹配原因；缺少匹配安装时非零退出，并提示 setup。检查本身不安装、不迁移依赖。
- 不增加每帧/每镜遍历全部 node_modules 的成本；依赖选择及必要检查按进程复用。任意传递包被人工改写的完整性审计不属于本批。

### 3.2 R5：较新流程保护

#### 版本判定

| `.wka/state.json` 情况 | 行为 |
| --- | --- |
| 状态文件不存在 | 沿用新工程初始进度；兼容性检查本身不创建文件。 |
| 缺少 flow 字段 | 按已有历史约定视为 flow 1。 |
| 整数 flow 1–4 | 保留现有向 flow 5 的迁移、工序映射与持久化行为。 |
| 整数 flow 5 | 按当前版本处理，不因检查改变文件。 |
| 整数 flow > 5 | 不迁移、不重标、不解释工序与签批；提供工程版本、支持版本、状态文件路径及升级插件的建议。 |
| 显式 null、0、负数、非整数、字符串或其他类型 | 版本无效，明确报错；不能用真假值回落为 flow 1。损坏 JSON、读取权限错误同样不能当成新工程。 |

建议统一错误码 `WKA_FLOW_TOO_NEW` 与 `WKA_FLOW_INVALID`，保留 human-readable 中文提示；未来版本比较的是整数 flow，不是插件 0.19.2、引擎 0.2.0 或导演指令 1.17.1。

#### 读取与写入入口

- `migrateProgress` 为纯函数，先判版本再构造迁移结果；较新版和非法版抛出兼容性错误。readProgress、recordProgress、recordApproval、commitSignoff 复用该规则，不能回写未知状态。
- `status` 扫描时逐片处理不兼容状态：显示其标题、版本与升级提示，不给出“下一道工序”“已完成”或重新解释签批。其他兼容影片照常显示。存在不兼容影片时总体退出码为 1。
- `resume` 对不兼容影片只返回兼容性诊断，退出码为 1；JSON 模式返回可识别错误码、flow、supportedFlow、状态路径、只读标记和升级提示，不输出“重跑原命令继续制作”等不安全建议。
- 所有会写影片或外部草稿的 CLI 路径在第一次副作用之前检查：signoff、qc、still、animatic、render、preview、clean、soundtrack、subtitles、final、audition、下载型 sfx，以及会写审阅报告的 delivery（含不带 --record 的形式）。
- brief/init 先解析实际目标片目录并检查已有 state；init-project 在 Git 初始化/忽略规则/提交前检查目标项目现有影片。新目录无状态时沿用现有行为。setup/check/list/new/help 不涉及已有影片状态，保持原入口。
- 兼容性预检早于 lockProduction 创建锁目录、active-command 记录、阶段账本、pending-approval、字体准备和渲染子进程。必要时取得既有制作锁后再次检查；不能为未来流程额外生成失败账本或报告。
- 共享 loadFilm、状态读写以及可直接调用的报告写入/阶段执行入口也使用同一无副作用检查，避免 CLI 与模块调用形成两套标准。内部纯工具函数不包裹成全局文件系统拦截器。
- 较新流程拒绝时，state、历史、签批、账本、缓存、素材、review、既有成片、外部剪映草稿及 Git 索引/提交树都保持原状；不存在的文件也不能新建。`--force` 不得绕过此保护。
- 只有不受支持的影片受阻；不要求整项目其他影片停工。init-project 为项目级写入，发现任何不兼容影片即停止该次初始化。

### 3.3 R6：剪映独立必跑任务

- 新增 `.github/workflows/jianying.yml`，稳定 job 名 `jianying`。对 push、pull_request、workflow_dispatch 均触发，不加仅修改某些路径才触发的过滤，不设 continue-on-error。
- 首批只承诺 Ubuntu 上的真实草稿生成与契约检查，使用固定 Node 20、Python 3.11、`pyJianYingDraft==0.3.1`；安装 ffmpeg、中文字体、Chromium 所需系统库及 MediaInfo 运行库。Python 在隔离环境中安装，确保被测试代码调用的 python3 指向该环境。
- Python 直接依赖版本集中在 `tests/requirements-jianying.txt`；本批不声称已锁定 Python 全部传递依赖。npm 依赖遵守 R4，浏览器缓存键包含现有 npm 锁摘要，Python 缓存键包含 requirements 摘要。
- 入口建议为 `npm run test:jianying`，启动前检查 Python 版本/pyJianYingDraft 精确版本、ffmpeg/ffprobe、browser 管线与浏览器可用性，失败即非零；真实导出测试继续验证系统库可用性。
- 必跑测试集合：`tests/integration/jianying.test.mjs`、`tests/integration/final-delivery.test.mjs`、`tests/unit/jianying-fonts.test.mjs`。基线为 19 个顶层用例，其中 15 个当前会因缺依赖跳过；不以固定“19”替代今后的实际测试发现。
- 测试运行器收集 Node 测试事件/结构化结果；任意失败、取消、skip、todo、指定测试文件缺失或无测试执行都令 job 失败。日志保存各文件和最终计数，失败时也上传诊断产物。不得仅凭 npm 命令退出 0 判断无跳过。
- 用独立运行器覆盖严格模式，保留普通本地 `npm test` 在确实缺少可选依赖时的明确跳过，避免让不导出剪映的用户被强制安装 Python 包。
- 必须覆盖真实短片/主副版草稿、107 镜切点连续、字幕原生版式、同名避让、用户修改保护及终版交付签批链；复用现有测试，不把真实导出改成 mock。
- workflow 以有限超时运行（建议 job 20 分钟，测试步骤 10 分钟）；不通过无限重试、缩短用例集合或放宽断言使任务变绿。
- “CI 必跑”指仓库 workflow 每次触发、严格执行且合并/发布验收必须看到成功。本轮不修改 GitHub 分支保护/Ruleset；若以后要由服务器禁止手工跳过合并，再独立确认管理配置，不能把 workflow 触发等同于已启用服务端强制规则。

## 4. 约束、兼容性与非目标

- 本批不改变画面、帧率、声音、字幕、主副版关系、15 道工序或 12 个审片节点。
- 测试只使用临时工程、临时用户目录与临时剪映草稿目录，不修改客户作品、已安装插件缓存或真实剪映草稿。
- 不升级现有 npm 依赖，不新增 Manim/Blender，不做第三批性能算法或核心整体重构。
- 本轮只编写待审阅规格与实施计划；实现、合并、发布和安装升级均不属于本轮执行范围。
- 不把 Linux 自动化草稿检查当作剪映桌面实际打开、字幕观感或所有宿主兼容的证明；既有 macOS 剪映 11.6 的人工验收边界继续保留。
- 依赖隔离会带来一次重装及额外磁盘占用；旧目录保留、不自动垃圾回收。此兼容代价需随规格一并批准。
- 较新流程保护不引入自动降级、用户文件修复或 `--force` 绕过；已知旧流程迁移规则保持原语义。

## 5. 错误处理与运维

依赖错误应区分源锁无效、清单不一致、npm 安装失败、浏览器安装失败、安装未完成与包加载失败；记录路径、阶段和可操作建议，保留实际子进程退出状态。安装命令不回显认证配置。失败只清理本次可确认的临时产物，其他身份及旧目录保留。

工程兼容性错误先于制作副作用返回，提示升级到支持该 flow 的插件；不能建议手动把 flow 改小、清空 .wka 或删除签批。status/resume 的只读提示不表示未来流程的产物已通过验收。

剪映 CI 依赖安装/预检失败与用例失败分别报告。可选的本地跳过不等于独立任务通过。临时作品不上传为正式交付物；CI 日志不包含用户真实工程。

## 6. 验收标准与测试

| 验收 | 场景 | 必须证明的结果 |
| --- | --- | --- |
| A1 / R4 | 干净复制插件后 setup；正常、缺失、损坏、不一致的锁文件 | 正常走 npm ci，复制的清单和锁字节未变；异常非零、不回退 npm install。至少一次真实网络/缓存安装核对实际包版本。 |
| A2 / R4 | 同引擎版本但锁不同；平台/架构/Node 主版本变化；同身份重跑 | 不同身份目录隔离，同身份有效安装复用；不覆盖旧版本。 |
| A3 / R4 | npm/Chromium 中断、未完成目录、同身份并发 setup | 不发布失败目录、不误报就绪；既有有效安装不变，重试可完成。 |
| A4 / R4 | 旧共享目录、开发目录、父级/global 的冲突包；选定根缺包或报错 | 两个解析 API 只使用同一验证根，不串包；check 给出准确修复建议。 |
| A5 / R4 | 原生复制安装和便携包实际 setup；仓库 npm run setup | 三种入口均使用相同锁版本；共享依赖不写插件缓存，开发测试继续可用；无需在每帧重查依赖。 |
| A6 / R5 | 缺 state、无 flow、flow 1–5、6/99、null/0/字符串/小数/损坏 JSON | 已知旧版按原规则迁移；较新版/非法版明确拒绝；输入对象与较新版文件字节不变。 |
| A7 / R5 | 混合版本项目 status；较新影片 resume 普通及 JSON | 兼容影片可见，较新影片只显示诊断，不解释步骤/签批；非零返回且该影片没有文件变化。 |
| A8 / R5 | 较新流程依次调用全部写入型 CLI，含 --force、brief/init、delivery、init-project | 在锁、账本、报告和制作前拒绝；文件集合/字节、外部草稿、Git 树与索引不变，未启动渲染/安装子进程。 |
| A9 / R5 | 直接调用状态迁移/写入、loadFilm、阶段执行及报告写入入口 | 使用统一规则，不能绕开 CLI 保护；正常 flow 5 签批/恢复行为不回退。 |
| A10 / R6 | 独立任务干净安装依赖并运行指定三文件 | 实际草稿导出成功，fail/cancel/skip/todo 全为 0；现有 15 个被跳过的用例真正执行。 |
| A11 / R6 | 移除 Python 包、错误版本、缺浏览器/ffmpeg；注入 skip/todo/空测试/失败 | 严格入口与 job 均非零，不能显示通过；普通本地 npm test 仍保留可选跳过。 |

实现时先运行定向失败回归，确认失败源自上述边界，再最小实现。模块测试使用故障注入与临时目录，至少一次真实 npm ci 和真实剪映导出作为集成证据，不能以源码字符串包含某个命令替代行为验证。

## 7. 设计取舍与审阅重点

1. 选择按锁身份新建依赖目录，代价是升级后一次 setup 和保留旧目录的磁盘占用；优于在仍可能被旧插件使用的目录里直接 npm ci。
2. 选择较新流程只读诊断、写入前拒绝，保留旧版迁移；不尝试猜测未来流程语义。
3. 选择独立严格剪映任务，同时保留普通本地可选依赖；增加一组 CI 时间，但让跳过不能冒充导出验证。

这三项方案、兼容代价、验收边界随本文一起待用户批准；没有需要先向用户索取才能完成草案的信息。

依据：仓库源码见第 1–3 节；npm ci 要求已有锁文件、不一致时报错且不改写锁文件，见 [npm 官方说明](https://docs.npmjs.com/cli/v11/commands/npm-ci/)。具体 npm/Node 测试接口兼容性须在实施时以项目 Node 20 环境验证，本文不指定未经验证的新版 API。
