## 实现与兼容边界

### Q1：命令生命周期

先以独立提交 `f5f8534` 修正 `fail → process.exit(1)` 绕过 `finally` 的问题，再建立可独立调用的 `runCli(argv, { log, error })`。执行器按唯一命令目录执行预检、取锁、登记、等待处理器与清理，最终返回 0/1/2；五行进程入口只等待结果并设置退出码。

22 个命令按环境、工程、审阅、媒体、音频、字幕与终版六组搬移。调用参数和日志函数按次传递；导入和连续调用不改 `process.argv/cwd/exitCode`。保持原锁范围，包括 `delivery` 仅在 `--final --record` 时取锁、其他只读路径不取锁，内部终版步骤不重复进入外层锁。锁获取失败不删除其他 owner 的锁；输出回调抛错同样经过清理。保留 active-command 和用户工程，不新增信号处理规则。

[独立基线夹具](../../../tests/fixtures/cli-v0.19.4.json) 保存 22 个命令策略、23 个真实 CLI 输出和四个旧模块导出列表，取自基线而非候选。18 个搬移辅助函数的 AST 已与基线对照，仅归一化必要的相对导入路径。

### Q2：核心依赖与实现身份

提取 `film-context`、`delivery-inputs`、`qc-config`、`command-args`，保留 `job.loadFilm`、`qc.qcConfig`、`delivery` 公开导出及旧 `bin/args.parseArgs`。六个提取的公开函数与基线 AST 一致；不重排原校验和业务逻辑。

基线的 `job/final-delivery/delivery/qc` 四模块循环、`core/delivery → bin/args` 反向依赖已消除。完整 Git 跟踪模块图从 60 个模块变为 76 个，候选零循环、零层次违规。

移动的实现纳入现有取证范围：全引擎身份自动覆盖新模块，最终交付 renderer/encoding/subtitle 投影补入 `film-context`；QC 生产者与最终交付校验者共用 `qc-source`，按相同顺序计算 `qc.mjs/qc-config.mjs/qc-source.mjs` 身份，每次仍读取实际来源。隔离副本测试证明修改新模块会使旧证据失效，账本和历史签批字节保持，新版本内未变化的输入可以复用。

升级后的旧缓存或批准可能按既有规则需要重新核实，这是实现身份变化的预期影响；没有伪造通过或改写历史。引擎依赖清单、运行时锁文件、FLOW/TIMING_VERSION、证据 schema 和插件版本均未改。

### Q3：持续结构检查

根开发依赖精确锁定 Acorn 8.19.0，新增根锁文件；引擎运行时不增加依赖。AST 检查覆盖静态 import、re-export 和字符串字面量动态 import，拒绝空扫描、解析失败、缺失或遗漏目标、循环、反向及传递越层依赖。

两处已有非字面量动态入口仅按文件、函数与表达式形状允许：registry 扩展插槽与 soundtrack 用户脚本。它们不是引擎静态图的一部分，也不代表任意用户脚本已被证明无环。CLI 的直接退出和导入时启动检查结合真实导入测试使用，不宣称静态分析能证明所有副作用不存在。

`npm run lint` 保留原检查并追加架构检查。lint、smoke 和 agent-installation 工作流安装根锁定依赖；三平台 Node 20 安装流程追加命令生命周期、契约及模块边界测试，原安装、文件 I/O 与严格剪映任务保留。远端执行结果仍待 PR 阶段确认。

### 一处原始工作量差异与补测

原工具的 single 场景只追加注释，画面不变。Remotion 重渲出的 segment 内容若与该版本的暖快照相同，既有 `preview`/`runStage` 按实际内容摘要复用已封装小样；否则重新封装。这两处算法及 Remotion 管线在本批没有改动。

原 Remotion 单镜 preview 的正式五轮中，基线封装次数为 `0/0/0/1/0`，候选为 `1/1/1/1/0`；两版都出现过复用与重新封装。独立探针基线 ffmpeg/ffprobe 为 `6/2`，候选为 `7/3`，多出一次音视频封装及其时间轴校验；两边始终只重渲一个镜头。不能把这一对原始探针描述成完全相同工作量，也不凭它断言具体浏览器/编码器的字节波动原因。

为排除该差异，另在相同隔离副本中把首镜标题改成同一个可见文字，要求每轮实际视频字节变化。追加 5 轮交替配对及双方各 1 次探针，单独保存，不替换原始样本：每轮均重渲 1 镜、重新封装 1 个小样、复用其余 3 个；逐个视频流结构与原输出一致，未改镜头的成品摘要保持。两引擎使用同一修改后脚本摘要，探针子进程计数一致。

补测基线中位数 **13.004 秒**，候选 **12.402 秒**，增量 -602.50ms，门槛 1300.43ms，通过。五轮范围分别为 11.855–14.098 秒、12.201–12.857 秒；探针均为 ffmpeg 7 次、ffprobe 3 次，另有 esbuild 和 Chromium 各 1 次。追加共 10 次计时、2 次探针，全部成功；它用于解释工作量差异，不扩充原定 21 场景的通过数量，也不覆盖原始较慢样本。
