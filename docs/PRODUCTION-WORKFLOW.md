## 角色

| 角色 | 由谁担任 | 职责 |
|---|---|---|
| 导演 | Claude（`director` skill） | 按本流程执行各道工序；提交审阅前先做内部预审 |
| 客户 | 用户 | 在每个审片节点审阅交付物，签批或提出返修意见 |
| 项目负责人 | 插件维护者 | 决定流程本身的变更（新增 / 调整工序与审片节点） |

客户和项目负责人可以是同一个人：审片时是客户，改流程时是项目负责人。

## 提交审阅

客户可能是第一次做动画：说话用大白话，术语第一次出现时用一句话解释（见文末「术语解释」）。每个审片节点按固定三步提交：

1. **交付物**：弹签批卡片之前，先把要签批的文件逐个列出，每个文件一行可点击的 Markdown 链接——链接文字是完整绝对路径，链接地址是相对当前工作目录的路径（文件不在当前工作目录下时也用绝对路径），客户点一下就能打开观看，例如 `- [/Users/me/动画/films/寒江/review/小样.mp4](films/寒江/review/小样.mp4)`；不加目录或播放命令；文本类（文学脚本、分镜、字幕）另贴原文。音视频和图片类审阅文件都在片目录的 `review/` 里：声轨、试听、接触表、动态分镜、小样、字幕预览。
2. **审什么**：一两句话说这是什么、请客户看哪几点。
3. **签批卡片**：问「可以签批吗？」，选项「签批」和「要返修」。没交付物不弹卡片；文字里不写「在下方 / 框里选」这类指向界面的话。

## 流程总览：14 道工序 · 11 个审片节点

每到 ✅ 审片节点，必须暂停，待客户明确签批（sign-off）后再执行 `wka signoff <片目录> "<审片结论>" --step N`：进度写入 `.wka/state.json`，同时以 git 提交做一次版本存档（定版快照）。**11 个节点没有自动通过的例外。**

**用客户的语言说话**：导演全程用客户的语言（客户说中文就用中文），包括工序之间的进度说明、自查说明和交付后的小结；命令、文件名、字段名保持原样。

**与客户交互：选择卡片**。第 2 道制作简报用文字追问（见第 2 道细则），其余要客户做选择的地方，导演用选择卡片（Claude Code / Cowork 的 `AskUserQuestion`）让客户点选，文字只做补充说明；没有卡片的环境退回文字，把同样的选项编号列出。

| 环节 | 卡片 |
|---|---|
| 第 1 道 | 恢复哪支在制的片子，还是新建 |
| 第 3 道 | 3 套视觉方案单选，另有「换一批」；选定即签批 ② |
| 第 6 道 | 自供录音 / AI 配音 / 本片不用人声；选 AI 配音的，试听后再用一张卡片选音色，选定即签批 ⑤ |
| 其余审片节点 | 先交付物，再问「签批 / 要返修」；要返修时多选「要改哪些方面」，细节可以手填 |

卡片的选项与写法见 `plugin/skills/director/SKILL.md`「与用户交互：选择卡片」。

| 12 | 终版渲染与终混（Final Render & Mix） | • `wka final` 依次执行：<br>&emsp;1. 终混（刷新人声同步点）<br>&emsp;2. 全分辨率终版渲染（未改动的镜头直接读缓存）<br>&emsp;3. 按 `subtitles.mode` 烧录字幕（只烧进成片画面，不影响镜头缓存）<br>&emsp;4. 按 `export.formats` 编码输出，文件名标明有没有字幕（`<name>_有字幕` / `<name>_无字幕`）；外挂字幕复制为 `<name>_字幕.srt`<br>• `export.formats` 不放 `jianying`，剪映草稿留到第 14 道 | 终审送审版成片（vN），外挂字幕 `<name>_字幕.srt` | — |
| 13 | 终检与交付（Final QC & Delivery） | • `wka qc` 对终版做 QC 终检（检测不带字幕的画面），抽看成片确认字幕正常，通过后把成片发给客户终审<br>• 第一次提交为 v1，每因返修重新提交一次加 1<br>• 有意见按「返修流程」改完重新提交；签批即定版 | 成片 vN 定版 | ✅ ⑩ 终审 `--step 13` |
| 14 | 剪映草稿交付 | • 不管简报怎么选，先问客户要不要导出剪映草稿<br>• 客户不需要草稿：签批，全片结束<br>• 客户需要草稿：<br>&emsp;◦ `wka check` 确认 pyJianYingDraft 已装、剪映草稿目录存在<br>&emsp;◦ 请客户完全退出剪映（剪映开着会拒绝导出）<br>&emsp;◦ `wka final --formats jianying` 导出（镜头读缓存；同名草稿已存在时自动导出为 `<片名>_v2`……）<br>&emsp;◦ 按清单自查镜头、各条音轨和字幕（有 `subtitles.srt` 就按它出字幕；字幕样式由导出器写入，不再跑片目录里的样式补丁），再请客户在剪映里打开<br>&emsp;◦ 告知客户：响度统一和淡出要在剪映里做；重导会生成新的一份，旧草稿还在 | 剪映草稿（写在剪映草稿目录，不进 git） | ✅ ⑪ 剪映草稿 `--step 14` |

## 工序细则

### 第 1 道工序：制作环境、工程初始化、恢复在制项目

- `wka check`：检查 Node、ffmpeg、Chromium、git、字体工具、TTS 和 pyJianYingDraft（可选，第 14 道导出剪映草稿用）。只有必需项（ffmpeg、渲染管线）缺失时结论才不是「一切就绪」，这时运行 `/wukong-animation:setup` 再继续；推荐项和可选项缺失不拦着往下做，告诉客户影响即可。
- `wka init-project`：工程目录未纳入版本管理时执行 `git init`，写入 `.gitignore` 并做初始存档。
- `wka status`：如有在制项目，向客户汇报"已推进到第 N 道工序，下一步是……"，确认恢复在制项目还是新建项目。

### 第 2 道工序：制作简报确认

导演用文字**追问**客户，确认简报各项，不用选择卡片。追问规则：

- **决策树**：把简报各项看成一棵决策树，每个决定会引出依赖它的决定（比如定了有人声，才问字幕方式）。
- **分轮问前沿**：前沿是前置决定都已定下、不用猜答案就能问的全部问题。每轮把前沿一次问完，然后等客户回答。
- **格式**：每题编号，写标题和问题（可含选项），下一行写推荐答案；措辞让客户答「是」即采纳推荐。
- **重算前沿**：客户的回答会让前沿往外推，据此问下一轮；依赖本轮未答问题的题，留到下一轮再问。
- **事实自己查**：可用风格、TTS 装没装这类事实，导演自己查，不问客户；决定交给客户。
- **问到没有遗漏**：决策树每个分支都走到、没有默默假定的项，追问才结束。**客户确认达成共识之前，不写简报。**

第一轮就问片名（导演按故事拟一个工作片名作推荐答案），片名定下即 `wka brief <片名>` 建占位片目录 `films/<片名>/` 和简报空白稿 `brief.md`。客户已经说清的项不再问。以客户的选择为准：选了故事里还没有的人声（比如选了对白，故事里却没有说话的角色），简报里说明第 4 道会补出说话的角色和人声文案。

**简报各项怎么填**：见 [`plugin/skills/director/specs/BRIEF.md`](../plugin/skills/director/specs/BRIEF.md)，包括各项的推荐答案（即默认规格）、「（推断）」标注、字幕方式与交付形式的取值。模板 `plugin/engine/templates/brief.md`。

**签批 ①**：写好 `brief.md` 后按审片节点三步提交（可点击路径 + 原文 → 审什么 → 签批卡片），签批后 `wka signoff films/<片名> "<结论>" --step 2`。要返修时可选的方面：目的与受众 / 内容与基调 / 制作规格 / 交付。第 3 道起各工序以签批过的 `brief.md` 为制作规格的依据。

### 第 4 道工序：文学脚本撰写

**怎么写**：见 [`plugin/skills/director/specs/STORY.md`](../plugin/skills/director/specs/STORY.md)：文学脚本是什么、不是什么，输入，逐部分写法，示例，签批前自查清单。

**产出**：`films/<片名>/story.md`。`wka init` 建工程时已经从模板 `plugin/engine/templates/film/story.md` 带出空白稿，在上面填写。

提交前导演按 `STORY.md` 的自查清单过一遍。

**提交客户审阅**：把 `story.md` 的**完整原文**贴给客户（不只给摘要），就四点征询意见：

- 影片基调是否准确？
- 段落节奏是否合适？
- 哪些文案（人声和屏幕文字）需要修改？
- 人声时长（字数）是否合适？提交时附上每段的字数与估算时长（中文语速约每秒 3.6 字），例如"承段人声 14 字，约 3.9 秒，段长 4 秒"。

**返修**：客户提出意见后在原文件上修改，文学脚本版本号加 1（v1 → v2……），重新提交审片节点③。签批时把结论写进 `wka signoff`，例如：

```bash
wka signoff films/寒江 "文学脚本 v2 签批：去掉 VO，改为古琴 + 流水" --step 4
```

签批后的文学脚本即定稿。之后再改（例如第 7 道发现人声太长），要回到本工序改 `story.md`、版本号加 1，再重新提交审片节点③。

### 第 5 道工序：分镜脚本

按 [`plugin/skills/director/specs/STORYBOARD.md`](../plugin/skills/director/specs/STORYBOARD.md) 写：表头、逐镜各栏、声音铺底，以及取决于风格的栏到 `STYLE.md` 哪一节查。模板 `plugin/engine/templates/film/storyboard.md`。`storyboard.md` 给客户审阅，`film.json` 给引擎渲染，两者逐镜对应。

### 第 6 道工序：人声素材来源

无论文学脚本有没有人声，这一节点都要停下来等客户签批：

| 情况 | 执行方式 |
|---|---|
| 客户自供录音 | 客户将录制好的人声（wav / mp3 / m4a，可按条分轨，也可整段单轨）放入素材目录 `films/<片名>/audio/voice/`，在 `voices[].file` 中逐条挂接；`"voice_source": "user"` |
| AI 配音 | 调用已安装的 TTS 引擎（edge-tts / kokoro）合成；未安装时先告知客户，可装好后再合成，也可先按字数预估时长、继续推进画面；`"voice_source": "ai"`。选定前先用 `wka audition` 把文案第一句用 2–3 个音色各合成一遍，交客户试听、用卡片选定；要慢读、低沉时调 `voices[].rate` / `pitch` 再试听。edge-tts 没有老年音色，不要硬压音高去做；内置音色不够时，客户可从剪映文本朗读、云配音平台、开源配音模型或真人录音拿音频，按自供录音接入同期声（`kind: live`）是现场原声，AI 配不出来，这类条目仍要客户提供录音并挂接 `file`，其余条目才由 AI 合成 |
| 文学脚本标注"无人声" | 请客户确认"本片不用人声"，确认后记 `"voice_source": "none"`；客户改主意要加人声时，退回第 4 道补写人声文案 |

### 第 7 道工序：声轨制作

- 配乐（Score）由 `audio/build.mjs` 程序化合成（古琴拨弦、流水、打击乐、混响），关键音效的时间点写进 `cues`。配乐、环境声、音效各写一个文件（`bgm.wav` / `ambience.wav` / `sfx.wav`），导出剪映草稿时各占一条轨。
- 人声逐条写 `voices[].kind`（`vo` 默认 / `dialogue` / `os` / `live`）与 `speaker`；同期声（`live`）只能用现场录音，必须挂接 `file`。
- `wka soundtrack` 不要求镜头文件已写好（镜头在第 8 道才画），接入客户录音或合成 AI 配音，实测每条人声的入出点写入 `cues`；超出镜头时长或相互重叠的人声条目会被标记，据此回调镜头时长。客户录音与文学脚本篇幅出入较大时，向客户说明并以实际录音为准。
- 把审听副本 `films/<片名>/review/声轨.m4a`（`wka soundtrack` 从 `mix.wav` 转出的 AAC，体积约为 WAV 的 1/8，聊天里播放不卡）交客户审听：人声效果、配乐、音效、整体节奏。`.cache/mix.wav` 在隐藏目录里，不交给客户。
- **没有任何声轨**（无人声、无配乐、无音效）时，`wka soundtrack` 不生成 `mix.wav`。这时也要停下请客户确认"本片无声"，签批后继续；第 8 道的动态分镜随之无声，只审画面节奏。
- 此后镜头代码一律通过 `s.cueIn('名')` 读取同步点，不写死时间码。

### 第 8 道工序：风格帧与动态分镜

- 每镜以最少代码出关键帧，`wka animatic <片目录>` 生成接触表（contact sheet）`review/接触表.jpg` 和动态分镜 `review/动态分镜.mp4`：每镜关键帧按镜头时长停留，配上第 7 道的声轨。
- 先做内部预审：每镜至少有主体和环境两个层次（前景 / 中景 / 远景至少两层），主体之外有陪衬；风格的留白下限、点缀色上限是边界，不是要贴着的目标，画面发空要加层次；景别与分镜一致。
- 再提交客户审阅：接触表看构图与视觉效果，动态分镜看节奏与声画对位。

### 第 9 道工序：镜头制作

在第 8 道写下的镜头代码上继续完成：`render(ctx, t, s)` 必须是关于时间 `t` 的纯函数，保证任意帧可确定性重渲；尺寸一律乘以单位系数 `s.u`；随机数使用固定种子；优先调用风格资产库的现成组件。屏幕文字和某条人声说的是同一句话时（如题字跟着旁白），从这条人声的入点开始、逐字对到人声里念到这个字的时刻，不用固定字速：给这条人声设 `"chars": true`，`wka soundtrack` 写出逐字同步点，镜头里用 `s.cueChars('名')` 取，做法见 `plugin/skills/director/specs/SHOT.md`「屏幕文字与人声对位」。

### 第 10 道工序：小样渲染与技术质检

- `wka render <片目录> --proxy` 渲染小样（半分辨率、半帧率），同时合成带声音的 `review/小样.mp4` 交客户审阅。
- `wka qc <片目录> --proxy` 逐帧检测留白比例、点缀色占比、帧间差异、黑帧 / 空帧、非预期硬切（跳切），阈值取自风格规格书 `style.json`，超标帧拼成接触表。
- `wka still <片目录> --frames 4 --proxy` 每镜抽 4 帧，按 `STYLE.md` 的美术检查清单逐项核对。
- 仅对问题镜头返修：`wka render <片目录> --proxy --only s03`。

### 第 11 道工序：字幕制作

**字幕是什么**：把人声逐句转成文字、跟着人声的时间显示，不属于画面设计，和屏幕文字（第 4 道）是两回事。字幕的文字只来自人声原文 `voices[].text`，时间来自第 7 道 `wka soundtrack` 实测的同步点。

**为什么放在这里**：⑧ 小样签批后，文字、时间、画面构图都已定下，字幕的断句和位置不会再被画面返修打乱；放在终版渲染之前，烧录字幕才能随终版一起出。

**本片不出字幕**（`subtitles.mode` 为 `none`，或没有 `subtitles` 字段）：也要停下请客户确认"本片不出字幕"，签批后继续：

```bash
wka signoff films/寒江 "本片无人声，不出字幕" --step 11
```

**生成**：`film.json` 写好 `subtitles`（取值见 [`director/specs/BRIEF.md`](../plugin/skills/director/specs/BRIEF.md) 字幕方式），然后 `wka subtitles <片目录>`：

| 规则 | 说明 |
|---|---|
| 一条人声不超过 `max_chars` 字 | 就是一条字幕，时间等于这条人声的入出点 |
| 超过 `max_chars` 字 | 先在句内标点（。！？；，、：）处切开、从左到右合并到不超过 `max_chars`；仍超长的按字数硬切；各段按字数比例分配这条人声的时长 |
| 结尾标点 | 去掉 。，、；：，保留 ？！… |
| `max_chars` 缺省 | 横屏 18、竖屏 12、方形 14（标点不计） |

生成后会检查：出点早于入点、超出片长是错误，必须改；相邻重叠、单行超长、短于 0.6 秒是警告，看情况改。断句不满意就直接编辑 `subtitles.srt`。`subtitles.srt` 已存在时，`wka subtitles` 只检查不覆盖，免得冲掉手改；声音返修后要重新生成，加 `--force`（会覆盖手改）。

**预览**：`wka subtitles <片目录> --preview` 把字幕烧录到小样上，输出 `review/字幕预览.mp4`（不管字幕方式是外挂还是烧录，审阅都看这一版）。烧录样式取风格 `style.json` 的 `subtitles` 块，缺省为 Noto Sans SC、白字黑描边、文字底边离画面底边 8%；这支片要换样式就写 `film.json` 的 `subtitles.style`（字段相同，逐项覆盖），不改插件目录里的文件。

**提交客户审阅**：把 `subtitles.srt` 原文和带字幕的小样一起交客户，就四点征询意见：

- 有没有错字？
- 断句是否自然？
- 出入时间是否跟得上人声？
- 位置是否压住了屏幕文字（题字、落款等）？

**签批前自查**：

- [ ] `wka subtitles` 没有错误，警告都看过
- [ ] 字幕文字与第 7 道定稿的人声原文一致
- [ ] 预览里字幕没有压住屏幕文字
- [ ] 字体和风格搭配（国风、手绘类风格不用缺省黑体，从 `engine/core/fonts.mjs` 的 `KNOWN_FONTS` 选开源字体）
- [ ] 字幕在安全框内：整体在画面中间 90% 的范围里，文字底边离画面底边不少于画高 5%

```bash
wka signoff films/寒江 "字幕 v1 签批：外挂 srt" --step 11
```

### 第 12–13 道工序：终版渲染、终检与交付

- `wka final <片目录>` 依次执行混音、终版渲染、烧录字幕（`subtitles.mode` 为 `burn` / `both` 时）、编码输出；未改动的镜头直接读缓存，字幕不进镜头缓存，改字幕不用重渲镜头。成片文件名标明有没有字幕：

| `subtitles.mode` | 成片 | 外挂字幕 |
|---|---|---|
| `none` | `<name>.mp4` | — |
| `burn` | `<name>_有字幕.mp4` | — |
| `srt` | `<name>_无字幕.mp4` | `<name>_字幕.srt` |
| `both` | `<name>_有字幕.mp4` + `<name>_无字幕.mp4` | `<name>_字幕.srt` |

`film.json` 的 `export.formats` 不放 `jianying`，剪映草稿等 ⑩ 定版后在第 14 道导出。
- `wka qc <片目录>` 做 QC 终检（检测的是不带字幕的画面），再抽看成片确认字幕正常，通过后把成片交客户终审（`wka final` 日志里列出的文件逐个给可点击路径，`both` 时两个版本都交）。
- **版本号**：第一次提交终审为 v1，每因返修重新提交一次加 1（v2、v3……）。签批后 `wka signoff <片目录> "成片 vN 终审通过" --step 13`，这一版即定版；有返修意见则按「返修流程」修改后，以下一个版本号重新提交终审。

### 第 14 道工序：剪映草稿交付

**为什么放在终审之后**：剪映草稿写在剪映自己的草稿目录里，不在片目录，git 定版快照管不到；客户在剪映里做的改动，wka 也管不到。等成片在 ⑩ 定版后再出草稿，就不会出现"客户已经在剪映里改了，成片又返修重导"的冲突。

**先问再导**：不管第 2 道选了什么，成片定版后都先用选择卡片问客户「要不要导出剪映草稿？」（简报选了要的，「导出」标推荐；否则「不需要」标推荐），客户确认要才导出。剪映草稿会写进客户自己的剪映草稿目录，要在动手前确认。

**客户不需要剪映草稿**：签批后全片完成：

```bash
wka signoff films/寒江 "不需要剪映草稿，成片 v2 交付完成" --step 14
```

**导出**：

1. `wka check` 确认 pyJianYingDraft 已安装（`pip install pyJianYingDraft==0.3.1`）、剪映草稿目录存在；草稿目录不在默认位置（`~/Movies/JianyingPro/User Data/Projects/com.lveditor.draft`）时，在剪映「全局设置 → 草稿位置」查到实际路径，设置环境变量 `WKA_JIANYING_DRAFTS`。
2. 请客户完全退出剪映（⌘Q）。剪映退出时会把内存里的旧草稿写回草稿目录，覆盖新导出的内容；引擎检测到剪映在运行（macOS 进程 `VideoFusion-macOS`）会拒绝导出。
3. `wka final <片目录> --formats jianying`：镜头全部读缓存，只导出剪映草稿，草稿名取片名。不能加 `--proxy`。剪映里已有同名草稿时自动导出为 `<片名>_v2`、`_v3`……旧草稿不动，日志里会说明新名字。

**草稿里有什么**：

| 轨道 | 内容 |
|---|---|
| 视频 | 每镜一段，镜头名即镜号 |
| 人声 | 放在「人声」轨，互相重叠的分到「人声 2」…… |
| 配乐 / 环境声 / 音效 | 按 `audio/build.mjs` 写出的文件各占一条轨，只保留有声音的片段 |
| 字幕 | 有 `subtitles.srt`（字幕方式不是 `none`）就按它，一条字幕一段；否则每条人声一条字幕，没有人声音频的条目时长为估算值，导出日志会列出。重叠的分到「字幕 2」…… |

**提交前自查**：

- [ ] 剪映里能看到草稿（看不到就重启剪映）
- [ ] 镜头数、时长与成片一致
- [ ] 配乐、环境声、音效、人声各在自己的轨上
- [ ] 日志里标了"时长为估算值"的字幕逐条核对过
- [ ] 读 `draft_content.json` 确认字幕的字体、颜色、描边已由导出器写入（不再跑片目录里的样式补丁）

**提交客户审阅**：告诉客户草稿名，请客户在剪映里打开查看，同时说明两件事：

- 草稿没做响度统一和结尾淡出，需要在剪映里用「响度统一」和淡出处理；
- 在剪映里的改动 wka 管不到。之后如果成片返修、要重导草稿，会生成新的一份（`_v2`、`_v3`……），旧草稿和客户在里面的改动都还在，不要的可以在剪映里删掉。

签批：

```bash
wka signoff films/寒江 "剪映草稿已交付，客户确认可在剪映里打开" --step 14
```

## 返修流程（Revision Loop）

| 返修类型 | 触发 | 执行 |
|---|---|---|
| 节点内返修（流程图 `↺`） | 任一审片节点未通过 | 留在本工序修改，改完重新提交同一节点 |
| 画面返修（内侧回路 9 ◄ 10 / 13） | ⑧ 小样或 ⑩ 终审提出画面意见 | 回到第 9 道修改 `shots/sNN.js` → 局部重渲（小样阶段 `wka render <片目录> --proxy --only sNN`，终审阶段 `wka final <片目录> --only sNN`）→ `wka qc` → 重新提交原节点 |
| 声音返修（外侧回路 7 ◄ 13） | ⑩ 终审（或 ⑧ 小样、⑨ 字幕）提出人声 / 配乐意见，或客户后期补录人声 | 回到第 7 道修改人声（`voice_source`、`voices[].file`）或 `audio/build.mjs` → `wka soundtrack` 刷新同步点 → 重新提交 ⑥ 声轨审听 → 有字幕的片子回到第 11 道 `wka subtitles --force` 重新生成、重新提交 ⑨ 字幕 → `wka final`，按同步点驱动的画面自动重新对位 → 重新提交原节点 |
| 字幕返修（11 ↺，或 11 ◄ 13） | ⑩ 终审提出字幕意见（错字、断句、位置），或已过 ⑧ 的片子要补字幕 | 回到第 11 道：改 `subtitles.srt`（补字幕时先在 `film.json` 加 `subtitles`、`wka subtitles` 生成）→ `wka subtitles --preview` → 重新提交 ⑨ 字幕 → `wka final`（镜头读缓存，只重新烧录）→ 以下一个版本号重新提交 ⑩ 终审 |
| 草稿返修（14 ↺，或 13 ◄ 14） | ⑪ 剪映草稿提出意见 | 草稿本身的问题（缺轨、字幕时长不对）：请客户退出剪映 → `wka final <片目录> --formats jianying` 重导（自动起新名字） → 重新提交 ⑪。成片内容的问题（画面、声音、字幕）：按画面返修、声音返修或字幕返修改完，以下一个版本号重新提交 ⑩ 终审，签批后回到第 14 道重导草稿 |

返修出问题时，可用 `git checkout` 回滚到任一审片节点的定版快照。

## 术语解释

| 术语 | 解释 | 本流程中 |
|---|---|---|
| 审片节点 / 签批（Sign-off） | 制作推进到关键环节时，把阶段成果提交给客户审阅，客户明确认可（签批）后才进入下一环节；签批后的内容视为定稿，后续改动按返修处理 | 11 个 ✅ 节点，签批后执行 `wka signoff` |
| 内部预审 | 提交客户之前，由导演先自查一遍，明显问题先改掉 | 第 8 道风格帧与动态分镜 |
| 定版快照 | 签批时对工程文件做一次版本存档，返修出问题时可回滚到这个状态 | 每个审片节点自动做一次 git 提交 |
| 制作简报（Brief） | 立项时确认的制作要求清单，通常包括内容、片长、画幅、声音、交付形式等基本规格，是后续所有工序的依据 | 第 2 道追问确认，写成 `brief.md`，审片节点 ① |
| 交付形式 | 成片交给客户的形态：只交成片文件，或同时交可继续编辑的工程（如剪映草稿） | 第 2 道确认，第 14 道执行 |
| 美术定调（Look Development） | 在正式制作前确定影片的整体视觉风格，包括画风、色彩、质感和运动语言 | 第 3 道工序，从风格库选定一种风格 |
| 文学脚本（Script） | 短片的文字底稿，包含主题、基调、情节梗概、段落结构、人声文案和屏幕文字；只写给人看，不含代码。动画行业里先有文学脚本，再按它画分镜脚本；长片一般称"剧本" | 第 4 道工序，产出 `story.md` |
| Logline | 用一句话概括影片讲什么，用于快速对齐主题 | 文学脚本的第一部分 |
| 分镜脚本（Storyboard） | 把文学脚本拆成一个个镜头，逐镜写明段落、时长、景别、画面、运镜、声音、屏幕文字和转场，是画面制作的施工图 | 第 5 道工序，产出 `storyboard.md` + `film.json` |
| 景别（Shot Size） | 镜头画面框取范围的大小，从大到小依次为远景、全景、中景、近景、特写；景别交替决定画面的视觉节奏 | 分镜表的一栏 |
| 运镜 / 动态 | 镜头中的运动设计：镜头本身怎么移动，画面里什么在动、怎么动、快慢如何 | 分镜表的一栏 |
| 停顿（Hold） | 动作完成后让画面停留一段时间，给观众留出看清和回味的余地 | 每镜动作完成后至少停 1 秒 |
| 转场（Transition） | 镜头与镜头之间的衔接方式，如连续、溶解、遮挡过渡、硬切 | 分镜表的一栏 |
| 硬切 / 跳切（Cut / Jump Cut） | 硬切指上一镜直接切到下一镜，不做过渡；跳切指同一画面中出现不连贯的跳跃。非预期的硬切或跳切会破坏流畅感 | 第 10 道工序由 QC 自动检测 |
| 人声（Voice） | 片中所有说话的声音：画外音、对白、同期声等 | 第 6 道工序确定素材来源；写入 `film.json` 的 `audio.voices` |
| 屏幕文字（On-screen Text） | 作为画面设计的一部分出现在画面里的文字，如片名卡、题诗、落款、印章、片尾 Logo；由镜头代码画出，成片里看得到。**不包含字幕** | 第 4 道写原文，第 5 道落到具体镜头，第 8–9 道画出 |
| 字幕（Subtitles） | 把人声逐句转成文字、跟着人声的时间显示的文字条，不属于画面设计 | 不算屏幕文字；第 11 道工序由 `wka subtitles` 生成 `subtitles.srt`，第 12 道按字幕方式烧录或外挂，第 14 道剪映草稿也读它 |
| 外挂字幕 / 烧录字幕 | 外挂字幕是和视频分开的字幕文件（如 srt），播放器按需显示；烧录字幕是把字直接画进视频画面，任何播放器都看得到，但关不掉 | 第 2 道确认字幕方式（`subtitles.mode`） |
| srt | 最常用的外挂字幕格式：纯文本，每条字幕写序号、入出时间和文字 | `subtitles.srt`，可以直接手改断句 |
| 画外音（VO, Voice-over） | 人声的一种：不出现在画面中的说话声音，如旁白、解说、内心独白 | 分镜「人声」栏的默认类型，`kind: "vo"` |
| AI 配音（TTS） | 由文字转语音（Text-to-Speech）引擎合成的配音 | 第 6 道工序的方案之一 |
| 声音先行（Pre-scoring） | 先确定配音和配乐，再按声音的节奏制作画面，常见于动画和 MV | 第 6–7 道工序排在画面制作之前 |
| 声轨审听（Audio Review） | 在画面制作前，单独审听混好的整条声轨（配音、配乐、音效），确认声音效果和节奏 | 第 7 道工序，⑥ 声轨审听 |
| 配乐（Score） | 为影片专门创作的背景音乐 | 由 `audio/build.mjs` 用代码合成 |
| 声音同步点（Cue） | 声轨上需要和画面对齐的时间点，例如某句人声的开始、某个音效的落点 | 写入 `film.json` 的 `cues`，镜头代码用 `s.cueIn()` 读取 |
| 入出点（In / Out Point） | 一段素材在时间线上开始和结束的时刻 | `wka soundtrack` 实测每条人声的入出点 |
| 风格帧（Style Frames） | 正式制作前，每个镜头先出一张代表性的静帧，用来确认构图和视觉效果 | 第 8 道工序 |
| 接触表（Contact Sheet） | 把多张静帧缩小后排在一张图上，便于一眼对比、整体审阅 | `wka animatic` / `wka still` 生成，风格帧和 QC 都用 |
| 动态分镜（Animatic） | 把分镜画面按镜头时长排好、配上声轨，做成可播放的粗片，用来在正式制作前审节奏和声画对位 | 第 8 道工序，`wka animatic` 输出 `review/动态分镜.mp4` |
| 小样 / 代理渲染（Proxy） | 用降低的分辨率和帧率快速渲染一版完整影片，用于审节奏和动作，节省时间 | 第 10 道工序，半分辨率、半帧率；审阅看带声音的 `review/小样.mp4` |
| 技术质检（QC, Quality Control） | 交付前对画面做的技术检查，包括量化指标检测和人工目视检查 | 第 10、13 道工序 |
| 终版渲染与终混（Final Render & Mix） | 用最终规格渲染全部画面，并把配音、配乐、音效混合成最终声轨 | 第 12 道工序，`wka final` |
| 终检与交付（Final QC & Delivery） | 对成片做最后一次质检，确认无误后交给客户终审 | 第 13 道工序 |
| 终审（Final Approval） | 客户对终版成片的最后一次审阅，签批后影片定版，不再修改 | 第 13 道工序，⑩ 终审 |
| 版本号（vN） | 成片每提交一次终审编一个版本号，便于追溯哪一版被签批 | 第一次终审为 v1，每返修重提加 1 |
| 返修流程（Revision Loop） | 根据审片意见修改、重新渲染、再次提交审阅的循环 | 节点内返修、画面返修、声音返修、字幕返修、草稿返修五类 |
| 剪映草稿 | 剪映专业版的工程文件：打开后时间线上是分好轨的视频、音频和字幕，可以接着剪 | 第 14 道工序，`wka final --formats jianying` 写进剪映草稿目录 |
| 安全框（Safe Area） | 画面中保证在各种屏幕和裁切下都能完整显示的区域，重要内容要放在框内 | 待议提案「多画幅同步交付」 |
| 交付物包（Deliverables） | 随成片一起交付的全部文件，如封面图、字幕文件、片尾字幕表 | 待议提案 |
