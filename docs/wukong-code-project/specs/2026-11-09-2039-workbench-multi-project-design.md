# 单端口多项目工作台

## 问题与目标

用户要求在同一个端口显示不同项目，通过当前影片切换，避免每片一个端口。现有服务已能列出单工程的 films/ 子目录，但只接收一个启动目录；两部示范片分属不同目录。本规格按用户长期授权默认通过，不涉及版本变更。

## 架构与组件边界

沿用一个 HTTP 服务和现有影片选择器。CLI 接受多个明确指定的项目或片目录，服务器合并各目录已有的影片发现结果。无需复制、搬动影片或引入代理、全盘扫描、后台常驻管理器。

## 接口、数据与行为

- 启动命令为 `wka workbench <首目录> [其他目录...] --port N --open`，无目录时仍使用当前目录，单目录行为兼容。
- 首目录仍是工作台会话存储位置与 workspaceId 的依据。影片 ID 统一按相对首目录的真实路径计算，保留原首目录下的 ID；重复目录及重叠目录只列一次。同名影片在名称后附相对路径，保证可区分。
- 各目录既可为片目录，也可为含 films/ 的工程。明确传入的目录先规范为真实目录并验证；影片 API、媒体、意见继续按对应片目录路由，不能按请求任意指定路径。
- CLI 正确消费 --port 等工作台选项的值，不把它们误当影片目录。capture/pending/register/repair 仍是单片操作，多目录组合应明确拒绝，避免静默忽略。
- 旧单片服务的正式审阅记录仍在各片目录；首目录的会话 ID 保持，额外项目先前单独启动时的私人草稿不迁移、不读取、不删除。

## 约束、兼容性与非目标

保留本机绑定、Host/Origin/Fetch Metadata 检查、Chrome 兼容、历史片只读和文件范围检查。仅接入明确目录；不改变生成、签批、鉴权或其他服务，不生成视频、不升版、不改插件安装缓存。不做全局端口发现、自动复用现存服务或动态注册；增加目录可在原端口重启此服务。

## 错误处理与运维

目录不存在或不是目录时在监听前报错；端口占用沿用现有报错。当前两个示范片统一到 63711，停止本会话的 63915 单片服务；不触碰其他影片的服务。服务重启后页面刷新获取新列表，旧 63915 页面改开统一地址。

## 验收标准与测试

1. 两个不同目录的影片在同一服务出现，ID 不冲突，各自文件和意见正确隔离；未指定的目录不可访问。
2. 首目录旧 ID 与 workspaceId 不变；重复/重叠目录去重，同名影片可区分，重启保持 ID。
3. CLI 端口值不成为位置参数，单片操作多目录明确失败；不存在目录不会启动部分服务。
4. 既有工作台、CLI、Chrome 来源检查回归通过；内嵌与外置 Chrome 在 63711 切换两部示范片并显示对应历史文件。

实施顺序：先写多目录与 CLI 失败用例，验证旧实现失败；最小修改发现与参数转发；更新帮助/文档；运行无视频生成的相关测试与 lint；替换当前服务并实测浏览器；提交并检查分支/worktree。
