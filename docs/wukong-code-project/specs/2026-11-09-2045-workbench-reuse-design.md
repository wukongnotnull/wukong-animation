# 自动复用本机工作台

## 问题与目标

用户要求以后打开新项目自动复用当前端口、加入选择器，无需手动追加目录或重启。承接单端口多目录实现，本规格按长期授权默认通过。

## 架构与组件边界

新增 CLI 工作台协调器，使用引擎用户数据目录 HOME 下的 workbench/ 保存运行记录和项目目录清单。服务仍是一个本机 HTTP 进程；首个启动命令持有进程，后续启动命令接入项目后退出。浏览器轮询更新选择器，不中断当前影片、播放、草稿或版本。

## 接口、数据与行为

- `wka workbench <项目或片目录> --open` 默认复用已登记且验证身份的工作台；否则恢复已有目录并启动，初次默认端口 63711。多目录一次接入仍支持。
- `--port N` 显式指定端口；已运行统一服务使用不同端口时明确报错，不偷偷另开服务。`--port 0` 保持临时独立服务能力，不读写统一服务登记，方便隔离验收。
- 运行记录包含本机地址、进程和随机实例标识及仅供本机 CLI 使用的控制凭据；目录权限 0700、记录文件 0600，凭据不进入页面、URL或日志。控制接口拒绝所有浏览器 Origin/Fetch Metadata 请求，并校验本机 Host 与控制凭据。网页 API 既有来源检查不变。
- CLI 先握手验证实例身份，再发送规范化目录；新增目录整批校验，保存成功后才生效，重复接入幂等。接入项目直接打开对应影片的 `?film=<ID>` 地址，裸地址仍可使用；已打开页面仅更新列表，不强制切换。
- 持久目录清单、首目录和端口保留，重启后恢复；已不存在的旧目录暂不显示，保留清单，不影响其他项目。新增目录错误则明确失败，不部分接入。损坏或新版登记不自动覆盖。
- 统一工作台私人会话保存在 HOME/workbench/workspace 下，避免首项目是历史档案时阻止新项目保存草稿。原单片私人草稿保留原处，不读取或迁移；正式意见与签批仍在各片目录，旧片继续只读。
- 启动锁串行化并发接入与启动；活跃锁等待，死进程遗留锁可恢复。实例结束仅清理自己的运行记录，项目清单保留。失联且进程仍活着时不抢占；非本工作台占端口时不终止、不改写、不向其发送项目路径。

## 约束、兼容性与非目标

不引入登录或浏览器鉴权长链接，不全盘发现项目，不启动视频生成，不自动签批，不升版、改安装缓存或自动发布。记录类 CLI 操作保持单片且不启动/连接服务。首个持有服务的命令退出后服务停止，不增加系统自启动或守护进程。

现有未支持接入协议的 63711 服务需要本次升级时重启一次；升级后新项目接入不再需要重启。不自动接管其他任务的旧服务。

## 错误处理与运维

统一服务状态与清单原子写入；连接有限超时，旧实例记录不能让新命令误连接其他服务。端口占用、不同端口、目录无效、存储故障给出可操作错误，保留已有服务与清单。

## 验收标准与测试

1. 两次独立 CLI 打开不同目录，第二次及时退出、URL 同源、第一服务进程不变、列表自动增加；重复接入不重复。
2. 并发启动与接入只产生一个服务，目录不丢失；停止后恢复目录和端口，死进程记录可恢复，损坏登记不被覆盖，其他服务占端口不受影响。
3. 无控制凭据、错误凭据、带浏览器来源的控制请求被拒绝；浏览器仍能正常同源读取，两片文件与意见隔离。
4. 活跃页面更新项目列表时保持当前影片、输入和版本；新打开页面按目标 film 选择，未知 ID 回落有效片。空列表也能在后续接入后恢复。
5. 内嵌与外置 Chrome 实测动态接入，无需刷新；记录相关回归、lint、分支/worktree 与 commit。
