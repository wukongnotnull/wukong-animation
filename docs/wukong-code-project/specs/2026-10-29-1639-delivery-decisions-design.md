# 可验证交付与已确认决定复用（FR-7）

Status: Draft，待用户审阅本文件；不是实现许可。
日期：2026-10-29；基线：main `d370839`。
依据：[已批准 PRD](../prd.md) FR-7、[issue #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。FR-6 回执提供产物状态；本设计负责交付链接与制作决定，不负责恢复执行。

## 1. 问题与目标

director 已有 Codex 绝对链接规则，但试听示例仍使用相对链接；引擎部分日志只打印相对路径。BRIEF 把必须元素、禁忌和参考放在同一题，未单独核对用户可提供的图片/视频/文件。第 15 道“无论简报选什么都先问”直接导致重复确认。

目标：交审前能证明目标文件存在并标明新旧状态；按宿主能力展示文件；已确认的字幕、画幅、素材与交付要求直接执行，缺少信息时才问。

## 2. 架构与组件边界

- 新 `core/delivery.mjs` 输出结构化清单和宿主 Markdown；不新增播放器或网络上传服务。
- `wka delivery <片目录> [--aspect <画幅>|all] --host codex|claude [--json]` 检查已登记产物，并写 `review/交付清单[-画幅].json/.md`。主副版各有状态，all 为汇总；不执行渲染、导出或签批。
- `.wka/decisions.json` version 1 存储来自明确用户选择的结构化制作决定和素材清单；`brief.md` 仍是用户审阅的简报，film.json 仍是实际渲染配置。此文件不是自动批准接口。
- director、BRIEF 规范、brief 模板及少量命令日志接入同一规则，删除冲突示例，不堆叠重复提示。

## 3. 接口、数据与行为

### 3.1 文件清单

每项含 `kind`（试听/声轨/接触表/动态分镜/视频/字幕/报告/草稿）、画幅、小样与否、绝对实际路径、文件/目录类型、大小或材料清单、内容签名、来源阶段、生成时间（已知时）、状态及宿主打开验证状态。

状态为 `current`、`stale`、`missing`、`unverified`。FR-6 的完成回执和当前输入签名一致且完整才为 current；旧工程只发现同名文件不能直接标当前，也不能编造生成时间。缺失/空文件/不可读/失效项列诊断，不能进入“可交付文件”链接列表。报告清单不能包含自己造成递归哈希。

默认只列当前存在的可交付文件，另区明确展示未完成或失效项；需要审阅的必需项缺失时命令返回非零并保存诊断。不以“清单生成成功”表示本次交付完整。产物无须重新生成即可检查路径；外部剪映草稿根据确切回执定位并展示草稿名、目录、状态及打开方式，不把目录伪装为可播放视频。

Codex/ChatGPT 本地链接用绝对路径；空格、中文、括号、`#`、`%` 等按 Markdown/URI 规则安全编码链接目标并保留可读标签，不使用 file:// 或虚构下载 URL。Claude 模式按其本地链接规则生成相对工作目录目标，目录外仍用绝对目标。路径标签避免破坏 Markdown。CLI/JSON 永远保留原始绝对路径，显示层编码不回写文件名。

图片、音频、视频的原生预览由 director 根据当前宿主实际能力提供；支持内嵌音频时附媒体预览。工具只打开了文件面板不能记成“播放成功”；验证记录区分 `not-tested`、`opened`、`playback-confirmed`，来源为实际工具结果或用户反馈。引擎路径检查不伪造宿主验证。不可用宿主标“未验证”，给存在的文件链接并保留边界。

### 3.2 制作决定

decisions 包含 `delivery`（video / video-and-draft）、`aspects`、`subtitles`（mode/bilingual）、`materials`，各项含值、`status:confirmed|unknown`、来源简报/用户原话摘要及确认时间（可核实时）。素材逐项记录类型、用途、原位置和本地副本（如有）；用户说“没有现成素材”是明确值，不是 unknown。

- 简报阶段单独问一次“有现成图片、视频、录音、参考文件或链接吗”，与现成口播稿分开。用户已提供的先登记并核对存在性，不重复询问；缺失或不可读时只问该项如何补齐。
- 已签批简报中的明确选择可以提取为 confirmed，来源指向简报内容及对应签批；不从含糊字词或缺省值推断批准。未知项才提问。
- brief、decisions、film 的相关项有冲突时说明具体差异并核实最新明确选择，不静默覆盖。用户新要求优先，保留变更依据；实质变更按既有审片流程重审受影响内容。
- 第 15 道：已选 video-and-draft 且当前成片/副版门槛满足，直接准备草稿导出；仅检测剪映正在运行时要求退出，缺依赖/目录时只处理该阻塞。video 已明确则记录无需草稿并结束；unknown 才问是否需要草稿。不得再次询问已确认的交付形式。
- 字幕方式、双语、画幅和素材按已确认决定继续执行；不把“别重复问”扩展为跳过声轨、字幕、成片、草稿的真实审片节点。

## 4. 约束、兼容性与非目标

- 旧工程不要求先补完整 decisions 才能使用现有 CLI；恢复时读取简报/历史，能确认才补登记，未知才询问。
- 不解析任意自然语言简报为可靠授权，不下载未授权素材、不创建虚拟媒体、不将本地素材上传到外部服务。
- 不承诺所有宿主播放器行为；本批必须在可用本地主机验证实际打开，其他宿主列明未验证。
- 不改变已有字幕文件命名、草稿同名避让或客户文件目录结构。

## 5. 错误处理与运维

失效项显示缺失路径和补做建议，不能生成指向不存在目标的交审卡片。保存清单原子替换，失败报告也必须反映本次检查。decisions 格式错误给文件/字段定位，不丢弃客户记录或用默认值替换。素材引用与实际文件分开记录，远程链接不能冒充已下载的本地素材。

## 6. 验收标准与测试

- 中文、空格、括号、`#`、`%` 目录中的试听、声轨、接触表、字幕、视频都生成有效目标；以解析后的链接实际打开文件，不能只匹配 Markdown 正则。
- 文件删除、替换、空文件、过期来源、失败导出不进入 current 链接；必需项缺失非零；历史文件标 unverified；主副版链接不混淆。
- 用可用 Codex 本地宿主实际打开代表图片/字幕/视频或音频，分别记录工具能证明的 opened/playback 状态；Claude 等未实际验证的宿主明确标注。
- 既有脚本/模板规则回归：已供参考和口播稿分别采用；已确认画幅/双语不再问；已选草稿直接准备；只有真实阻塞才要求退出剪映；未知交付才询问。
- decisions 与最新用户要求冲突、素材缺失只询问变化项；真实审片门槛保持等待。
