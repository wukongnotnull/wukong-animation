# 简报签批前自动打开工作台

## 问题与目标

用户于 2026-11-13 提出：“在对简报进行批签的时候，自动启动工作台，好让我在工作台预览简报，进行审阅”。当前第 2 道只写“交付方案简报，请用户核对”，工作台要用户另行要求才打开，用户签批简报时只能读聊天里的文件路径。

本规格按项目约定默认通过。目标：第 2 道简报进入签批前，导演自动保证工作台已运行并选中本片，用户直接在工作台里预览 `brief.md` 及素材清单，再回到对话作签批决定。

## 范围与行为

1. 仅限第 2 道方案简报的签批。其他审片节点沿用“用户要求才打开”，不改。
2. 弹签批卡片之前，导演依次运行：`wka workbench <片目录> --capture`（把当前 `brief.md` 存为交审版本），再 `wka workbench <片目录> --open`（复用已登记服务并选中本片；没有服务就启动，沿用首次默认端口 63711）。
3. 交付物清单第一行给工作台本机地址，其后照常逐行列出 `brief.md` 与 `review/素材/素材清单.md`（若有）的路径，并提示在工作台预览。
4. 工作台已在运行时直接复用，不重启、不新开服务进程；多支片同时待签时分别对各自片目录运行同一命令，同一页面按影片列表切换。
5. 宿主没有本地执行能力或启动失败时，如实说明原因，退回文件路径审阅，不伪造链接，也不因此阻塞签批。
6. 工作台只用于查看和写批注。签批仍只能由用户在对话卡片里明确作出；打开、浏览、批注都不等于通过。简报被修改后须再次 `--capture`，页面自行载入新版本。

## 非目标

不改引擎代码、工作台页面、`wka signoff` 行为与工程 flow；不升版本、不发布、不推送。

## 验收标准与测试

`tests/unit/director-signoff-copy.test.mjs` 断言导演技能第 2 道包含：签批前自动 `--capture` 与 `--open`、地址列在交付物首行、失败时退回文件路径、工作台不代替签批。运行 `node --test tests/unit/director-signoff-copy.test.mjs`，并跑 `npm run lint` 检查文档一致性。
