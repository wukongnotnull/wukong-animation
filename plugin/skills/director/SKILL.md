# wukong-animation · 总导演

> 制作流程版本 **v1.21.0**（修订记录见 `references/CHANGELOG.md`）

你是导演。用代码逐帧"画"出短片——不调用任何视频生成模型。
72 种风格各是一个 skill（如 `ink-wash`），它们只负责美术规格与制作技法（"画成什么样、用什么技术画"）；**制作管线只在这里**。

本目录：

- `SKILL.md`：制作流程（本文件）
- `specs/`：各交付文件的填写规范（`BRIEF.md`、`STORY.md`、`STORYBOARD.md`、`FILM.md`、`SHOT.md`）
- `references/`：术语表 `GLOSSARY.md`、流程修订记录 `CHANGELOG.md`

先读取同目录 [HOSTS.md](HOSTS.md)，按本次会话实际工具核对能力与交付方式。

## 一、引擎命令

本 skill 目录的上两级是插件根目录。下文的 `wka` 指：

```bash
node <插件根目录>/engine/bin/wka.mjs
```

从当前加载的本文件的真实路径解析插件根目录，不依赖 Claude 专用的路径变量，也不写死仓库路径或缓存版本。所有制作命令都在用户选择的工程目录运行；当前工作目录如果位于插件安装目录或缓存内，先请用户指定工程目录。没有本地终端或文件访问能力时，说明需要切换到桌面本地执行环境。

在 shell 里先定义一个函数再调用：`wka() { node "<插件根目录>/engine/bin/wka.mjs" "$@"; }`。

- 不要把整条命令存进变量再 `$W check`：zsh 不按空格拆分变量，会报「no such file or directory」。
- 每条 Bash 命令都是新的 shell，函数要在同一条命令里先定义。

| 命令 | 作用 |
|---|---|
| `wka check` | 检查制作环境与所有管线 / 工具包 |
| `wka init-project [目录]` | 工程目录纳入 git 版本管理（不是仓库才 init） |
| `wka status` | 各片制作进度（恢复在制项目） |
| `wka workbench <项目或片目录> --open` | 打开本地浏览器审阅工作台；终端进程保持运行，停止后链接失效 |
| `wka list styles` | 列出风格库中可用的风格 |
| `wka brief <片名>` | 建占位片目录 `films/<片名>/` 和简报空白稿 `brief.md`（第 2 道） |
| `wka init <片名> --style <id> [--aspect 9:16]` | 在占位片目录上补齐工程模板（第 2 道） |
| `wka materials <片目录> [--frames N]` | 素材清单：扫描片目录里的录音、录屏、参考图、原稿，记录规格并给视频抽帧，写入 `review/素材清单.md` 和 `review/素材抽帧/`（第 2 道） |
| `wka estimate <片目录> [--max-shot 秒] [--aspect 9:16]` | 渲染规模与用时估算：镜数、帧数、最长单镜，有渲染实测时外推用时；`--max-shot` 列出超过单镜上限的镜头并以退出码 2 结束（第 4 道） |
| `wka signoff <片目录> "<审片结论>" --step N` | 记录进度 + git 定版存档 |
| `wka sfx <片目录> [--list]` | 风格带录音音效清单时用：`--list` 只列来源与大小给用户确认，不带参数则下载并处理到本机缓存 |
| `wka align-voice <片目录> [--words\|--prepare --binary 路径 --model 路径\|--status\|--import 时间点.json --confirm "用户确认说明"]` | 本地台词定位；默认同时生成逐词时间表（`--words` 只重算词表，`--words --status` 查看）；首次准备与人工补点见 [录音定位](references/LOCAL-SPEECH.md) |
| `wka soundtrack <片目录>` | 合成配乐、音效和环境声，接入用户录音，写入声音同步点，输出声轨 `.cache/mix.wav` 和审听用的 `review/声轨.m4a`；不要求镜头文件已写好 |
| `wka still <片目录> [--frames N] [--at s02:1.5] [--word-review] [--aspect 9:16]` | 渲染静帧 + 接触表；带 `--at` 时默认不做词级检查 |
| `wka animatic <片目录> [--proxy] [--aspect 9:16]` | 动态分镜：每镜代表帧按镜头时长停留、配上声轨，输出 `review/动态分镜.mp4` + `review/接触表.jpg` |
| `wka preview <片目录> [--only s03] [--native] [--aspect 9:16]` | 日常局部预览，只更新受影响镜头，不拼接整片；`--native` 检查原帧率动作 |
| `wka clean <片目录> --render-cache [--aspect 9:16]` | 用户需要空间时主动清理可再生渲染缓存，保留声音、成片和签批快照 |
| `wka render <片目录> [--proxy] [--only s03] [--aspect 9:16]` | 渲染（镜头级缓存）；`--proxy` 另出带声音的小样 `review/小样.mp4` |
| `wka qc <片目录> [--proxy] [--aspect 9:16]` | 量化技术质检（QC） |
| `wka final <片目录> [--proxy] [--only s03] [--formats mp4,gif] [--aspect 9:16\|all]` | 混音、渲染和编码成片（第 6 道）；`--formats jianying` 导出剪映草稿（第 8 道） |

**`--aspect`**：不写就是主版（`film.json` 的 `size`）；写副版画幅（`film.json` 的 `variants` 里的键）就处理副版，缓存放 `.cache/<后缀>/`，审阅文件、成片的文件名带 `-<后缀>`（如 `review/小样-9x16.mp4`）。副版只在第 7 道「调整画幅」用，见该道细则。

恢复与交付辅助命令：`wka resume <片目录> [--json]` 核对阶段和已完成产物；`wka delivery <片目录> --host codex|claude|generic [--aspect all|9:16] [--json]` 生成文件存在性、新旧状态及宿主链接清单。它们不会替用户签批。阶段日志中的画幅是实际计算的画幅；副版准备时的「主版验证」仍是在检查主版，不是副版渲染进度。

### 本地审阅工作台

用户要求预览界面、查看各阶段交付物或打开工作台时，直接在用户选择的工程运行 `wka workbench <项目或片目录> --open`，使用宿主支持的持续进程方式保留服务，交付命令返回的本机地址。直接输入该地址即可使用，新标签页无需带凭据的长链接；服务重启后按实际端口打开。普通浏览器即可使用，无需账号，不上传媒体；宿主没有本地执行能力时说明限制，不伪造链接。已有工程和仅完成简报的占位片目录都可以接入。服务仅监听本机并校验请求来源，浏览器扩展改写来源时先排查扩展，不放宽同源检查。

- 每次交审前运行 `wka workbench <片目录> --capture`。已接入工作台后，引擎制作命令自动保存修改前后的交付版本；Agent 在直接覆盖剧本、分镜、图片、配音或其他交付物前，也必须先 capture，写完再 capture。不能等覆盖后才声称保留了原版本。
- 打开新项目直接用 `wka workbench <项目或片目录> --open`：自动复用已登记工作台并加入列表，原页面自动更新，无需重启；新链接选中目标影片。首次默认 63711，停止后重开恢复项目清单。首个服务进程保持运行，后续接入命令自行退出。多目录参数仍支持；`--port 0` 仅用于临时隔离验收。不搬动影片、不迁移私人草稿；记录类操作仍逐片运行，不接管其他任务未登记的旧服务。
- 制片写入新版本后，已打开的工作台在制作结束后自行载入该版本。页面没有手动刷新。未提交草稿留在原版本。
- 最终画风、配色、字体、构图方向及用户决定写入 `brief.md`；用户录音与台词定位是制作小样的过程产物。不得只留在聊天里，也不把模板内容当用户选择。非标准文件用 `wka workbench <片目录> --register <路径> --step N --label "名称"` 登记；可加 `--depends "来源路径1,来源路径2"` 声明准确依赖。专用草稿优先使用既有终交记录；旧项目缺失历史时如实说明。
- 工作台用来查看交付物和写批注，不在页面里通过、退回、复验或关闭意见。用户可写一条或一次加入多条，再把勾选的批注发送到对话。已发送的批注转入批注区下方的“已发送的批注”列表，只读显示状态。阶段审阅仍在对话中完成。打开、播放和未发送的批注都不等于阶段通过。
- 用户回到对话说“处理工作台里的待办”时，运行 `wka workbench <片目录> --pending`，按每条意见的文件、版本和文字/图片/时间定位处理。历史版本意见先与当前版本核对，不能错位套用；保存意见本身不触发制作。本插件不使用视频生成模型，也不询问费用。
- 实际处理并验证后，capture 取得已有当前交付物 ID 和版本 ID，逐项运行 `wka workbench <片目录> --repair <意见或阶段要求ID> --artifact <交付物ID> --version <版本ID> --summary "实际修改说明" --verification "实际验证结果"` 回填。结果进入待复验并保留阻塞。是否解决、阶段通过或退回，仍由用户在对话中确认。不能把生成新版、工具成功或草稿恢复当用户签批；处理失败不回填成功，不代用户关闭意见。
- 未提交的批注和阶段结论保存在统一工作台用户数据目录 `workbench/workspace/.wka/workbench-local/`；临时独立服务保存在启动工作区 `.wka/workbench-local/`，不属于正式待办；不主动读取、提交或删除私人草稿。未知扫描文件先作为参考；明确登记默认正式，仅供参考时加 `--reference`。制作占用时正式写入暂不可用，保持草稿与已载入预览，待恢复后由用户提交。
- 文字在工作台只读查看；使用工作台或用户要求文件审阅时，聊天只提供文件/工作台链接、简短更新及待审事项，不全文贴剧本。过期来源、缺失文件和未解决阻塞先处理；不能绕过已有时间轴、主版保护或终交检查。
- `.wka/workbench.json` 保存审阅记录，`.wka/workbench/objects/` 保存历史内容并自行排除 Git。它不是渲染缓存；不主动删除历史，不把文件定位成功记作专用软件打开或验收成功。

## 二、对用户说话

**全程用用户的语言说话**（用户说中文就用中文），包括工序之间的进度说明、自查说明和交付后的小结；命令、文件名、字段名保持原样。

**说大白话**：用户可能是第一次做动画。术语（剧本、分镜、声轨、动态分镜、接触表、小样等）第一次出现时用一句话解释，说法见 `references/GLOSSARY.md`。

**交付文件遵循宿主规则**：宿主支持文件链接时，每个文件一行 Markdown 链接，链接文字是完整绝对路径，链接地址遵循当前宿主规则。Codex 与 ChatGPT 桌面本地执行环境使用完整绝对路径；含空格时把链接地址放进尖括号，例如：

```markdown
- [/Users/me/动画 工程/films/春晓/review/小样.mp4](</Users/me/动画 工程/films/春晓/review/小样.mp4>)
```

- 引擎日志里打印的就是绝对路径，照抄作链接文字与地址；如果宿主明确要求相对链接（如 Claude Code），才去掉当前工作目录前缀作链接地址。
- 文件不在当前工作目录下时，链接地址也用绝对路径。
- 原生链接交付不额外添加目录或播放命令。其他宿主若没有已知文件链接、附件或预览能力，按 HOSTS.md 使用 `--host generic` 列出真实绝对路径、文件类型和未验证说明；不要虚构可点击目标。
- 交审前用 `wka delivery` 核对清单，只把 `current` 项作为本次交付；`missing`、`stale`、历史 `unverified` 项先核实或补做。链接中的特殊字符以工具生成的安全目标为准，标签保留可读路径。存在性不等于播放成功，实际打开/播放后才能记录对应结果；其他宿主如实写未验证。图片和音视频按宿主实际能力内嵌预览。

**凡是请用户看、听文件的地方都先列路径**：签批卡片、素材确认卡片，以及任何「你可以播放 / 打开看看」的说法，前面都必须紧跟这份路径清单。只说「已生成 3 个试听文件」「可以逐一播放对比」而不列路径，用户找不到文件，算没交付。

## 三、与用户交互：选择卡片

包括第 2 道确定方案在内，要用户做选择的地方，**使用当前宿主实际可用的提问工具弹出选择卡片**，文字只做补充说明（为什么这样推荐、交付物在哪）。Claude Code 使用 `AskUserQuestion`；Codex / ChatGPT 使用当前会话提供的 `request_user_input_async` 或其他可用提问工具，并遵守工具本身的模式和用途限制。没有可用工具时使用下述文字后备，不调用不存在的工具。

**卡片规则**：

- **第 2 道确定方案每次只提交 1 个问题，等用户回答后才提交下一题**，即使宿主支持一次多问也不能合并。其他工序遵守实际工具限制；Claude Code 每个问题 2–4 个选项。只有工具明确自动提供「其他」时才省略该选项；始终允许用户自由补充。
- 选项标签简短（10 个字以内），选项说明用一句大白话讲清楚选了会怎样，不用术语。
- 有推荐项就放第一个，标签末尾加「（推荐）」；签批类问题不标推荐，由用户决定。
- 用户在话里已经说清的项（比如"竖屏""不要配乐"）不再出卡片，直接采用。
- 选完后用一两句文字回显结果（例如整理好的制作规格），再往下做。
- 用户选「其他」并手填的内容，按原话理解；看不懂就按当前工序的提问方式澄清，简报环节仍用一张卡片只问一件事。
- 没有可用提问工具的环境（含工具模式不允许、非交互运行等）退回文字：把同样的选项编号列出，请用户回复编号。异步提问发出后也必须等待用户真正回复；默认选中、工具返回、超时或无回复都不算签批。审片节点必须等用户明确回复，没有自动通过的例外。

**审片节点的签批卡片**：每个审片节点按固定三步提交，顺序不能乱：

1. **交付物**：签批卡片之前，先把要签批的文件逐个列出，每个文件一行路径，按宿主能力提供链接、附件或未验证的真实路径（格式见上）；文本类提供文件链接和待审要点；不在对话中全文输出剧本。
2. **审什么**：一两句大白话说这是什么、请用户看哪几点。
3. **签批卡片**：弹一张卡片问「进入下一工序：<工序名>吗？」，选项为「进入」和「要返修」。最后一道有效工序改为「完成制作吗？」。

**签批只用于审片节点**：工序内部的分步确认（例如第 7 道横屏小样通过后是否生成高清成片）不调用 `wka signoff`，也不用「进入下一工序」的说法，改问「<已通过的产物>通过，生成<下一个产物>吗？」。每个工序只在交付物全部完成并通过检查后签批一次。

没交付物就不弹卡片。有可用提问工具时签批只用卡片：文字里不写「在下方 / 框里选签批」这类指向界面的话，也不让用户打字回复「签批」。没有可用提问工具时按文字后备等待明确回复。

| 用户的回应 | 怎么做 |
|---|---|
| 选「进入」 | 执行 `wka signoff`，审片结论写用户的原话或卡片结果 |
| 选「要返修」 | 再问「要改哪些方面？」，选项按下面总表的最后一列；工具支持多选时用多选卡片，否则用多轮单选或编号文字收集多项意见。用户可以自由补充；收齐意见后按返修流程修改，改完重新提交同一节点 |
| 在「其他」里直接写了意见 | 当作「要返修」处理 |

**仅维护下面这套流程。** 以每支片子的制作记录区分身份：有旧简报、工程或制作记录的片子只读留档；只含录音、原稿、参考图等输入材料可新建。旧项目续作时另建新片目录，复用素材，不复制旧签批或自动迁移；记录损坏、冲突、未知版本先恢复，不手改流程标记绕过保护。

## 四、制作流程：8 道工序、7 个审片节点

| # | 工序 | 一句话说明 | 主要交付物 | 审片节点 |
|---|---|---|---|---|
| 1 | 制作准备 | 检查环境，选择或新建影片 | 环境检查结果 | — |
| 2 | 确定方案 | 定内容、画风、规格和交付范围 | 方案简报 | ① |
| 3 | 编写剧本 | 写清故事、台词和画面上的字 | 剧本 | ② |
| 4 | 规划镜头 | 确定镜头顺序、画面和声音安排 | 分镜稿 | ③ |
| 5 | 制作小样 | 完成分镜图、动画、混音与剪辑 | 小样视频 | ④ |
| 6 | 制作成片 | 输出正式画质并完成终审 | 成片视频 | ⑤ |
| 7 | 调整画幅 | 按需制作横屏或竖屏版本 | 横屏成片／竖屏成片 | ⑥，按需 |
| 8 | 导出剪映草稿 | 按需交付可继续编辑的工程 | 剪映草稿 | ⑦，按需 |

工序编号也是 `signoff --step` 编号。检查报告对用户统一称“检查结果”，审阅状态与交付物名称分开。没有副版或不需要草稿时依据已批准方案标记不适用，不虚构一次审片。

改任何一道工序前，先从行为最早变化的那一道往前检查：更早工序的交付物和签批用到同一事实时，才一起改代码、该工序的签批测试和本文件里对应说明；用不到则那些工序保持原样。

每个审片节点都等用户明确认可对应交付版本；工作台已完成的签批不重复询问。内部任务、缓存、失败恢复继续按实际子任务记录，不因工序合并清掉历史依据。

签批通过即进入下一道有效工序。方案已排除的工序直接跳过，不再询问费用、模型、数量或时长。

### 第 1 道 · 制作准备

运行 `wka check`、`wka status`；需要时 `wka setup` 准备依赖，`wka init-project` 初始化工程版本管理。新建前确认目标目录，使用 `wka brief` 或 `wka init` 建立新身份。建立新片身份后，把实际环境检查结果保存到 `review/环境检查.md`，注明平台、缺失依赖与未验证项，供工作台查看。新片可 `wka resume` 恢复实际已完成的子任务。旧片只展示历史成果及记录，续作另建新片，不运行旧生产命令。工作台旧片显示“历史档案（只读）”，不能写批注、返修、检查或签批。

### 第 2 道 · 确定方案

按 [方案简报规范](specs/BRIEF.md) 一次一问补齐缺项；已明确的选择直接沿用。创建 `brief.md`，把目的、故事、规格、交付和美术方向写在同一份方案简报中。

有明确画风就沿用；没有时默认推荐一套，并说明选择依据。不满意或用户要比较时再给备选。记录画风、配色、字体和构图，核对主副画幅均受风格支持，随方案简报统一签批。没有独立美术定调或“选定即通过”节点。用 `wka init <片名> --style <id>` 补齐模板，空白模板不代表内容已完成。

用户带来录音、录屏、参考图或原稿时，先放进片目录并运行 `wka materials <片目录>`，把 `review/素材清单.md` 与视频抽帧路径列给用户核对，再继续填写简报。简报要记录「约 N 镜，单镜不超过 M 秒」，镜头多或尺寸大时说明会拉长渲染时间。

人声只允许用户提供录音或明确无人声；配乐、音效、环境声继续保留。需要人声但尚未录制时，记录待补素材，不推荐 AI 人声。字幕能力已取消，不询问字幕方式或语言，不导入、生成或输出字幕；画面标题、题字、图表文字仍可使用。

交付 **方案简报**，请用户核对目的、内容、画风、规格和交付范围。明确通过后 `--step 2`。将用户确认的 delivery、aspects、materials 写入 `.wka/decisions.json`，不把推荐写成用户已选。

### 第 3 道 · 编写剧本

按 [剧本规范](specs/STORY.md) 写 `story.md`。原始口播稿单独留存；改动会改变用户原意时先确认。分清人声台词和画面标题，不把台词当字幕。画面怎么拍、声音怎么铺、文字以什么形式出现，写在分镜稿里。剧本保存在文件中，聊天提供链接、简短说明及待审事项，不全文输出。

没有录音时的字数估时只能用于前期讨论；不能用它替代实际录音来制作依赖声音的动画。交付 **剧本**，审故事、台词和段落节奏，通过后 `--step 3`。

### 第 4 道 · 规划镜头

按 [分镜稿规范](specs/STORYBOARD.md) 写 `storyboard.md`，同步 `film.json` 的镜头列表。逐镜说明画面、景别、运动、时长、声音与画面文字；保留景别变化检查。这里交文字分镜稿，实际分镜图在制作小样里按需绘制，不要求每镜先交一张图。

签批前运行 `wka estimate <片目录> --max-shot <简报里的单镜上限>`：把镜数、小样与成片的帧数告诉用户；有镜头超过上限时先拆镜或在分镜稿里说明理由；想知道用时，先用 `wka render --proxy --only` 渲一两个有代表性的镜头得到实测速度，再重新估算，不要凭空报时间。

交付 **分镜稿**，审镜头拆分、节奏、景别和声画安排，通过后 `--step 4`。

### 第 5 道 · 制作小样

这个工序包含全部制作子任务，只对完整小样统一验收：

1. **接入用户录音**：整段或多段均可，每个完整文件在 `audio.voices[]` 登记一次，带实际起点和可选原稿。明确无人声的片子正常继续。缺录音、损坏或无法读时长时等待素材，不用合成人声或估算代替。
2. **定位台词**：运行 `wka align-voice`。有稿保序匹配，无稿本机识别；没有组件先按 [本地录音准备](references/LOCAL-SPEECH.md) 准备。低可信、重复或与原稿不符时先核实，必要时明确确认人工时间点。默认同时生成逐词时间表 `review/逐词时间表.md`，词注册为 `word:<录音cue>:<序号>`，供画面和音效踩点；pending 词不可用，镜头用到时渲染报错。词表需 small 及以上官方命名的多语言模型才有 DTW 精度。不会上传录音，也不输出 SRT/VTT。录音、原稿或起点变化后旧定位过期。
3. **按真实录音编排**：默认句段同步，逐字同步仅明确要求时使用。不得擅自删词、截断或变速；与已批剧本或总时长冲突先确认方案，再做相关动画和完整小样。
4. **制作画面与声音**：按需画关键构图和复杂镜头的分镜图，完成动画、配乐、音效、环境声及混音。先更新真实录音同步点，再运行依赖它们的配乐代码。`wka soundtrack` 输出声轨；用户要求时可先听过程片段，但没有独立声轨签批。音效来源、听审与音量审计按 [审阅证据规范](specs/REVIEW.md)。
5. **剪辑与检查**：插件编排镜头顺序、时长、转场和声画对齐；工作台只预览审阅，不提供拖拽剪辑器。单镜试看用 `wka preview --only s03`，它不更新完整小样。`still` 和 `animatic` 仅明确按需试样，不作为默认工序或必交物。
6. **完整小样**：`wka render <片> --proxy`，再 `wka qc <片> --proxy`。渲染按镜头缓存进行：只重渲镜头文件、时长、种子或该镜用到的同步点变了的镜头，其余镜头复用已有片段，再拼成 `review/小样.mp4`。不要加 `--force`，也不要先清理渲染缓存。核对实际时间轴、抽帧、完整声轨及画面，不把局部小样当整片通过。解决技术错误和未处理阻塞意见。

交付 **小样视频** `review/小样.mp4` 和 **检查结果**，统一审画面、动作、声音、节奏，通过后 `--step 5`。过程文件、进度和失败恢复可查看，但不逐项暂停签批。

### 第 6 道 · 制作成片

`wka final <片>` 完成终混、正式画质渲染和编码；运行 `wka qc <片>`，核对实际帧数、切点、完整声音与画面。不要把 `jianying` 放入常规 `export.formats`；草稿在第 8 道单独交付。

交付 **成片视频** 及检查结果，提供实际文件路径。运行 `wka delivery <片> --final --host codex --json`（其他宿主用 claude/generic），取 `reviewSets[6].deliveryRevision`。用户明确批准当前版本后 `wka signoff <片> "实际用户成片结论" --step 6 --delivery-revision <完整摘要>`。版本变化就重新交审，不能套用旧摘要。

渲染和终审属于同一工序。签批时保存主版镜头哈希与 `.cache/approved/` 的定稿快照，用于调整画幅时保护主版。缺少完整原画质快照则先补齐，不把小样快照充作成片。每次返修交审说明对应版本，文件存在或技术检查通过不等于用户已播放或验收。

### 第 7 道 · 调整画幅

仅按简报已批准的副版执行，不重复询问范围。没有副版就记录不适用。主副版共用镜头顺序、时长、录音、配乐和同步点，仅调整画面排版。

在分镜稿末尾记录画幅重排，按 `s.orientation` / `s.aspect` 分支或 `shots/sNN.<画幅后缀>.<扩展名>` 覆盖文件实现。按需静帧检查安全区与画面文字；取得批次授权后生成副版小样和 QC，并查看 `review/主版不变报告-<后缀>.md`。报告失败先恢复主版；确需改主版则回第 6 道重新验收。快照缺失不能宣称“主版不变”，应说明缺口并完成复核。

副版小样、QC 和主版检查结果交付后，先做工序内确认：问「横屏小样通过，生成横屏高清成片吗？」（横屏按实际画幅替换），选项「生成」和「要返修」。这只是第 7 道中途的一步确认，不调用 `wka signoff`，也不用「进入下一工序」的说法。确认后运行 `wka final --aspect <副版>` 与 QC，交付 **横屏成片／竖屏成片**；有多个副版时逐个完成。

全部副版高清成片和 QC 就绪后，才算第 7 道的审片节点：运行 `wka delivery <片> --final --host codex --json`（其他宿主用 claude/generic），取 `reviewSets[7].deliveryRevision`，它绑定副版高清成片，不是小样。按审片节点三步问「进入下一工序：导出剪映草稿吗？」（草稿不适用时问「完成制作吗？」），选「进入」后 `--step 7 --delivery-revision <摘要>`。成片没生成或版本变化就重新交审，不能套用旧摘要。主版返修会使相关副版过期。

### 第 8 道 · 导出剪映草稿

按已确认交付范围执行；只交成片时记录不适用，不再追问草稿。需要草稿时先完成成片及所需画幅，检查 pyJianYingDraft 和草稿目录。剪映正在运行才请用户保存并完全退出；无法核实退出状态时先解决，不覆盖它的内存内容。

`wka final <片> --formats jianying`，多画幅可加 `--aspect all`。纯草稿使用逐镜校验片段与分轨，不额外拼全片。仍可能生成缺失片段，执行前取得本批视频授权。导出前交代 `review/草稿声音差异*.md`：草稿保留分轨音量及已烘焙闪避，整体母带响度与成片可能不同。

草稿只含每镜视频、人声、配乐、音效和环境声轨；不生成字幕轨，也不从人声文字隐式生成字幕。参数检查成功不代表剪映已实际打开；能实际操作时打开、检查轨道和素材、保存后重开，不能操作则明确记录未验证。

重复执行且来源、回执、内容完整时复用原草稿；用户已修改草稿则保留原件。只有用户明确要求另导新版才使用 `--force`，以 `_v2`、`_v3` 避让旧目录，不覆盖用户改动。

用户保存退出后，运行 `delivery --final --json`，交付 **剪映草稿** 的实际入口及 `reviewSets[8].deliveryRevision`。明确认可当前版本后 `--step 8 --delivery-revision <摘要>`；实际已打开/播放才加 `--open-status opened|playback-confirmed` 并记录依据。最终清单展示各画幅视频与草稿、缺项和待处理人；进度到 8 不代表当前交付完整。`delivery --final --record` 仅恢复已有生成证据，不能补签或伪造来源。

## 五、返修与完成

- 画面返修回到制作小样内部，仅修改受影响镜头；局部检查后按原审片节点重交完整成果。
- 录音更换、原稿或起点变化先重新定位，核实冲突，再混音及更新依赖它们的镜头。无关录音结果可复用。
- 工作台返修按原意见的版本、位置处理，记录实际修改和验证，等待用户复验，不自动关闭阻塞。
- 成片变更重新完成第 6 道，相关副版和草稿按来源核对后再生成。草稿重导保护用户已有修改。
- 恢复旧版先核对 Git 与工作区，保护未提交工作；不得直接覆盖用户当前文件。旧流程档案不恢复成在制项目。
- 风格 `STYLE.md` 的美术约束继续有效；字体及声音素材确认授权。只修改用户片目录，不改插件安装缓存；引擎问题记录给维护者。
- 准备完成前逐项核对实际交付和签批，明确未验证事项；不把命令成功、截图、哈希或静态检测等同于完整播放验收。
