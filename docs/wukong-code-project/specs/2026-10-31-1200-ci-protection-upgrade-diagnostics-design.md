# 第五批：CI 合并保护与升级诊断

Status: Approved — implementation in progress
Baseline: v0.19.5 / 9b913f2e4bc37835406f6366efb4c06305ff8268

## 问题与目标

已实查 main 未保护、required checks 为空、rulesets 为空；CI 会运行但不强制阻止合并。smoke 使用 paths-ignore，直接设为必过会使纯文档 PR 缺少结果。原 check 展示引擎版本、路径及依赖身份，没有独立插件版本与更新诊断。最近发布曾被无关失效 marketplace 条目阻断。

目标：使每个 PR 都有明确的必要检查结果；提供用户可理解的安装身份、依赖及更新指引。范围限两个独立交付项，按门禁、诊断顺序实施。

## 架构与组件边界

新增始终触发的聚合工作流，为 main PR 产生唯一稳定检查 `merge-gate`。由同一工作流调用 lint、三平台安装、严格剪映及媒体回归的可复用工作流；保留原有 push/手动入口，消除 PR 重复执行。聚合任务使用 always 判定所有需要的任务真实 success；需要执行的任务 skipped/cancelled/failure 均拒绝。纯文档变化只允许明确白名单跳过媒体工作，聚合任务仍必须执行并解释原因。未知或混合变更走完整检查，不依赖 paths-ignore 产生必过上下文。

main 采用分支保护：要求 PR、最新基线及 `merge-gate` 成功，管理员同样受约束，禁止强推和删除；不要求自我批准，不设置额外审批人数，不引入合并队列。应用前确认稳定检查实际出现并绑定 GitHub Actions 来源；权限或套餐不支持时明确阻碍，不伪装已生效。

新增 `check --upgrade` 只读诊断；提取 core/installation-diagnostics.mjs，CLI 负责呈现。原 check 不变。模块可注入读取环境，测试使用隔离目录。

## 接口、数据与行为

`check --upgrade` 输出插件版本、引擎版本、实际插件路径、可证明的 native/portable/development 来源、依赖来源与身份，以及按该来源生成的升级操作。原生读取自身清单；便携读取并校验 bundle.json；来源证据不完整则 unknown，不能靠目录名猜测版本。配置解析只限所需字段，输出不包含凭据或完整用户配置。

`check --upgrade --json` 输出 schemaVersion:1，包含 plugin、engine、installation、dependencies、guidance、warnings；缺失值为 null 并有原因。已识别且身份一致退出 0；清单损坏、身份冲突或必要依赖未就绪退出 1；单纯无法判断远端最新版本或宿主是否已重载为警告，不冒充失败。提示打开新聊天/按宿主刷新；不声称能检测当前聊天实际加载版本。

诊断不调用 marketplace 更新、不联网查 latest、不自动运行 setup。若可只读发现失效的其他 marketplace，指出条目名称和路径及手动核对建议；不能因为它失败而隐去本插件自身信息。宿主配置格式未知时降为警告。原生给官方更新命令，便携给相同 agent/scope/project/variant 的升级说明，未知来源不给自动修改命令。

## 约束、兼容性与非目标

1. 只保护 main；不改变插件身份、运行时依赖、工程流程、签批和媒体算法。
2. 不删除或自动修复其他插件、marketplace 配置、旧依赖和用户作品。
3. 诊断默认只读、离线；不能证明的安装来源、远端更新或宿主加载状态显示未知。
4. 保留既有 check 默认输出及退出码契约；新增诊断使用显式选项。
5. CI 失败、取消、跳过或未产生必要结果不能通过合并门禁；不放宽现有断言。
6. 仓库保护变更先保存原配置、验证权限和回退方案；获批实施后再应用，发布另行授权。

不包含 Windows 真机渲染、依赖垃圾回收、自动升级、性能改造、其他宿主配置修复或安装器重写。

## 错误处理与运维

保护配置与实际检查名写入验收报告；先在临时 PR 证明成功/失败门禁，再应用 main。使用 API 预期状态核对，避免覆盖并发变更；回退仅恢复本次变更前保存的保护字段。失败 PR 不为验证而合并。临时分支和测试 PR 在取证后关闭，保留原因。

## 验收标准与测试

| ID | 条件 |
