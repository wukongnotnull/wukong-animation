# 剪映草稿交付可靠性修复设计

Status: Draft
Last updated: 2026-10-30
基线：`main fe921d7`。关联：[体验优化 #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。
用户已确认优先修草稿交付；本文件的具体设计尚待批准。依据：[实拍复盘](../reports/2026-10-30-production-delivery-review.md)及已确认 PRD 的 FR-1/FR-4/FR-7。属于既有行为修复，不新增产品需求编号。

## 1. 问题与目标

使标准 `wka final --formats jianying` 能导出连续多镜头和完整双语字幕，避免依赖作品目录内的 Python 包装器、CLI 绕过脚本和整轨手动调字号。修复三项：微秒重叠、英文建议误拦截、草稿字幕实际显示偏小或长句越界。

保留用户已批准的原文、镜序、声音、画幅、字幕样式和正式审片节点；修复引擎不等于重新批准客户成片。

## 2. 架构与组件边界

- `exporters/jianying/plan.mjs`：由当前输出的统一帧切点生成微秒起止；承接画布尺寸及逐条字幕排版，生成完整计划。
- `bin/wka.mjs`：将英文文本完整性检查与建议分开；纯草稿路径进行当前原生尺寸字幕版式测量，不为此拼全片或烧录视频。
- `core/subtitle-layer.*` / `subtitle-preflight.mjs`：复用真实字体测量、逐条中英字号和字框；只在必要时补充内部返回信息，不改变字幕文本与时间。
- `exporters/jianying/write_draft.py`：写入每条字幕的样式，保持旧计划未提供逐条样式时的轨道/全局回退行为。
- `director/SKILL.md`：区分“样式参数已写入”和“实际显示已核验”；说明草稿验收所需检查及尚未验证的边界。

校准证据和验证结果保存为仓库测试夹具及报告；不保存客户草稿、人物图片、成片或本机素材绝对路径。

## 3. 接口、数据与行为

### 3.1 统一量化切点

对每个镜头从引擎已确定的输出帧起止派生整数微秒起止，`duration=endUs-startUs`。相邻镜头共享同一切点；末镜终点与统一时间轴终点相同。不得独立 round 起点与长度，不以逐镜裁掉 1μs 或放宽 Python 重叠检查作为正式方案。

源计划的实质重叠、逆序、零长度及与媒体不符的长度继续拒绝并报告镜号。声音和字幕时间不随视频量化修复被整体平移；素材时长不足不能被静默裁短成有空隙的成功草稿。

### 3.2 英文完整性和版式建议分离

缺文件、非数组、条数不匹配、中文不对应、空英文继续作为错误；使用已有双语挂接逻辑，避免另一套不一致的结构判断。

字符数和句号提示保留为明确警告，不能触发“字幕缺失”异常，不能自动改写、截断或重新翻译字幕。长句依据当前尺寸、字体和实际文本做版式测量；测量错误或实际越界须报告对应字幕和原因。

纯草稿的测量可在空画布上执行，不依赖已拼接的视频。复用报告必须匹配当前字幕、样式、画幅、原生尺寸和字体来源；旧报告或小样尺寸不能作为当前高清版式证明。

### 3.3 画幅和逐条字幕样式

以烧录层当前版式为参考：基础字号来源于已合并的 style / film / variant 配置，逐条中英缩放来自实际字体和安全宽度测量。保留英文术语、原文和人工换行。内部计划支持每条字幕样式覆盖，覆盖优先于轨道样式，轨道优先于全局缺省。

剪映字号映射必须接收画布尺寸，结合本机 pyJianYingDraft 0.3.1 和实际剪映版本做隔离校准，校准记录包含宿主版本、库版本、画幅、参考像素字号、导出参数、实际截图和保存重开结果。用至少两档基础字号及横竖两种画幅验证映射，不用四个手调数值替代通用换算。

中文和英文分别映射实际字号与位置；最长英文沿用测量后的缩放，不能因整轨统一放大再次越界。中英文行间距和底边位置依据实际版式计算，不能仅按未缩放的统一字号上移。

字体替代继续如实披露。浏览器字体测量通过只证明参考版式；剪映替代字体的显示要独立核验。相同可用字体的隔离样本以可见字框高度相对画高与参考版式的偏差不超过 10% 为校准门槛；替代字体样本额外检查边界、两行间距和可读性，不宣称像素一致。

若目标宿主不可用，代码和自动检查可以交付，但字号修复保持“实际显示未验证”，不得声称首批全部完成。

## 4. 约束、兼容性与非目标

- 不修改客户 `film.json`、字幕、已签批镜头或已有剪映草稿；真实工程仅作为只读时间/文本诊断样本。校准与集成导出使用隔离测试目录和新的草稿名。
- 保留剪映运行时拒绝写入、素材复制、同名避让、用户编辑保护、完成回执和阶段恢复。不得通过 `--force` 自动覆盖用户决定。
- 修改发生于拥有源码的仓库，不修改插件安装缓存。保持公共 CLI 用法和现有作品配置兼容。
- 本批不处理人工修改后的验收状态、清单默认摘要、线程预算、bundler 缓存、背景审美、审片数量或母带一致化。这些发现保留在复盘中。
- 不升级 pyJianYingDraft，不扩大剪映支持版本承诺，不自动发布。

## 5. 错误处理与运维

失败应区分时间轴错误、双语结构错误、版式错误和第三方写入错误，给出镜号或字幕序号。字符数建议只记录 warning。

保留失败诊断和原草稿；导出不得留下看似完成的半成品。写入之前沿用实际剪映运行检测，需要退出时只处理该阻塞。实际打开检查结束后，按现有方式保存并复核，不在宿主运行时用外部脚本改草稿文件。

## 6. 验收标准与测试

先新增能复现旧行为的失败测试，确认失败后最小实现；批准本文件后再写实施计划与代码。

| 验收 | 通过条件 |
| --- | --- |
| A1 切点 | 三镜各 2/30 秒和 107 镜非整微秒帧长用例：每个相邻 end=start，总终点准确；真实非法重叠/逆序/零长度仍拒绝 |
| A2 真实写入 | 30fps 107 镜隔离媒体经标准 CLI 输出横竖草稿，Python 写入无 SegmentOverlap；逐段核对实际草稿时间区间及末端，不只验证生产纯函数 |
| A3 文本校验 | 超过28字符但版式可容纳的英文能导出且保留警告；句号仅警告；缺英文、条数错误、中文错配、格式错误仍阻断并准确说明原因 |
| A4 来源与边界 | 改字幕、字体、尺寸或样式后测量失效并重做；小样报告不能证明高清；真实越界必须给出序号，不能因已有签批放行 |
| A5 逐条字号 | 新导出横竖双语草稿包含不同长度的中英文、两档基础字号；逐条写入测量后的字号和位置，长英文与普通句不再共用错误的整轨尺寸 |
| A6 实机校准 | 实际打开新导出的横竖草稿，核对常规句、最长英文、白底和暗底：可读、不截断、不互相重叠且落在配置安全区；同字体字框满足上述10%门槛；保存重开仍成立，证据记宿主版本与时间点 |
| A7 原有保护 | 剪映运行时拒绝写入；重复完整导出复用；用户修改后保留旧稿，明确另导才新建；旧计划样式回退与分轨/素材完整性测试继续通过 |

验证命令：针对性的 jianying-plan、subtitles-en、jianying 集成与恢复测试，随后 `npm test`、`npm run lint`、`npm run smoke`。自动检查和实机 A6 分开报告；未运行或跳过的检查明确标记，不将本次36项基线测试当作修复证据。
