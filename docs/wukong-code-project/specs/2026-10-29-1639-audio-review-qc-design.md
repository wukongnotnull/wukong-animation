# 声轨审听、QC 处置与草稿声音差异（FR-8）

Status: Confirmed；用户在本会话明确回复“确认”，批准本文件。
日期：2026-10-29；基线：main `d370839`。
依据：[已批准 PRD](../prd.md) FR-8、[体验报告](../reports/2026-10-29-codex-editing-experience.md)、[issue #93](https://github.com/wukongnotnull/wukong-animation/issues/93)。本文件的人工审阅记录不替代任何用户签批。

## 1. 问题与目标

客户指出开场重复鼓点枯燥，说明数值审计不足以判断配乐编排。当前音效 audit 实际检查相对电平，不能证明听过音乐；QC 输出问题区间，但没有带来源和理由的逐项处置。剪映导出器在写完草稿后才提示“未做响度统一和淡出”，披露太晚。

已核实声音处理：soundtrack 先做按人声闪避，返回的 tracks 使用处理后文件；终混叠加各轨 gain，裁切全片、统一末尾淡出，再做整体 loudnorm。剪映使用分轨及其音量，包含已处理的闪避素材，但不等同于终混的整体响度/尾部淡出。不能笼统说草稿“完全没有声音处理”。

目标：提交声轨前有实际开场/段落审听记录；QC 原始告警和人工处置分开；导草稿前就说明真实声音差异，保留可编辑分轨。

## 2. 架构与组件边界

- 新 `core/review-evidence.mjs` 验证人工记录与当前来源，汇总审阅状态；不增加自动音乐评价模型。
- 新片内 `review-notes.json` version 1 可纳入版本管理，记录音频分段与逐项结论；schema 验证结构，实际文件哈希/时间范围另做校验。
- `audio/audit.mjs` 与 `core/qc.mjs` 保留原始测量，附加稳定 finding id、来源签名、人工处置和待审汇总。`soundtrack` 生成声轨审听清单；`qc` 生成可读报告到 review。
- `jianying` 导出前生成 `review/草稿声音差异[-画幅].md/.json`，内容写入 FR-7 清单；FR-6 的导出阶段在写外部草稿之前打印差异。

## 3. 接口、数据与行为

### 3.1 实际声轨审听

`review-notes.json.audio` 包含当前 mix 内容 SHA-256、段落 `sections:[{id,label,range:[in,out]}]`、逐段 `checks:[{section,range,reviewer,reviewedAt,verdict,note,evidence}]`。reviewer 只描述真实操作者（用户/代理/制作者），不冒充客户签批；未核实时间不编造。

声轨产出后创建独立的 `review/声轨审听.md/.json`，列出实际可播放路径、开场检查段（从 0 至 min(15秒,全长)）、声明段落及转折前后各最多2秒的检查窗口。短段窗口裁切到全片；重复窗口合并但保留所覆盖段落。未写 sections 时只提供开场和“段落划分未声明”，不凭镜头切换猜音乐段落。

director 在音频宿主实际可听时审听，记录鼓点/编曲是否有变化、转折是否衔接、是否压住人声、音效起音与整体节奏。听不到就标 `not-listened`，把文件交用户审听，不写“已听过”。实际音频文件、审听时间范围与结论必须对应；只有 RMS/LUFS 或音效电平测量只能标 `measured`。

每个窗口结论为 `needs-fix`、`accepted` 或 `not-listened`，accepted 必须有具体听感理由和实际播放证据说明；有意持续重复的配乐也需要明确说明目的与审听范围。缺段落、缺结论、未审听、过期来源显示待审；不因此自动替用户接受作品。音乐/人声/混音内容改变后相关结论失效，不能沿用旧 SHA。

### 3.2 QC 原始问题与人工处置

每次 QC 报告保留原始 `issues`、测量阈值、采样率、原视频 SHA-256、时间轴签名和算法版本。finding id 绑定该次来源、类型、镜号和实际区间，不能只用列表序号。音效审计同理记录测量窗口与原始差值，库中 quiet 只是设计标记，不能自动生成“人工接受”。

`review-notes.json.qc` 的条目用 finding id 关联，含 `disposition:accepted|needs-fix`、reviewer、reviewedAt、range、reason、evidence。accepted 需区间覆盖该问题、理由非空、证据指向已实际查看/审听的帧或片段；无法确认的保持 unresolved。全片统计类问题需附抽查范围和全片设计理由，不伪造单一时间点。

报告分为 unresolved、needs-fix、accepted、stale-notes 四类。accepted 展示原测量和人工理由，不能删除原告警、改测量值或打印“机器检查全部通过”。修复后新一轮未检出问题，标“本轮未再检出”，不只靠手写 resolved。

硬性技术错误（时间轴失败/证据缺失、解码失败、字幕预检 errors、主版保护失败）不能用人工接受记录绕过；现有技术门槛继续阻断对应签批/导出。留白、点缀、帧差/硬切及音效相对电平这类启发式告警可附人工接受。返回值区分 `machineOk` 与 `reviewStatus`；原 `ok` 保持机器判定语义，避免旧调用方因接受备注而忽然放行。

### 3.3 导出前的草稿声音说明

纯草稿和混合格式导出都在任何外部草稿写入前列出当前处理：分轨来自哪些文件、起点/音量、哪些闪避已烘焙；成片末尾淡出时长 min(1.2秒,全长10%)、风格 loudness 目标及可用实测值；草稿未应用相同的整体母带响度处理和统一尾部淡出，需要在剪映核对。

如果当前无音轨，报告“无声”，不套用响度处理提示；实测值不可用时写未测量，不假报达到目标。导出后清单继续附该说明；用户已在简报选择草稿，阅读差异不新增“是否导出”的重复选择。

不改变当前母带算法，不把混音代替可编辑分轨；草稿声音自动等同成片需独立设计。本批不承诺自动处理所有音质问题或自动判断鼓点是否枯燥。

## 4. 约束、兼容性与非目标

- review-notes 可选；旧工程没有时生成明确待审清单，不捏造历史审听或取消既有客户批准。
- 不自动重写配乐、不修改原录音、不自动调低 QC 阈值，不把制作者接受冒充用户终审。
- 报告只声明实际检查的采样和范围；未被抽查的帧/音效仍不能声称已全面验证。
- 依赖 FR-7 提供正确文件链接，但审听/QC 内容判断独立，不阻断 FR-5 的技术实现。

## 5. 错误处理与运维

无效 JSON、越界区间、找不到 finding、旧来源、空理由或证据缺失都报告文件/字段定位；对应接受项不生效，原问题仍可见。生成失败保留本次失败状态，不能继续交付旧成功结论。报告原子写入，保留原始测量以便复核。

## 6. 验收标准与测试

- 长片含开场和至少三个音乐段落：生成全部审听窗口，短片/边界窗口不越界；无 sections 不假称段落检查完成。
- 用固定 WAV 证明来源变更使原审听记录过期；未播放不能仅凭数值生成 accepted。实际宿主可用时审听固定测试片段并如实记录；不可听时交用户，保留 not-listened。
- 同一条 QC 告警分别呈现未处理、needs-fix、有效 accepted；空理由/错区间/旧视频/旧阈值/不存在 id 不放行。原始测量保持不变，重排列表不误绑定。
- 构造时间轴/解码/字幕/主版失败，人工 accepted 不能解除技术门槛；启发式告警接受不把 machineOk 改成 true。
- 验证剪映写入器调用前已输出差异报告；闪避、音量、末尾淡出和 loudness 描述与生产参数一致；无声分支准确；草稿仍分轨，不增加重复交付选择。
- 保留现有响度、ducking、音效审计、QC、剪映计划与导出回归。
