# v0.19.3 · 安装与流程可靠性优化

本版交付第二批三项优化：锁定制作依赖、保护较新工程流程、让剪映导出测试在 CI 中完整执行。[修复 PR #116](https://github.com/wukongnotnull/wukong-animation/pull/116) · [跟踪 #113](https://github.com/wukongnotnull/wukong-animation/issues/113)

## 改了什么

- **依赖安装可复现**：原生插件与便携包使用随包提供的完整清单和锁文件，以 npm ci 安装；不同锁文件、平台、架构和 Node 主版本隔离。安装完整成功后才发布到依赖目录，失败不覆盖已有安装；重复 setup 可复用已验证的同一套依赖。
- **较新工程不会被旧插件改写**：当前支持 flow 5，已知旧流程继续按原规则迁移。遇到较新或非法流程时，在写锁、缓存、签批、报告和 Git 之前停止；status/resume 提供只读诊断，force 不绕过保护。
- **剪映 CI 完整执行**：独立 jianying 检查在 push、PR 和手动触发时运行真实草稿导出；依赖缺失、失败、取消、skip、todo 或空执行均失败，日志管道保留失败状态。

## 升级

通用、Codex、Claude 插件清单及 Claude marketplace 统一为 **0.19.3**。引擎包版本仍为 0.2.0，npm 依赖版本、工程流程编号和视觉基准没有升级。

Codex 原生 Git 来源更新方式：

```bash
codex plugin marketplace upgrade wukong-animation
codex plugin add wukong-animation@wukong-animation
codex plugin list --marketplace wukong-animation --json
```

核对安装版本为 0.19.3，打开新聊天加载新版本；若宿主尚未刷新，重启后再检查。新版首次使用需运行 setup，以建立与当前锁文件和环境匹配的依赖目录。在新聊天中说「用 wukong-animation 检查并安装制作环境」即可；也可用新安装目录内的 `engine/bin/wka.mjs setup`，随后执行 `check`。

旧依赖目录、作品、自定义风格、共享字体与音效保留；首次安装会增加磁盘占用，后续同身份可复用。更新后若提示依赖未就绪，应运行新版 setup，不要复制旧 node_modules 或修改锁文件。

Claude Code 按既有 marketplace 更新。其他 Agent 下载本版 `wukong-animation-agent-skills-v0.19.3.zip` 和 `SHA256SUMS`，核对校验和后使用相同 agent、scope、project、variant 执行 upgrade，再运行新版 setup/check。发布提供更新来源，各宿主仍需执行自身更新流程，不表示所有用户的本地副本已自动替换。
